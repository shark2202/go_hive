Claude Code Queen 特性说明书

把一个外部 Claude Code CLI 注册成 queen：她能像其他 queen 一样收信、回信、使用 queen mail， 但“大脑”不是 Hive 的 agent loop，而是每次信件触发的一次 claude -p 回合。 本页只描述设计特性，并把 go_hive 当前实现状态单独列出，避免把“有配置”当成“能用”。

01一句话定位

她是什么
外部 Agent Queen
Claude Code CLI 作为执行体，Hive 只负责信件路由与协议包装。
她不是什么
不是人格模板
没有内置 persona YAML，不使用 Hive 的 soul / 记忆 / worker 体系。
存在条件
配置驱动
默认不存在；只有 queen_mail.claude_code.<id> 配了才会出现。
关键边界：她是 queen mail 的参与者，不是 Hive colony 的 Queen。她没有自己的聊天窗口， 不进入侧边栏，也不能像普通 Queen 那样创建 colony 或派 worker；她的“工作面”是 Claude Code 自己的工作目录。

02身份、组织位置与可见性

维度行为
身份来源queen_mail.claude_code.<queen_id>，id 由配置键决定；name/title 可由配置覆盖，默认 id 与 “Claude Code”。
org chart显示为虚线卡片，与普通 queen 并列；打开后是只读会话记录，不在侧边栏出现。
聊天窗口没有。她不是客户端直接对话对象；与她交互的唯一方式是 queen mail 信件。
被其他 queen 发现list_queens 会列出她（只要参与 queen mail），其他 queen 可 message_queen 给她。
参与名单Claude Code queen 不受 queen_mail.queens 白名单限制：配置了就算参与；普通 queen 仍受白名单约束。
回信她在一个会话里说的话，会回到写信方对应的会话；不需要她再调用 message_queen 才能回复。

03一次信件如何变成一次 Claude Code 回合

STEP 01
其他 Queen 写信
message_queen(queen_id, message) 进入 Hive qmail，生成 hop 与深度。
STEP 02
定位会话
按 (Claude Code queen, 写信方) 找持久会话；没有就创建，命名 claude_code:<id>:<session>。
STEP 03
排队 / 合并
已有回合在跑时，新信进入队列；空档后合并成下一回合的输入。
STEP 04
运行 Claude Code
claude -p --output-format json，首轮 --session-id，之后 --resume。
STEP 05
回信
取回合最终文本，按最新一封信的 reply_to 回到写信方会话；失败也回传原因。

她如何“主动”写信

每次运行会拿到一个只对本次会话有效的 hive MCP server：

MCP 工具作用
mcp__hive__list_queens列出可写信的 queen（含其他 Claude Code queen）。
mcp__hive__message_queen发信；走回 hive serve，携带只对当前 conversation 有效的 token。

MCP 配置写入临时 JSON（0600），回合结束删除；token 不能用于别的会话。

04完整配置项

位置：configuration.json → queen_mail.claude_code.<id>。下表以 Python 上游行为为准。

键默认说明
name, titleid, “Claude Code”其他 queen 在 list_queens 里看到的名字与头衔。
command"claude"Claude Code 程序路径；也可以是“程序 + 前置参数”的列表。
auth"api_key"api_key 或 subscription。订阅模式有条款风险，见下文。
api_key无她的 Anthropic API key；没有且不是订阅模式时她不运行，写信方会收到原因。
api_base无设置 ANTHROPIC_BASE_URL，用于网关/代理。
config_dirHIVE_HOME/claude_code/<id>/config她的 CLAUDE_CONFIG_DIR：设置、会话、订阅登录都在这里，与用户自己的 Claude 配置隔离。
cwdHIVE_HOME/claude_code/<id>/workspace她运行回合时的工作目录。
permission_mode"default"传给 --permission-mode。无人值守时 default 会拒绝所有需要确认的工具；bypassPermissions 等于放开。
allowed_tools无传给 --allowedTools；非 bypass 模式会自动加入两个 Hive MCP 工具。
disallowed_tools无传给 --disallowedTools。
add_dirs无传给 --add-dir，允许她访问额外目录。
modelClaude Code 默认传给 --model。
timeout_minutes30单回合最长运行时间；超时会杀掉该回合整个进程树，并告知写信方失败。
system_prompt无追加到 Hive 固定信件说明之后，作为 --append-system-prompt。
env无额外环境变量；在 Hive 环境白名单之上合并。
 
"queen_mail": {
  "enabled": true,
  "max_parallel_turns": 2,
  "claude_code": {
    "queen_claude": {
      "name": "Claude",
      "title": "Claude Code",
      "command": "claude",
      "auth": "api_key",
      "api_key": "sk-ant-...",
      "model": "claude-sonnet-4-5",
      "permission_mode": "acceptEdits",
      "timeout_minutes": 30
    }
  }
}

queen_mail.enabled 必须为 true；否则 queen mail 整体不运行，她也不会参与。

05运行时参数与进程行为

行为细节
非交互调用claude -p --output-format json；从 JSON 输出中取最终文本作为回信。
会话首轮 --session-id <uuid>，之后 --resume <session-id>；每个通信对象一个会话。
工具配置--mcp-config <temp> --strict-mcp-config；只注入 hive 一个 MCP server。
系统提示固定信件协议说明 + 可选 system_prompt，通过 --append-system-prompt 注入。
并发queen_mail.max_parallel_turns，默认 2；每个回合独立进程树。
超时timeout_minutes 默认 30；超时先终止，10 秒后仍未退出则强杀。
队列回合进行中到达的信件进入内存队列；回合结束后合并为下一次输入。
失败回传超时、API key 缺失、命令启动失败等会作为“回信失败”返回给写信方，而不是静默丢弃。
停止时Hive 停止会杀掉所有运行中的进程树；队列里尚未开始的信件只在内存，停止即丢，写信方不会被通知。

06隔离与安全模型

环境隔离
只继承白名单
只保留路径、locale、临时目录、代理等运行必需变量；不继承 Hive 的 credential key、provider keys、cloud 凭据、tokens。
身份隔离
独立 CONFIG_DIR
她有自己的 Claude 设置、会话与登录；不会读写用户自己的 Claude 配置。
付费隔离
自己的 API key
只用她自己的 api_key，不会借用 Hive 已保存的任何 Anthropic 凭据。
MCP 令牌
单会话、0600、即删
token 只对一个 conversation 有效；配置文件仅所有者可读，回合结束删除。

订阅模式的风险

auth: "subscription" 使用她 config_dir 里登录的 Claude 套餐。文档明确警告：无人值守地替其他 agent 消耗订阅可能违反套餐条款，风险由使用者承担；官方支持的方式是 API key。

export CLAUDE_CONFIG_DIR="$HIVE_HOME/claude_code/queen_claude/config"
claude          # 然后在交互界面里 /login

07限制与失败语义

限制结果
没有 api_key 且非订阅她不运行；写信方收到“为什么不能回”的原因。
qeen_mail 未启用她不出现在 list_queens，也不能收信。
日限 daily_limit限制的是发信方每天主动发信数；回信不计入。
链深 max_depth超过深度：主动发信被拒并给出原因；回信被丢弃并记录审计。
回合超时整个进程树被杀；写信方收到失败回传。
Hive 停止运行中的回合被杀；未开始的排队信件丢失且不通知。
权限模式default 下需要确认的工具会被拒绝；要她真正动手，必须显式配置 allowed tools 或放宽权限。
Windows 启动裸 claude 可能是 claude.cmd，实现会用 shutil.which 解析；必要时配置 CLAUDE_CODE_GIT_BASH_PATH。
