GO_HIVE · ACP CLIENT · REQUIREMENTS → DESIGN

ACP client 需求—设计链

把外部 ACP agent 变成 go_hive 的独立工具面：纯 Go、stdio JSON-RPC、独立 internal/acp 包、独立 acp_* tools；acpx 只作为行为参考，不作为 Node 运行时依赖。

状态：design包：internal/acp协议：ACP v1 / schema 1.34.1传输：stdio only

00目标与非目标

目标之外：Make external ACP coding agents first-class, independently testable tools: go_hive can delegate a bounded task to Claude, Codex, Gemini, OpenCode, Pi or Hermes without PTY scraping, Node running inside the release binary, or one bespoke adapter per agent.

go_hive can talk to Claude Code through one Claude-shaped CLI adapter and can talk to MCP tool servers, but it has no generic ACP client. Every new coding agent would need another process/argument/transcript parser, and none of those agents can use the same session, permission, filesystem or event contracts.

用户价值
  • Run one ACP adapter and reach Claude, Codex, Gemini, OpenCode, Pi, Hermes and custom ACP agents.
  • Keep multi-turn coding sessions, queue prompts, cancel turns and inspect tool/plan events without PTY scraping.
  • Apply one permission policy and one workspace-root policy instead of one security story per CLI.
  • Use the capability as an opt-in tool family; the existing Claude Code queen runner stays untouched in v1.
为什么不是当前 parity
This is a post-1.0, opt-in capability. ACP is not in the current parity claim, and go_hive must not claim ACP support before the package, fake-agent tests and at least one real adapter E2E exist.
研究基线：acpx 0.22.0 @ e6a5e17（pre-1.0 alpha; CLI/runtime interfaces may evolve）；ACP wire 1 / schema 1.34.1；go_hive 当前No ACP client or acp_* tool exists at HEAD; the existing Claude Code queen runner is a Claude-specific CLI adapter, not ACP.

非目标

  • Do not port acpx flows, the TypeScript workflow engine, flow replay viewer, compare command or embedded acpx runtime.
  • Do not implement a multi-process queue owner/shared CLI session layer in v1; one go_hive process owns its ACP sessions.
  • Do not implement ACP remote HTTP/WebSocket transport; ACP documents it as a draft, and v1 is stdio only.
  • Do not implement ACP v2; v1 wire protocol is the stable target. Revisit after an upstream stable release.
  • Do not bundle Node, npx, acpx, @agentclientprotocol/sdk or any agent adapter in the release archive.
  • Do not migrate the existing Claude Code queen runner to ACP in this design; that is a later, separately accepted migration.
  • Do not expose raw acp_request, fs/read, fs/write or terminal tools to the model; only the curated tool family is public.
  • Do not claim OS sandboxing. ACP is a protocol boundary; the agent binary and its own tools remain trusted processes.
  • Do not read acpx's ~/.acpx/config.json implicitly; go_hive owns its own config and migration is explicit.

04设计链

D1

Package boundary

internal/acp is a stdlib-only client library. It exposes Config, Registry, Client, Session, Turn, Event, PermissionBroker and Store. It imports no server, CLI or builtin-tool package, so fake-agent tests and a future CLI can reuse it. The adapter at internal/tools/builtin/acp_tools.go owns model schemas, approval metadata, registration and event publication.

D2

Transport and process lifecycle

Launch the agent with exec.CommandContext and explicit argv. Use stdin/stdout pipes and a line scanner bounded to 4 MiB; stderr is drained into a bounded ring for diagnostics. One reader goroutine routes responses by JSON-RPC id and server requests to the client router; one writer mutex serializes outbound frames. Close stdin first, then terminate the process group, then kill after a bounded grace. Track a launchId and never let a late write target a retired process.

D3

Protocol and capability negotiation

Speak ACP v1 JSON-RPC 2.0. Initialize with protocolVersion 1, clientInfo and only implemented clientCapabilities (fs read/write, terminal, elicitation, plan, session notices/compaction/subagents as applicable). Treat omitted capabilities as unsupported. Reject protocol mismatch, unknown methods and capability-gated requests with -32601/-32602. Do not expose a raw request path.

D4

Agent registry and config

Ship a small embedded registry of friendly names (claude, codex, gemini, opencode, pi, hermes, cursor, copilot) with argv templates. User config merges built-in < $HIVE_HOME/acp.json < <cwd>/.hive/acp.json < <cwd>/.hive/acp.local.json. argv is required for custom agents; no shell string, no model-supplied executable, no model-supplied env. Missing binaries are a typed unavailable error.

D5

Session store and scope

Store records under $HIVE_HOME/acp/sessions/<record-id>/record.json with 0600 files and 0700 directories. Scope is (resolved argv, absolute cwd, optional name). An ensure finds or creates exactly one open record for that scope. Record fields: local id, name, agent name, argv, cwd, ACP session id, optional provider session id, created/updated time, closed flag and last turn summary. Never persist permission callbacks, resolved policy or credentials.

D6

Session lifecycle

session/new is the baseline. If the agent advertises sessionCapabilities.resume, prefer session/resume for a quiet reconnect; otherwise use loadSession/session/load for history replay. If neither is available, a new prompt may only continue on the live connection. A failed load/resume returns a typed error and never silently creates a replacement conversation. session/close is used when advertised; otherwise close the process locally and mark the record closed.

D7

Prompt turn and queue

Every prompt gets a caller-generated turn_id. One active turn per session; additional prompts queue FIFO and return queued status. session/prompt receives content blocks and returns a stop reason (end_turn, max_tokens, max_turn_requests, refusal, cancelled). session/update is processed in wire order until the prompt response. Cancel sends session/cancel, marks unfinished tool calls cancelled, resolves pending permissions as cancelled, waits for the terminal stop reason, then retires the connection if needed.

D8

Permissions and authentication

PermissionPolicy has mode (approve-all, approve-reads, deny-all), per-tool autoApprove/autoDeny/escalate/defaultAction, and nonInteractivePermissions (deny or fail). Rule precedence is deny, approve, escalate, default, mode. In a server there is no TTY, so an escalation without a host approval broker becomes deny/fail, not an implicit allow. Permission replies are a host/UI concern; the model that called acp_prompt must never approve its own request. Authentication resolves from HIVE_ACP_AUTH_<METHOD> or the credential store; authPolicy skip/fail is explicit.

D9

Filesystem callbacks

Serve fs/read_text_file and fs/write_text_file only when advertised. Resolve against the session root set (cwd plus additionalDirectories), compare components after symlink resolution, reject symlink escapes, special files, hardlink writes and non-regular files. Writes use a temp file in the same directory, fsync where available, chmod from the existing file or 0600 for new files, and atomic rename. Recheck request lifetime immediately before mutation.

D10

Terminal callbacks

Serve terminal/create, terminal/output, terminal/wait_for_exit, terminal/kill and terminal/release only when the terminal capability is enabled. Bind each terminal to the admitted prompt and cwd; launch argv without a shell; cap output; drain pipes; kill the whole process group on cancel; revoke late create/kill requests. --no-terminal advertises terminal=false and returns method-not-found for terminal calls.

D11

Event mapping

Define a small internal Event union: text_delta, thought_delta, tool_call, tool_call_update, plan, mode_changed, config_changed, usage, notice, compaction, session_info and permission_request. Preserve unknown variants and raw _meta as an audit blob with redaction. Apply a per-session cursor and bounded queue; a slow consumer drops/queues according to policy rather than blocking the agent reader. Never write secrets or full environment into events.

D12

Independent tool family

The adapter registers acp_agents, acp_session, acp_prompt, acp_status, acp_cancel and acp_control. acp_prompt is async and returns {session_id, turn_id, status}; acp_status reads state, last text, usage, pending permission and errors; acp_cancel targets one turn; acp_control uses set_config_option or set_mode. No raw request, fs, terminal or permission tool is model-facing. Permission escalations go to the host broker/UI, not the model.

D13

Security and trust

Agent argv and env come only from the registry/config; the model selects a name and optional session name/cwd under the workspace. Apply envAllow/envBlock and never place tokens in argv or logs. Treat all agent-authored text, paths, URIs, commands and tool output as untrusted; do not auto-open links, run commands from agent text, or fetch remote resources. The ACP agent can still act through its own tools; ACP is not an OS sandbox.

D14

Limits, recovery and observability

Defaults: initialize 15s, session/new 30s, prompt 30min, cancel grace 5s, idle close 300s, max 4 sessions, max line 4MiB, stderr 64KiB, event queue 512, pending permissions 8, max 20 events per status read. Detect EOF/exit, fail pending requests, mark the session dead and apply bounded restart only on the next prompt. Emit structured logs with agent name, record id, turn id and error code; never credentials.

Package 边界：internal/acp 是独立可测核心；internal/tools/builtin/acp_tools.go 只做 schema / 审批 / 注册。The core package owns the ACP wire client, agent registry, session store, queue, permissions, filesystem/terminal callbacks, events and limits. It must not import internal/server, internal/cli or internal/tools/builtin. Tool schemas, approval metadata and registration live only in the adapter. 维护：Maintain acp as an independent Go package: its own API, doc.go, fake-agent tests and package gates. It must be usable without a session, HTTP server or tool registry.

08权限与安全

approve-all

Approve every request not resolved by a per-tool rule. Never the default; requires explicit config and host approval.

approve-reads

Approve read/search/non-mutating requests; other requests go to the policy/escalation path. Default.

deny-all

Deny every request not resolved by a per-tool rule.

规则顺序：autoDeny > autoApprove > escalate > defaultAction > mode

非交互：The server has no TTY. Unresolved requests deny by default; nonInteractivePermissions=fail returns PERMISSION_PROMPT_UNAVAILABLE.

升级：Escalations are emitted to the host approval broker/UI. The model that requested acp_prompt cannot decide its own permission. With no broker, the request is denied or failed closed.

撤销：Cancellation, timeout, turn completion or connection close revokes pending permission requests; a late answer cannot authorize a new file/terminal operation.

信任边界：ACP permission is advisory: the agent executes its own tools. The client only controls its own fs/terminal callbacks. ACP is not an OS sandbox.

不要宣称 sandbox：ACP 只约束 client 的 fs/terminal 回调；agent 自己的工具仍然按它自己的权限运行。用户必须信任所配置的 agent 二进制。
