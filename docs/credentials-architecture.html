04Store / Provider / 解析

4.1 默认 Provider

侧默认 Provider说明
PythonStaticProviderCredentialStore.__init__ 默认只有 Static（store.py:97：providers or [StaticProvider()]）；store.py:50 的 [OAuth2Provider(), StaticProvider()] 是 docstring 用法示例，不是默认值。生产 app.py:1008 调 with_aden_sync(auto_sync=False)：有 ADEN_API_KEY 时注册 AdenSyncProvider + AdenCachedStorage，无 key 时回落 EncryptedFileStorage + 默认 Static。
GoStaticProviderNewCredentialStore 只在 provider 为空时注册 Static；默认与 Python store 相同。没有 OAuth2Provider / Aden provider 实现（差异在可选 provider，见 C2）

4.2 解析顺序

  • 缓存：300s TTL；过期或 auto_refresh 时走 provider。
  • refresh-on-access：Python 生产经 AdenSyncProvider（配置 ADEN_API_KEY 时）；通用 OAuth2Provider 需显式注册，不是默认 provider。Go 只有工具层 3 个 provider 的 token refresher + env 桥。
  • store→env：保存/重同步后导出到进程 env，供 MCP 子进程和工具读取。

09主要差异

#差异影响 / 证据
C1已更正 两侧 store 默认 provider 相同：StaticProvider原报告把 store.py:50 的 docstring 用法示例误读为默认值；实际默认在 store.py:97（providers or [StaticProvider()]），Go store.go:52-67 同为只在缺失时注册 Static。默认 Static 下两侧都不做通用 OAuth2 refresh-on-access，因此这不是差异。
C2Go 无 OAuth2Provider / AdenSyncProvider / AdenCachedStorage 实现通用 OAuth2 不是默认 provider 差异（两侧默认都是 Static，见 C1）；真实差异是 Aden provider/storage 缺失：Python 生产在 ADEN_API_KEY 存在时经 with_aden_sync 用 AdenSyncProvider + AdenCachedStorage 在 store 层自动拉取/刷新，Go 无对应，云端 OAuth 账号不能同样处理。另有可选 OAuth2Provider 类型缺失，仅 3 个 provider 有工具层 refresher。Go oauth2.go 只有类型；oauth_refresh.go 仅 3 个
C3Go resync 是本地重读，不是 Aden force-fetch；accountsByProvider 走本地 adapter/resync 后 OAuth 新账号可能不出现；UI 可能看不到 Aden 账号。Go routes_credentials.go:187-205、accountsByProvider
C4Go presyncAdenTokens 只导出 env，且只在 validation 路径调用普通工具解析不会触发 Aden 拉取；依赖 env 是否已被填。Go aden_presync.go、agent_validation.go:171
C5Python 生产 store 用 with_aden_sync(auto_sync=False)两侧生产装配不同。Python app.py:1008 vs Go DefaultAdapterAt
C6Go 缺 LocalCredentialRegistry.ValidateAccount无法“重新验证某个本地账号”；保存时健康检查仍可用。Python local/registry.py:234
C7A15：权限/索引/provider_id null 语义已登记，不阻塞
C8resync 注释仍写“Go 无 Aden client”，但 aden_client.go 已存在文档漂移，误导维护者。Go routes_credentials.go:79-82

10结论与建议

结论：本地凭据子集高度一致（模型、Fernet、布局、解析顺序、42 个健康检查、115 行 specs、12 条路由、check-agent、CLI、UI）；默认 provider 两侧也一致（均为 Static，见 C1）。云/Aden 路径不一致：Python 生产在 ADEN_API_KEY 存在时 store 是 Aden-aware（AdenSyncProvider + AdenCachedStorage），Go store 是 local+env，且 Go 无 Aden provider/storage 与可选 OAuth2Provider 实现。
  1. 在 Go 实现 AdenSyncProvider + AdenCachedStorage（Aden 路径）与可选 OAuth2Provider，或至少把 DefaultAdapterAt 在 ADEN_API_KEY 存在时升级为 Aden-aware。
  2. 让 /api/credentials/resync force-fetch Aden，并让 accountsByProvider 读取 Aden 账号。
  3. 补 ValidateAccount 与对应测试。
  4. 修正 resync 的过时注释，把 C1–C4 登记到 alignment-differences 或 cloud-dependencies。
  5. 补一条真实 Aden OAuth 的 E2E（授权 → resync → specs 可见 → 工具可解析 → 过期刷新）。
