GO_HIVE · LSP · REQUIREMENTS → DESIGN

lsp 需求—设计链

用纯 Go 的 stdio JSON-RPC 客户端接入项目已有的语言服务器，先做只读语义导航与诊断，再按审批边界补齐 rename/code actions。外部语言服务器是运行时依赖，不是 go_hive 发布包的一部分。

状态：design目标：CGO_ENABLED=0核心动作：9 read-only + 3 write 后置

00目标与非目标

目标之外：Give go_hive agents IDE-level semantic navigation, diagnostics and auditable refactoring, while keeping the release binary pure Go and the language-server ecosystem an explicit external dependency.

go_hive has no semantic code-intelligence surface. Text search and AST search can locate syntax, but cannot answer what a symbol means, where it is defined, which files reference it, or whether a rename is type-safe.

用户价值
  • Ask the same language server an editor uses for definitions, references, types, diagnostics and fixes.
  • Perform semantic renames that follow imports, re-exports and cross-file references.
  • Use it only when a matching project marker and server binary exist; never invent a result when no server is available.
  • Keep the Go core CGO_ENABLED=0; language servers remain external processes selected by the user.
为什么不是当前 parity
This is a post-1.0 opt-in capability. Hive upstream has no lsp tool or LSP client, so this is not part of the current parity claim.

非目标

  • Do not bundle gopls, pyright, rust-analyzer or any language server in the go_hive release archive.
  • Do not add a DAP/debugger client in this feature; that is a separate protocol and product surface.
  • Do not implement a full VS Code-compatible client in v1; only the capabilities the tool actions need.
  • Do not claim parity with omp's 55-server catalog; ship an embedded catalog and test a representative subset, with custom servers supported through config.
  • Do not support YAML config in v1 unless a YAML dependency is separately approved. JSON is the v1 format.
  • Do not expose raw LSP request, remote LSP, browser/editor UI, or background workspace indexing in v1.

02决策链

ID方案结论理由
O1Use a Go LSP libraryrejectedThe protocol surface needed here is small and stateful; an external library adds dependency and lifecycle semantics we would still have to audit. Stdlib keeps CGO=0 and the release surface controlled.
O2Embed tree-sitter / ast-grep insteadrejectedSyntax parsing cannot answer type, reference or rename semantics. It is a different feature; ast_grep remains the syntactic fallback.
O3Pure-Go stdio JSON-RPC client + external serverschosenNo cgo, no new Go dependency, matches the LSP ecosystem and keeps server installation explicit. The work is in lifecycle, document sync and edit safety.
O4Shared broker / lspmux in v1deferredUseful for multi-session reuse, but adds a daemon, socket protocol and cross-session document cleanup. Private per-project clients first.
选择：Implement a pure-Go, stdio JSON-RPC LSP client and the read-only lsp tool first; no cgo and no bundled language servers.

03设计链

D1

Tool surface

Register lsp only when $HIVE_HOME/lsp.json settings.enabled is true. V1 registers the read-only actions and returns a typed unsupported-action error for write actions until P1. The full target enum is documented but not exposed as a false promise.

D2

Transport and lifecycle

One process per (workspace, server) with a reader goroutine and a writer protected by a mutex. Frame with Content-Length; cap frame size; route responses by JSON-RPC id; turn notifications into events; cancel with $/cancelRequest; kill the process group on shutdown. Initialize with processId, clientInfo, rootUri, workspaceFolders and only the capabilities the client implements.

D3

Config and discovery

The independent internal/lsp loader merges embedded defaults with $HIVE_HOME/lsp.json only. The session directory is the file tools' sandbox root and is agent-writable, so <sessionDir>/.hive/lsp.json and .hive/lsp.local.json are never read (see go_hive/docs/config-roots.html). Shallow merge per server; object-valued fields replace as a whole. Auto-detect requires a workspace root marker and a resolvable command in workspace-local bins first, then PATH; a definition may pin an absolute validated rootDir instead, which roots discovery, local bins, the server process cwd/rootUri, documents and workspace scans there. Invalid new servers are ignored with a warning; invalid overrides retain the previous definition, and a missing rootDir directory reports the server as unrooted with a reason.

D4

Action router

Resolve file -> server by fileTypes, excluding disabled servers and preferring primary over isLinter. Read-only actions use one client lookup. Workspace forms are explicit: diagnostics/symbols can use file='*'; status ignores file; capabilities may inspect all. No request action in v1.

D5

Position mapper

LSP positions are zero-based line plus UTF-16 code units. Build a per-line index from UTF-8 bytes to UTF-16 columns and back. Resolve symbol columns with identifier boundaries, exact case first then case-insensitive, occurrence selector name#N, line-local only. Never use Go byte offsets as LSP character offsets.

D6

Document manager

Track uri, languageId, version, text and last-used time. Open a document before a position request; reconcile from disk when the file changed; send didChange with the full text for v1; close idle documents after five minutes. Refuse non-regular files and paths outside the workspace.

D7

Diagnostics and results

Keep push diagnostics per URI/version. For a single file wait for a fresh publish or pull diagnostic if supported; do not call an empty stale publish clean. Sort by severity and range; dedupe by range+message. Render deterministic text; cap references and symbols; expose structured details for the UI.

D8

Workspace edits

Parse both changes and documentChanges. Validate URIs, versions, ranges and overlapping edits before touching disk. Apply per-file with a temp file and atomic rename; keep enough original bytes to roll back the whole operation on failure. rename defaults to preview, apply requires explicit approval; rename_file sends willRenameFiles/didRenameFiles and rolls back reference edits if the filesystem move fails.

D9

Timeouts and resource bounds

Tool timeout 5..300s, default 20s. Warmup 5s; project-load wait 15s; single-file diagnostics 3s; glob diagnostics 400ms/file; max 20 glob files; max 200 workspace symbols; max 50 contextual references; max 2 workspace checkers. Idle client sweep 60s; open document idle 5min; failed initialization backoff 3min.

D10

Security and trust

Server command and args come only from embedded defaults or $HIVE_HOME/lsp.json, never from model input. Do not log secrets or full environment. Redact stderr to a bounded tail. Enforce workspace-root and symlink checks. Write actions are approval-gated. Raw request is absent in v1.

协议生命周期

spawn → initialize → initialized → didOpen/didChange → request(s) → shutdown → exit → wait with bounded grace → kill process group

帧格式

[
  "Content-Length: <bytes>\\r\\n",
  "Content-Type: application/vscode-jsonrpc; charset=utf-8 (optional on read)",
  "\\r\\n",
  "JSON body"
]

04LSP Config Scheme

Config Scheme：frozen 归属：LSP configuration is owned by the independent internal/lsp package. One operator-level JSON config file ($HIVE_HOME/lsp.json) is merged over embedded defaults; configuration.json and session-directory files are not LSP config sources in v1. 格式：JSON only in v1. YAML is deliberately out of scope until a YAML dependency is separately approved.
文件格式

JSON only v1

只有一个 operator 级 JSON 文件（$HIVE_HOME/lsp.json）；不引入 YAML 依赖，不读 configuration.json 或会话目录的 LSP 配置。

优先级

built-in < user

所有存在文件都参与合并，不是 first-file-only。

缓存

per-home + reload

配置缓存按 HIVE_HOME；修改 $HIVE_HOME/lsp.json、root marker 或二进制后必须 reload。

合并规则：The user file is merged over the built-in defaults. Per-server merge is shallow: a user server object overrides top-level fields; settings, initOptions, capabilities and workspaceReadyTimings replace as whole objects, never deep-merge. Servers absent from the user file retain built-in values.

发现与缓存：Load and cache the merged config per home. Root-marker and binary discovery are evaluated against the workspace root (session directory) unless a server definition pins rootDir, in which case they use that absolute directory; no parent-directory walk either way. Reload：After changing $HIVE_HOME/lsp.json, root markers or installed binaries, call lsp action=reload file=*; reload clears the home cache and restarts servers whose identity changed.

服务器字段

新服务器必须有：command, fileTypes, rootMarkers。可选：args, languageId, initOptions, settings, disabled, warmupTimeoutMs, isLinter, watchFiles, rootDir。覆盖内置服务器时 required 字段可继承；无效的新服务器忽略并告警，无效 override 保留旧定义。

内置目录：55 个 omp-style 定义；验收代表：gopls, pyright, rust-analyzer, typescript-language-server, clangd, yamlls, bashls。目录是数据，不等于每个服务器都已安装或认证。

Package 边界：internal/lsp 是独立可测的核心包；internal/tools/builtin/lsp.go 只做工具 schema / 审批 / 注册适配。The core package owns config/discovery, JSON-RPC transport, client lifecycle, documents, positions, diagnostics and edits. It must not import internal/server, internal/cli or internal/tools/builtin. The tool schema, approval metadata and registration live in the adapter package. 维护：Maintain lsp as an independent Go package: its own API, doc.go, fake-server tests and package gates. It must be usable without a session, HTTP server or tool registry.

08风险与来源

风险影响缓解
LSP servers are heavy and may take seconds to initializefirst call latency and user-visible timeoutslazy start, bounded project-load wait, idle shutdown, explicit status and no silent fallback.
UTF-16 position conversion is easy to get subtly wrongqueries hit wrong columns or corrupt editssingle position mapper, CJK/emoji/CRLF matrix, never use byte columns directly.
WorkspaceEdit application can partially mutate a projectdata loss / broken worktreevalidate all edits first, atomic per-file writes, transaction rollback, preview default for rename.
Config execution is a trust boundaryarbitrary binary executionembedded/user config only, model cannot set command/args, write approval, path and stderr controls.
55-server catalog is broader than the tested setuntested servers may failcall the catalog data; test seven representative servers; missing binaries are evidence gaps, not passes.
No shared broker means duplicate servers across sessionsmemory usedefer shared mux; cap processes; start private clients only.
