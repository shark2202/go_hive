03元维度：验证方法本身要升级

现在的“对齐证据”偏向三类：路由名、JSON 键集合、测试注解。这三类都能同时全绿而用户可见行为仍不同——18 端点里 8 PASS 就是例子：路由全在，但 queen 身份与事件数据不对。

下一层：场景级 golden trace

同一 HIVE_HOME 初始状态 · 同一 prompt · 同一模型
  ├─ 双跑 Python / Go
  └─ diff：
       · SSE 事件序列（type / 顺序 / 关键字段）
       · 最终 transcript parts（conversation/parts/*.json）
       · events.jsonl / snapshot / stats
       · 工具调用参数与结果（含失败路径）
       · 磁盘目录树 + sqlite schema
       · 成本 / 延迟 / token 计数

现有每日 9:00 的自动快照（refresh_surface_matrix.py）只防路由/表面漂移，防不了行为漂移；下一步把 golden trace 纳入定时对比，才算“行为回归网”。

04明确不要求对齐的

  • csv_sql / excel_sql：依赖 DuckDB（native），纯 Go 无 cgo 有意排除，调用时返回未知 action，不假装支持。
  • 平台专有 PTY 实现细节（Windows 无 PTY 工具，属于已知限制）。
  • 订阅制 OAuth 的厂商细节（Codex/Kimi/Claude 订阅路由属上游专有行为，go_hive 以不可用/未验证标注）。
  • UI 的中文 i18n 是 Go 侧增量，不要求回灌上游。
