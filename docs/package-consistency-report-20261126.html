03仍然影响使用的功能缺口

口径：w197–w201 已关闭 trace 生产接线、PDF 引导、similarweb 工具名、集成面账本范围和 Go-only orchestrator 死码。当前仍影响使用的外部面只剩 Senders/Sentinel 真实投递和 91 个无凭据集成验证；OAuth2 本地-only 默认 StaticProvider、DecisionTracker 无生产写入方、pipeline/graph orchestrator 均按上游边界登记，不是待补的代码不一致。

#不一致现状影响 / 证据
1本地 OAuth2 凭证没有默认 providerOAuth2 的 Base/Zoho/HubSpot provider、生命周期、刷新实现都已存在；但 NewCredentialStore 默认只注册 StaticProvider，生产路径没有 RegisterProvider(OAuth2...)。只有配置 Aden sync 时 AdenSyncProvider 才接管本地-only store 里 oauth2 凭证没有 provider 认领：best-effort 读取仍返回 stale 值；raise-on-failure 路径（如 hive-cred token）现在返回 reauth_required，不再把过期 token 说成已刷新。hive-cred 只有 token/browse/inspect，没有 login/authorize
2DecisionTracker 后验审计链不完整DecisionTracker/StreamDecisionTracker 已移植，colony 也建了 decision runtime；但 agent loop / graph-node 没有 decide()/record_outcome() 生产调用方运行时不受影响；缺“决策→选项→理由→结果”的事后审计数据。不能按“tracker 包已 ported”判全绿
3图执行引擎整体 out_of_scopeGo 侧 internal/orchestrator 已删除（w201）；Python 的 checkpoint 续跑、node 级重试、条件路由、EntryPoint 热替换没有 1:1 等价物依赖图能力的用法必须改写成 colony + agent loop，不能直接迁移
4pipeline 没有生产触发路径7 stage/runner 已移植，但生产代码没有调用方；ColonyRuntime.Trigger 只是 API surface，pipeline 维度标为 out_of_scope包内测试不等行为对齐；不能宣称 pipeline 端到端一致
5Senders / Sentinel 的外部面未闭环Senders 无云端池/ESP/OAuth 投递、无 team quota；threads.json 与 provider seam 已补，Sentinel Slack Socket Mode 已接线但只用假 server 验证真实 Slack/ESP/云投递不可宣称对齐
6集成工具面仍有未验证/缺失会话工具 48/48，但集成 102/854+9；DuckDB 有意缺失；91 个集成无凭据验证实际第三方调用能力未被证明
