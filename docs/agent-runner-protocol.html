01现状：Claude Code runner 到底耦合了什么

事实源：core/framework/server/claude_code_queens.py、go_hive/docs/claude-code-queen-runner.md（回合生命周期 §2、MCP 注入 §4、失败文案 §5）。拆出 8 个耦合点：

#耦合点当前做法判定
1进程调用claude -p --output-format json；prompt 走 stdin（[Name(id)]: text）；超时杀整个进程树形状专属（每家参数不同；杀进程树/并发上限通用）
2回合结果解析读 stdout 最后一个 JSON：is_error / result / num_turns；退出码 + stderr 尾 500 字Claude 专属
3会话续跑首轮 --session-id <uuid>，之后 --resume；conversations.json 的 started；lost/taken 各重试一次语义通用（参数专属）
4MCP 注入写 HIVE_HOME/claude_code/<id>/mcp/<session>.json（0600，回合后删）+ --mcp-config --strict-mcp-config格式通用（mcpServers 是 MCP 标准；参数/路径专属）
5权限--permission-mode + 自动加 --allowedTools mcp__hive__*（非 bypass 时）Claude 专属
6身份/付费auth=api_key（ANTHROPIC_API_KEY/ANTHROPIC_BASE_URL）或 subscription（config_dir 登录）；env 白名单隔离Claude 专属（env 白名单机制通用）
7转录/dashboard读 Claude 会话文件 projects/*/<session>.jsonl，归一成 letter/text/tool/result，跳过 thinking/isSidechain/isMetaClaude 专属
8失败文案/审计6 类逐字文案（无 key/超时/无法启动/is_error/退出码/她已被移除）；queens/mail.jsonl 审计机制通用、文案专属

03统一接口规范（草案）

3.1 Runner 接口（Go）

type Runner interface {
    Kind() string                                           // "claude-code"|"codex"|"opencode"|"pi"|"hermes"|"acp"
    Capabilities() Capabilities
    EnsureSession(ctx, SessionSpec) (SessionHandle, error)  // new / resume（provider_session_id 归一）
    RunTurn(ctx, TurnRequest, emit func(TurnEvent)) (TurnResult, error)
    ReadTranscript(ctx, SessionID) ([]Entry, error)         // dashboard；无转录 provider 返回 nil,ErrNoTranscript
    Close(ctx) error
}

type Capabilities struct {
    Streaming, Resume, MCPInjection, PermissionPrompts, Transcript bool
    AuthModes []string          // api_key | subscription | oauth | none
}

type TurnRequest struct {
    QueenID, SessionID, Ref string   // Ref 形如 claude_code:<queen>:<sid> / codex:<queen>:<sid>
    Prompt     string
    Cwd        string
    Env        map[string]string     // 白名单后的环境
    MCPServers []MCPServer           // 由 Mail 生成：hive + URL/TOKEN/FROM 三元组
    Timeout    time.Duration
}
关键纪律：能力是声明式的。pi 的 MCPInjection=false、Hermes -z 的 Streaming=false 必须显式暴露——调度层据此降级（放弃回信工具 / 只取最终文本），不许伪装成功（与现有「不伪造 profile / 不假装成功」的口径一致）。

3.2 统一事件（归一化）

{"kind":"started","provider":"codex","session_id":"0199a2…"}
{"kind":"text","text":"…","final":false}
{"kind":"tool","name":"Bash","input":{…},"status":"running|ok|error"}
{"kind":"usage","input_tokens":24763,"output_tokens":122,"cost_usd":0.077}
{"kind":"done","text":"final answer","stop_reason":"end_turn|timeout|error","error":null}

映射关系：Claude「最后一个 JSON」→ done；Codex item.completed/agent_message → text、item.*command_execution → tool、turn.completed.usage → usage；OpenCode NDJSON / pi --mode json / ACP session/update 同理各自映射。

3.3 配置 schema（向后兼容）

"queen_mail": {
  "enabled": true,
  "runners": {
    "codex":  {"queen_cx": {"command":["codex"], "auth":"api_key", "cwd":"…", "sandbox":"workspace-write"}},
    "hermes": {"queen_h":  {"command":["hermes","acp"]}},
    "acp":    {"queen_z":  {"command":["npx","@agentclientprotocol/codex-acp"]}}
  },
  "claude_code": { … }          // 保留原键，内部映射到 runners["claude-code"]
}

3.4 会话与转录存储（归一）

runners/<kind>/<id>/{conversations.json,inbox/,mcp/}
conversations.json: {"conversations": {"<peer>": {"provider_session_id":"…","reply_to":"…","started":true}}}
转录：每 provider 一个 normalizer → 统一 Entry{at,kind,text,tool?,error?}；无转录 → 空，不造条目

04交互流程

4.1 一次来信（provider 无关）

4.2 ACP 回合（推荐统一路径）

C→A  initialize {protocolVersion:1, clientCapabilities:{…}, clientInfo:{…}}
A→C  {protocolVersion:1, agentCapabilities:{loadSession/promptCapabilities/mcpCapabilities…}, authMethods}
C→A  session/new { cwd, mcpServers:[ {name:"hive", command:"hive", args:["queen-mail-mcp"],
                      env:[{name:"HIVE_QUEEN_MAIL_URL"…},{TOKEN},{FROM}]} ] }   ← queen mail 直接进协议
A→C  { sessionId }
C→A  session/prompt { sessionId, prompt:[{type:"text", text:"[Ava(queen_ava)]: …"}] }
A→C  session/update*（agent_message_chunk / tool_call / plan / …）
C→A  （权限请求）session/request_permission → 由 Hive 策略回答（allowlist/deny/escalate）→ 权限决定回执
A→C  v1：prompt 响应带 stopReason；v2：prompt 立即确认 + idle state_update 带 stopReason

v1/v2 必须锁一个：v2 把「轮次结束」从 prompt 响应移到 state_update，且 session/load 被 session/resume 取代。混用会得到「永远等不到 stopReason」或「协议版本不匹配」。

4.3 超时 / 并发 / 错误（沿用现状语义）

  • 超时：单回合 timeout_minutes（默认 30 分钟）→ 取消/杀整个进程树（Windows 目前只 Process.Kill()，无 taskkill /T 等价物——已知差异）。
  • 并发：同一会话串行；不同会话可并行；全局上限 queen_mail.max_parallel_turns（默认 2）。
  • 错误分类：no_auth / timeout / spawn_failed / provider_error（is_error / 非零退出）/ refused（Hive 侧拒绝）。文案按 provider 归一后仍保留各自原文供排查。

06ACP 作为统一层：为什么

  • 一次实现，多 agent：ACP 是 Zed 生态的「编辑器↔agent」标准（JSON-RPC 2.0 over stdio）。Hive 只需做 client，agent 侧用现成适配器或原生模式。
  • MCP 注入在协议内：session/new 自带 mcpServers——queen mail 的 list_queens/message_queen 不用再写每家的配置文件，也不用为 pi 的「无 MCP」另案。
  • 权限可控：权限请求是协议内消息（session/request_permission），Hive 可以统一做无人值守策略（白名单放行 / 拒绝 / 升级给 Sentinel），而不是每家一套 --permission-mode。
  • 事件流统一：session/update（消息/工具/计划/状态）天然映射到 §3.2 的统一事件，dashboard 转录也能从中归一。
  • 已被生态验证：Claude Code、Codex、Gemini CLI、OpenCode、pi、Hermes 都有 ACP 入口或适配器（见 §02 矩阵备注）。
维度v1v2
prompt 响应挂起到回合结束，响应带 stopReason立即确认（插入 user message），结束时发 idle state_update 带 stopReason
会话恢复loadSession 能力 + session/load（全量重放）只剩 session/resume（可选 replayFrom）
能力声明clientCapabilities/agentCapabilities 布尔统一 capabilities + info，对象标记
基线方法new/prompt/cancel/update+ list/resume/close 成为基线

07落地路线（建议顺序）

  1. 抽 Runner 接口：把现有 Claude 适配器改成第一个实现，行为零变化——现有 internal/qmail/claude_runner_* 测试全绿是验收线。
  2. 接 Codex（本机 0.162.1 可实测）：JSONL 映射 + resume UUID 存储 + 隔离 CODEX_HOME；补 fake-codex 夹具与真实回合 smoke。
  3. 接 Hermes（走 ACP）：同时把 ACP client 落地——这一步同时交付「ACP 统一层」的最小可用版本。
  4. OpenCode（需先安装）：优先 opencode acp；若走 server API，补版本探测与事件归一。
  5. pi：先解决 MCP 缺口（扩展 or pi-acp 验证），再上 --mode rpc。
  6. 收口 ACP：Claude/Codex 从「原生 CLI 适配」迁移到 claude-acp/codex-acp（原适配保留为 fallback）。

验收清单（每接一个 provider 都要过）

  • 首轮/续轮：会话 id 落盘、第二封信走 resume、lost/taken 校正重试；
  • MCP：queen 真的能调 list_queens/message_queen（或显式声明 MCPInjection=false 并说明降级）；
  • 失败文案：无 auth / 超时 / 无法启动 / provider 报错 / 配置移除，五类均可达；
  • 安全：env 白名单（不含 HIVE_CREDENTIAL_KEY 与任何 provider key）、token 只对该会话有效、回合后清理临时配置；
  • 并发：同会话串行、全局上限生效；超时杀掉整个进程树（≤ Windows 已知差异）；
  • 观测：统一事件序列可回放、dashboard 转录归一（无转录 provider 返回空）；
  • 证据：留一条真实回合的落盘记录（请求/事件/最终文本/计费），不以假服务替代。
