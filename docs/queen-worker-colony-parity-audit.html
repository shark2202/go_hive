06结论：哪些维度不能宣布「完全一致」

总判定：queen / worker / colony 的核心机制在 Go 侧「可运行、可派活、可恢复、可审计」已经成立（12 维代码级对齐），但 12 个维度不能宣布与 Python 完全一致（9 部分 + 1 未对齐 + 2 未验证）。对外表述建议：「机制已对齐 12/24；行为面存在 1 个 P0 未对齐（模型槽位消费）、1 个 P0 部分/未验证（Sentinel 投递）；worker escalation 已按上游语义补齐（#20 的 escalation 部分，含真实 E2E），#20 仍因计划作用域与双存储保留部分」。禁止使用「完全一致 / 100% 对齐」。
#维度状态为什么不能宣布一致补齐条件（验收判据）
16模型槽位运行时消费未对齐worker_llm/vision_fallback 零生产消费；queen_llm 创建期不生效。worker 构建时消费 worker_llm；text-only 模型走 caption 链；queen 新建会话即用 queen_llm；三条都有端到端测试。
