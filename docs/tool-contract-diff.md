## 7. 不可逐字项

| 类别 | 参数数 | 说明 | 样例 |
| --- | --- | --- | --- |
| `default-vs-missing` | 110 | Python schema carries an explicit default or null; proto3 presence cannot tell null from absent | `attach_file.max_bytes_mb`, `chart_render.dpi`, `chart_render.height` |
| `double-nan` | 6 | JSON number mapped to double; NaN/Infinity have no JSON encoding | `attach_file.max_bytes_mb`, `pdf_read.max_bytes_mb`, `search_tools.max_results` |
| `free-form-object` | 2 | object without properties; proto falls back to map<string, JsonValue> | `sentinel_setup.target`, `task_update.metadata_patch` |
| `int64-narrowing` | 34 | JSON integer mapped to int64; |value| >= 2^63 is not representable | `chart_render.dpi`, `chart_render.height`, `chart_render.width` |
| `union-type` | 1 | more than one non-null JSON type; proto falls back to JsonValue | `attach_file.paths` |
| `untyped` | 1 | no JSON type declared; proto falls back to JsonValue | `chart_render.spec` |

这些类型在 JSON 层无法既表达 Python 的接受域又保持逐字一致：
`int64` 收窄（>2^63-1 的 Python int 无法表示）、`double` 的 NaN/Inf 无 JSON 编码、
以及 proto3 presence 无法区分「显式 null / 缺省值」与「字段缺失」。要逐字一致，只能在 JSON
Schema 层约束（加 `maximum`、禁用 NaN、`required` 显式化），这都要求改运行时行为，属于本 lane 之外。

另有两条跨切面规则没有实例参数，但写契约时必须记住：
Python `bool` 是 `int` 的子类，integer 参数在 Python 侧能接受 `true`，Go 的 `int64` 解码会直接报错；
JSON number 没有宽度，`uint32`/`uint64`/`bytes` 无法从 JSON Schema 推出，本契约不声称它们。
