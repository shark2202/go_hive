02read_file

行为细节
普通输出带行号 %6d\t<line>；单行超 2000 rune 截断并追加 ...
hashline=true每行 N:hhhh|content，hhhh = crc32(line.rstrip(" \t")) % 65536 的 4 位小写十六进制（空行为 N:0000|）；该模式不做行截断（截断会破坏哈希）
行切分与 Python str.splitlines() 一致（\n、\r\n、\r、\v、\f、\x1c-\x1e、\x85、\u2028/29 都算行边界）；CRLF 只算一次；末尾换行不产生额外空行
分页offset 从 1 起；limit=0 → 2000 行；未显示完追加 (Showing lines A-B of N. Use offset=… to continue reading.)
字节预算50KB（格式化后行字节+1 累计），超出截断并追加 Truncated by byte budget.
二进制检测为二进制时不输出内容；可查看的图片/PDF 会提示改用 attach_file(paths=…) 以图片形式查看
状态记录每次成功读取都把原始字节记入 stale-edit guard 缓存（部分读取也记录整文件哈希）

03write_file

  • 创建或覆盖；父目录自动创建；原子写入（tempfile + rename）。
  • stale-edit guard：只对已存在的普通文件设防 —— 没读过 → 拒绝；读过但磁盘变了 → 拒绝。新文件可直接创建。错误文案与上游逐字一致，例如：
    Refusing to overwrite '<path>': call read_file('<path>') first so the harness can track its state before you replace it. …
  • 写成功后立即记录新状态，同轮链式编辑不会自我失效。
  • 成功文案：Go 为 Wrote N bytes to <path>（上游是 Created/Updated <path> (N bytes, M lines)）——既有差异，见 §07。

04edit_file

mode=replace

  • 唯一匹配（replace_all=false）或全部替换（true）；空 path/old_string、old_string == new_string 直接报错。
  • 写前顺序：路径策略 → 文件存在性 → guard → 匹配（与上游一致的顺序）。
  • fuzzy 策略链（9 级，按序尝试）：exact → line-trimmed → whitespace-normalized → indentation-flexible → escape-normalized → trimmed-boundary → unicode-normalized（弯引号/em-dash/NBSP）→ block-anchor（0.50 单候选 / 0.70 多候选）→ context-aware（逐行 ≥0.50 且均值 ≥0.65）。命中非 exact 时返回 (matched via <strategy>)。
  • 返回 unified diff（3 行上下文，2000 字符截断）；未命中时附最多 3 条近似行与 Use read_file … or search_files 提示。
  • CRLF 文件在 LF 空间匹配、按原行尾写回。

mode=patch（V4A）

  • 支持 *** Begin/Patch、Update/Add/Delete/Move File:、@@/@@ hint @@、行前缀 /-/+，容忍缺前缀的隐式上下文行与 \ No newline at end of file。
  • 两阶段 apply：先在内存里验证全部操作（fuzzy 唯一性、add 已存在、move 目标、路径逃逸、write_safe_root）——任一失败返回 Patch validation failed (no files were modified)，磁盘不变；全部通过才写入。
  • 写入阶段失败 → Apply phase failed (state may be inconsistent — run git diff …)。
  • 摘要：Modified/Created/Deleted N file(s): <abs paths> + 各文件 diff。
  • patch 模式不设 stale guard（与上游一致：只记录写后状态），但同样受路径/沙箱约束。

05search_files

模式行为
target=content + output_mode=contentrel:line:text；context>0 时命中行 rel:line:text、上下文行 rel:line-text，分组间空行
output_mode=files_only每行一个相对路径
output_mode=countrel:count
hashline=true命中行 rel:line:hhhh|text（同一 crc32 算法）
分页limit 默认 50（content 最小 1）、offset 默认 0；未显示完附 [Hint: showing N of M matches. Use offset=… ]；越界 No matches at offset N (total: M).
target=files按 basename glob（*/*<.ext>）；跳过 .git/__pycache__/node_modules/.venv 等与所有 . 开头目录（另跳隐藏文件）；按 mtime 倒序输出相对路径
实现Go：纯 Go 遍历 + RE2（不依赖 rg 子进程）；非法模式 Error: invalid regex: …；不支持反向引用等 Python 专有语法
防循环进程级 tracker 按 task_id/共享 bucket 计数完全相同查询：第 3 次加 [Warning: …]，第 4 次 BLOCKED: …；查询 key 含分页参数，翻页不误伤

06路径与沙箱

  • write_safe_root（可选、单值或列表）：写路径必须落在任一配置 root 之下；越界文案 write denied: '<original>' is outside the configured write_safe_root(s) (<roots>)。Go 用 Toolbox.SetWriteSafeRoots(…) 配置。
  • 读不放宽：write_safe_root 只作用于写；读仍严格限定在沙箱 root 内。
  • Go 的 root = 会话沙箱根（builtin.New(root) 构造时绑定）；模型的 session_cwd 是隐藏 context 参数，不进入 schema。
  • 上游读绝对路径原样可用（仅凭据 deny list）；Go 一律要求落在 root 内——比上游更严，属于沙箱模型差异而非能力缺失。

07已知差异（Python ⇄ Go）

项上游 PythonGo
读绝对路径原样使用（仅凭据 deny list）严格限 root（更严）；write_safe_root 不放宽读
写绝对路径原样（deny list + 可选上限）root 内，或配置后在 write_safe_root 内
系统/凭据写 deny list逐条（/etc、~/.ssh 等）未逐条复刻（root 边界已覆盖）
根外目标 + edit_file可读可编辑即便 write_safe_root 允许写，仍会先被 guard 拦（读不能出 root）；write_file 不受影响
write_file 成功文案Created/Updated <path> (N bytes, M lines)Wrote N bytes to <path>
before_write 钩子 / session_cwd 注入有未移植（由 Toolbox root + 原子写替代）
内容搜索引擎Python re（含反向引用等）RE2 子集
.gitignore 语义rg 路径遵守；Python fallback 不读固定 skip 集 + 隐藏目录规则
