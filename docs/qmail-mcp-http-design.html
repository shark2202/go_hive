qmail MCP HTTP 需求—设计链

把 stdio 的两个 queen-mail MCP 工具通过一个可选 HTTP 端点暴露给外部 agent/harness。配置采用 queen_mail.mcp_http.<id>，URL 使用 /mcp/queen-mail/<id>/<conversation_ref>，令牌只放在 Authorization header。webhook 是可选的回信/新信推送：缺失或 webhook.enabled=false 时 seat 只做入站；启用后才发送 signed webhook。v1 不做 pull，也不增加额外 MCP 工具。

状态：design需求：11设计项：12验收：17工具：2协议：Streamable HTTP

00目标与非目标

目标之外：Let another agent or harness use the same two queen-mail MCP tools as a local Claude Code queen, with a fixed sender identity and no process-local environment, while keeping the existing stdio adapter untouched. The optional Hive-queen-to-remote-harness direction is delivered by a signed webhook push when enabled, not by a new MCP read tool.

The current queen-mail MCP command is stdio and its identity is the HIVE_QUEEN_MAIL_URL/TOKEN/FROM environment. That gives one client one process and one fixed conversation. A remote harness cannot share it safely, cannot be identified by URL, and cannot be configured next to the existing queen_mail.claude_code entries. The same gap leaves no path for a Hive queen to deliver a reply or a new letter to a remote harness.

用户价值
  • One HTTP endpoint can serve several external harnesses.
  • Each URL/token pair has a fixed queen and conversation_ref, so the sender is never a tool argument.
  • The configuration mirrors queen_mail.claude_code.<id> instead of adding a second participant database.
  • The model-facing tool names and semantics remain exactly list_queens and message_queen.
  • A Hive queen can push a reply or a new letter to the configured webhook of that remote seat when webhook.enabled is true.
  • The local stdio path stays unchanged and the endpoint is off unless configured; the webhook is optional and default false.
  • A webhook-disabled seat remains usable as an inbound-only MCP participant; no outbound push is implied.
为什么不是当前 parity
This is a Go-only extension; upstream Hive has no HTTP MCP server for queen mail. It is not part of the 1.0 parity claim and remains at design status until the configuration and reply boundary are accepted.

非目标

  • Do not add participants.json or an inbox file; the config entry itself is the participant record.
  • Do not make webhook mandatory or default it on; a missing webhook object and webhook.enabled=false both mean inbound-only.
  • Do not add read_letters, reply_letter, a cursor or any pull endpoint in v1; when enabled, webhook push is the only Hive-to-harness channel.
  • Do not add a Hive-to-Hive federation transport or remote Hive registration.
  • Do not put the token in the URL path or query string; use the Authorization header.
  • Do not expose the endpoint on 0.0.0.0 by default or reuse HIVE_DESKTOP_TOKEN.
  • Do not add a new Go module, cgo dependency or bundled runtime.
  • Do not change the local model-facing tool catalogue or the stdio MCP handshake.

前提

  • <id> is a stable configuration key and URL segment; it is not accepted as an unverified queen identity.
  • queen_id in the entry must name a queen or Claude Code queen already known to queen mail; an unknown queen is a startup/config error, not a new queen.
  • conversation_ref is a stable, URL-safe identifier owned by that entry; it is unique across entries and is not chosen by the tool caller.
  • The external harness that enables webhook has an HTTPS endpoint that can verify a webhook HMAC and deduplicate by delivery_id; if it is down, Hive retries and may dead-letter rather than dropping silently. A disabled webhook has no such endpoint requirement.
  • The endpoint exposes only list_queens and message_queen to the remote harness; when enabled, Hive-to-harness delivery is out-of-band webhook push, not an MCP read tool. When disabled, the seat is inbound-only.
  • A webhook-disabled seat is not advertised as a Hive-deliverable correspondent; a Hive queen cannot target it and no outbound queue is created.
  • Queen-mail configuration is read at serve startup; mcp_http changes require a restart, matching the current queen_mail lifecycle.

03设计链

D1

Deployment shape

Mount the MCP handler under the existing serve process at /mcp/queen-mail/. It is off unless at least one enabled mcp_http entry exists. Default serve binding remains loopback; remote use is a reverse-proxy/TLS deployment. The handler does not widen the rest of the serve route surface and does not reuse HIVE_DESKTOP_TOKEN.

D2

Streamable HTTP transport

POST accepts JSON-RPC and returns application/json or text/event-stream; GET provides the optional SSE stream; DELETE ends the session. After initialize the server returns Mcp-Session-Id; subsequent requests carry MCP-Protocol-Version. HTTP accepts 2025-03-26, 2025-06-18 and 2025-11-25; stdio keeps its four versions.

D3

Configuration entry

queen_mail.mcp_http.<id> is a map entry like queen_mail.claude_code.<id>. Required fields are queen_id, conversation_ref and exactly one of token or token_sha256. Optional enabled defaults to true. The entry is the participant record; no participants.json is read or written. Duplicate conversation_ref and unknown queen_id fail startup.

D4

URL and identity binding

The canonical URL is /mcp/queen-mail/<id>/<conversation_ref>. The header token is authoritative; the path is only a routing hint and must exactly match the entry. <id> and <conversation_ref> are URL-safe segments with no slash, dot-dot or control characters. A token bound to another seat, a path mismatch or an unknown id fails closed before Mail is called.

D5

Tool parity

Expose exactly list_queens and message_queen with the same names, descriptions, inputSchema, outputSchema and tool-result envelopes as the stdio adapter. There is no read_letters, reply_letter, admin or raw protocol tool. The local model's default catalogue is not changed; the remote endpoint is a separate HTTP surface.

D6

Mail bridge

After auth, list_queens calls Correspondents(queen_id); message_queen calls the existing Send(writer, fromRef, to, text, nil). Daily limit, max_depth, self-send, unknown queen and audit metadata remain the existing queen_mail behavior. Local Hive and Claude Code delivery are unchanged; only a target that is a webhook-enabled remote mcp_http seat goes to the webhook dispatcher. A webhook-disabled seat is not a deliverable correspondent. The adapter creates no inbox and no read path.

D7

Network and secret security

Token only in Authorization; reject query/cookie/path tokens. Constant-time comparison; token_sha256 is preferred over plaintext token. No access log records Authorization or the token; the path logs only the non-secret id/ref. Validate Origin and Host; no CORS wildcard; cap request bodies; require an HTTPS public_url for non-loopback.

D8

Config lifecycle

Parse mcp_http in the same startup read as queen_mail. Invalid fields, duplicate refs or unknown queens fail the MCP listener with a fixable error; the rest of serve may continue. Changing an entry requires a restart; there is no hot reload in v1. Disabled entries return 404, not a fallback to another seat.

D9

Package and build boundary

internal/qmailmcp owns MCP transport and config/principal validation; internal/qmailwebhook owns the durable outbox, HMAC, retry and HTTP client. Neither may import internal/server, internal/cli or internal/tools/builtin. internal/server mounts a thin adapter and supplies the Mail methods. No dependency, cgo flag, model tool registration or local catalogue change is introduced.

D10

Federation and pull boundary

This is not a remote Hive peer. No federation endpoint, remote queen registration, delivery lease or remote retry protocol is added. The webhook HMAC and retries are local delivery to a remote seat, not a federation handshake. There is no read_letters, cursor or pull endpoint in v1: when webhook.enabled is true, Hive-to-remote delivery is push-only through the configured webhook; when false, there is no outbound path.

D11

Remote seat and optional delivery

Every mcp_http.<id> entry is a remote seat. With webhook.enabled=true it is added to the queen-mail roster so a Hive queen can list it and write to it, and Mail.deliver routes a letter or reply addressed to that seat into the webhook dispatcher instead of a local Hive session. A queen reply to the seat's conversation_ref enters the same path. With webhook absent or enabled=false the seat remains inbound-only: it is not advertised as a Hive-deliverable correspondent, no outbox or dispatcher is started, and a forced send returns a typed webhook_disabled error rather than silently dropping the letter. The MCP tool surface stays list_queens and message_queen.

D12

Webhook delivery contract

When webhook.enabled is true, persist a durable per-seat outbox, then POST one JSON event per letter or reply with delivery_id, event kind, participant id, letter id, from/to, depth, caused_by and optional text. Sign the raw body with HMAC-SHA256 over timestamp.body and send X-Hive-Webhook-Id, X-Hive-Webhook-Timestamp and X-Hive-Webhook-Signature. Retry 408/429/5xx and network errors with exponential backoff and jitter; never retry a permanent 4xx. Preserve per-seat order, expose attempts/state, and move exhausted deliveries to a dead-letter record. There is no pull fallback.

04MCP HTTP 协议

传输

Streamable HTTP

端点 /mcp/queen-mail/<id>/<conversation_ref>；POST，GET 可选 SSE，DELETE 终止。

版本

2025-03-26 / 2025-06-18 / 2025-11-25

HTTP 端点拒绝 2024-11-05 的旧 HTTP+SSE；stdio 继续接受 2024-11-05 / 2025-03-26 / 2025-06-18 / 2025-11-25。

认证

Authorization: Bearer ***

token 只在 header；path 只做路由，不能替代 token。

Legacy：HTTP+SSE from 2024-11-05 is out of scope; stdio is unchanged. 会话：Mcp-Session-Id；后续请求带 MCP-Protocol-Version。

05Webhook push（可选）

默认关闭：The webhook object is optional. Missing webhook or webhook.enabled=false mounts the MCP endpoint inbound-only; URL, secret and retry fields are not required.
关闭行为：A disabled webhook creates no outbox, dispatcher or dead-letter directory. The seat is not advertised as a Hive-deliverable correspondent; a forced Hive-to-seat send returns webhook_disabled and no letter is silently queued.
默认值

webhook.enabled = false

缺失 webhook 对象与显式 false 等价；URL、secret、retry 均不是必填。

安全（仅启用时）

  • HTTPS only for non-loopback URLs.
  • Block private/loopback/link-local addresses unless allow_private_network is explicitly true.

10风险、待拍板与来源

风险影响缓解
webhook-enabled delivery has no pull fallbackreceiver outage beyond retries loses delivery unless dead-letter is replayedpersistent outbox, bounded retries, dead-letter retention, admin replay, alerting; disabled webhook has no outbound delivery to lose.
at-least-once retries can duplicate a webhookreceiver processes the same letter twicestable delivery_id, receiver deduplication, persisted attempt state.
webhook URL is an SSRF or data-exfiltration pathinternal service access or letter text exfiltrationHTTPS, private-IP block, no redirects, allowlist/opt-in, HMAC, no body logs.
per-seat ordering breaks under concurrent retriesreplies arrive out of ordersingle FIFO worker per seat, retry head-of-line, bounded concurrency across seats.
plaintext token or webhook secret in configuration.jsonconfig leak grants send or spoofing capabilityprefer token_sha256 and secret_env, 0600 config, rotation, no logging.
v1 has no pull, so an offline harness cannot catch upoperator may believe delivery is durable when receiver is permanently gonedocument push-only, dead-letter retention, admin replay; add pull only as a later approved feature.

待拍板

  • Should webhook be one endpoint per mcp_http seat, or a list of endpoints with per-event filters? v1 one URL; flexible config can add a list later.
  • What is the dead-letter replay interface: local CLI only, or a protected admin HTTP route?
  • Should webhook payload include letter text by default, or only metadata plus a separate encrypted body?
  • Should a 2xx with an empty/invalid ack body count as delivered, or require a signed receiver ack?
  • Should retries preserve strict per-seat order at the cost of head-of-line blocking, or allow parallel delivery with sequence numbers?
  • Which protocol versions are mandatory in the first release: 2025-06-18 only, or the 2025-03-26/2025-06-18/2025-11-25 set?
  • Should v1 add idempotency for message_queen, or explicitly document duplicate risk on retry?
