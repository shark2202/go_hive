Hive 触发器：timer 与 webhook（字段级契约）

触发器（trigger）是会话级的时间/事件入口：到点或收到 HTTP 请求时，把一条任务以 user 消息注入 queen 会话。两类：timer（cron 或 interval_minutes）与 webhook（本地 HTTP path + methods）。本页给出配置、请求、响应、事件、注入五层字段的类型、必填性、默认值与语义，并登记已知差异。

01触发定义（triggers.json / 列表 API）

字段类型（JSON / Go / Python）必填默认含义
idstring / string / str是—触发器标识（URL/工具入参 trigger_id）；同一会话内唯一，重设即更新
trigger_typestring 枚举 / string / str是—"timer" | "webhook"
trigger_configobject / map[string]any / dict是—按类型见 §02/§03；未知键忽略
descriptionstring / string / str否id展示名（卡片/列表）
taskstring / string / str否*""注入消息里的任务指令；*空 task 也可触发（只有 payload）
enabledboolean / bool / bool否false激活开关；激活时才注册 timer/webhook
last_fired_atstring|null / *string / str|None输出null最近触发时间，ISO8601 UTC
next_due_atstring|null / *string / str|None输出null下次到期，ISO8601 UTC（webhook 恒 null）

存储位置：triggers.json 位于所操作 colony 根目录（agent export dir，<colony>/triggers.json），按 id 唯一；会话只是创建/激活入口与运行载体。

02timer 的 trigger_config

字段类型必填默认含义与边界
cronstring与 interval 二选一—5 字段（分 时 日 月 周；秒=0）或 6 字段 croniter 布局（秒在最后，second_at_beginning=False）。严格子集：names/macros、L/W/#/?、跨夜区间、7 字段年份均拒绝
interval_minutesnumber（float）与 cron 二选一—>0；首触发延迟=值×60s；可为分数（0.5=30s）。无毫秒语义

缺失两者 → 错误 Timer trigger needs 'cron' or 'interval_minutes' in trigger_config.；错过的 tick 不补跑，重开时重建 missed（上限 100 条）→ resolve_missed（fire_latest|skip|reschedule）。

03webhook：请求侧字段

trigger_config类型必填默认含义
pathstring是—必须以 / 开头；精确匹配（区分大小写，无通配/前缀）。错误文案：Webhook trigger requires 'path' starting with '/' in trigger_config (e.g. '/hooks/github').
methodsarray<string>否["POST"]允许的 HTTP 方法；比较前大写化（GET/POST/PUT/PATCH/DELETE...）
portinteger否8090本地监听端口；host 固定 127.0.0.1。多会话需各自配置不同 port

路由表以 path 为键：重复注册同一 path = 后者覆盖（两侧一致，routes[path]=route）。secret 字段在服务层存在（HMAC-SHA256），但 queen 触发创建流程不读它 → 实际不鉴权。

HTTP 请求字段类型/取值约束与语义
methodstring必须 ∈ methods（大写比较）；否则 405
pathstring精确等于 path；否则 404
headersobject<string,string>任意；Content-Type 不校验。同名头取首值（真实 aiohttp 实测 dict(request.headers) 取首值；Go 已对齐 a91ae182），并额外加入 Host
query_paramsobject<string,string>任意；同名参数取首值（实测对齐 a91ae182）
bodybytes可选。上限 1 MiB（两侧一致）：≥1 MiB 一律拒绝并回 400（上游 aiohttp 在 read() 抛 HTTPRequestEntityTooLarge 后由 handler 转 400，不存在 413 路径）。空 body → {}
body 解析JSON → object；非 JSON → {"raw_body": string}非法 UTF-8 以 U+FFFD 替换；JSON 但非 object（array/number/string/bool/null）：两侧均原样保留为 payload（Go 侧 2026-11-23 修复，commit 3597215d；微差见 §09）
curl -X POST http://127.0.0.1:8090/hooks/github \
  -H 'Content-Type: application/json' \
  -d '{"action":"opened","number":7}'

05事件：WEBHOOK_RECEIVED 字段

字段类型含义
typestring 常量"webhook_received"（Go EventWebhookReceived；Python EventType.WEBHOOK_RECEIVED）
stream_idstring= source_id = 触发器的 trigger_id（不在 data 内重复）
data.pathstring请求路径
data.methodstring已大写化的方法
data.headersobject<string,string>请求头（Go 空则 {}）
data.payloadobject<string,any>解析后的 body；Go 空/非 object 时可能为空 map 或缺失（见 §09）
data.query_paramsobject<string,string>查询参数（空则 {}）

06注入：TriggerEvent 与消息文本

TriggerEvent 字段类型（Go / Python）含义
trigger_typestring / str"timer" | "webhook"
source_idstring / str触发器 id
payloadmap[string]any / dict[str, Any]webhook：{task, path, method, headers, payload, query_params}
timestampfloat64 / floatepoch 秒（Python time.time()）

注入为用户消息（is_trigger=true 标记，UI 渲染成 banner；LLM 看到逐字文本）：

[2026-11-23 09:12 CST]
[TRIGGER: webhook/t1]
Task: 处理新 issue
{"task":"处理新 issue","path":"/hooks/github","method":"POST","headers":{...},"payload":{"action":"opened","number":7},"query_params":{}}

模板：[stamp]\n[TRIGGER: <type>/<id>] + 若有 task \nTask: <task> + \n<json(payload)>；stamp 为本地时区 %Y-%m-%d %H:%M %Z。上游会把多个待触发合并成一条（\n\n 连接）；Go 每事件一轮（已知差异，见 §09）。

09已知差异与限制（登记）

  • 非 object JSON body（已修复 2026-11-23，3597215d）：两侧均原样保留任意 JSON 类型；剩余微差两条：① 数字统一为 float64（Python 区分 int/float、>2^53 大整数精度不同）；② Python json.loads 接受 NaN/Infinity/-Infinity（非标准），Go 走 raw_body 分支——极端 body 才有差。
  • 批量注入（已对齐 2026-11-23，1e8ef0a1）：连续 trigger 合并为一条消息（单 stamp、\n\n 连接、FIFO 不越过 client 消息）。
  • 重复头/query 与 body 上限已对齐（a91ae182）；残留登记三条：头名 wire 拼写（上游保留原拼写，Go net/http canonical 化）、JSON 序列化形态（空格/换行）、超限后连接 drain（aiohttp lingering vs Go ≤256KiB）。
  • 消息文本编码：上游 json.dumps(default=str) 默认 ensure_ascii=True（非 ASCII 转 \uXXXX）；Go 输出原始 UTF-8（SetEscapeHTML(false)）→ 同一 payload 的文本形态可能不同（语义等价，未做逐字节断言）。
  • 无鉴权（secret 未接线）、只监听 127.0.0.1、不落盘/不重放/无去重、多会话同 port 争用。
  • 无毫秒、无“延迟队列/一次性 after-N”类型（timer 仅 cron/interval；延迟需 interval 近似或外部承担）。
