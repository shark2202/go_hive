04维护流程（不更新 = 没改完）

  1. 改代码前：确认改动触及哪些 INV；在 issue/提交标题写编号（如 INV-06: events flush）。
  2. 改代码时：同步改上游对齐断言/测试；若新增跨模块依赖，新增一条 INV（编号递增，不复用）。
  3. 改代码后：更新本页对应的“事实源/校验方式”行；跑门禁： 
    cd go_hive/go-hive && make ci
uv run python go_hive/scripts/surface_audit.py --strict
bash go_hive/scripts/check_parity.sh
bash go_hive/scripts/check_parity_targets.sh
python3 go_hive/scripts/wiring_check.py
  4. 评审：接口变更 PR 必须包含本页 diff；只改代码不改本页的 PR 视为未完成。
  5. 定时：每日 9:00 的 refresh_surface_matrix.py 同时刷新本页的“自动校验”区块；路由/事件/工具计数漂移会直接显示。
分层规则：能机器校验的（路由、事件常量、工具计数、端口）→ 脚本；不能机器校验的（字段语义、错误码映射、token 生命周期）→ 测试 + 人工评审，并在“校验”列写明具体测试名。
