GO_HIVE · G2 LOSSLESS REPLACEMENT

老用户 无损替换：数据级无损 · 可回滚 · 升级实测

一个非空旧版（v1 / v2 布局）HIVE_HOME 能否直接交给 Go 版 hive serve：自动迁移、数据不丢、字段不坏、可回滚、可升级。判定基于同一份旧 home 的 Python/Go 双跑、Go 写过的 home 用 Python 读回，以及 v1.0.25 → 1.0.26 的升级/回退演练。数据级无损 ≠ 逐字节一致；已知例外逐条列出，其中 P0-G2-1 待用户决策。

一句话：旧 v1/v2 HIVE_HOME 可以交给 Go 版直接启动；迁移按 v2 → v3 → colony_sessions → tracker ensure 执行，任一步失败只告警不阻断。回滚方向是只读的，两个方向都没有数据损坏。未发现需要「回滚迁移」或修复数据的情况。
待决策（P0-G2-1）：v1 exports/ 的解析基准，Python 用 CWD 相对路径、Go 锚定 $HIVE_HOME/exports。Python 从 core/ 启动时会写 .migrated-v2 却不搬 colony；Go 无此问题。本次未改 exports 行为；是否要求 Go 逐行为复刻 Python 的 CWD 语义，需用户拍板并在发布说明注明。

02夹具与双跑统计

夹具由 go_hive/scripts/g2_home_fixture.py 生成（仅标准库），同一模板复制两份，各自重写绝对路径、冻结 summary mtime；Python 侧调用 SessionManager.__init__ 同一迁移序列，Go 侧调用同一序列的导出函数；再用 storage_compat_diff.py 做路径归一后的 sha256、逐 JSON 字段路径+类型、逐 DB schema/索引/触发器/行比较。同起点、同输入、各自实现。

2.3 读探针与 API 覆盖

  • v1-rich：冷会话 2、history 2（parts 4/2）、tasks 2；legacy/ops colony 发现与 tracker（deals 2 行、v0→v3、2 触发器）；记忆 3 文件（含合并分支）、senders 2 行、skills 3 文件——逐文件 sha256 一致。
  • v2-rich：冷会话 3 + colony 会话 alpha 3 / beta 1；history 8（最多 6 parts，含 tool calls / is_skill_content / spillover）；alpha/beta tracker（leads 3、invoices 2、activity 2、change log 3、4 触发器、JOIN 聚合一致）；colony.db 2 条 playbook_runs；记忆 6、skills 用户/queen/colony 各 2——两侧 0 差异。
  • API：两侧真实二进制在未迁移夹具上启动，/api/discover、/api/colonies/<c>/data/{tables,rows,changes} 载荷归一化后 0 差异；启动迁移树文件集合一致（v1 50、v2 99 文件，markers 相同）。
  • 交叉消费：对 Python 迁移后的 home 原地跑 Go 迁移，manifest 前后逐文件相同（不重写）；双向读 diff 0/0/0。

04升级步骤

4.1 固定步骤

  1. 先整目录备份（唯一可靠的回退路径）：cp -a "$HIVE_HOME" "$HIVE_HOME.bak-$(date +%Y%m%d-%H%M%S)"。
  2. 安装/校验归档：bash go_hive/install.sh --from <release-dir>；脚本校验 SHA256 与归档内容，落盘 hive / hive-cred / hive-browser / browserbridge 四二进制并逐个跑 --version/--help。
  3. 首次启动新版本：HIVE_HOME="$HIVE_HOME" hive serve --port 8788。确认 GET /api/health 200；磁盘上出现 .migrated-v2 / .migrated-v3 / colonies/.migrations/colony_sessions_v1；日志出现 tracker_db: ensured N。
  4. 抽查数据：hive session list --cold、hive queen sessions <queen>、hive colony list；hive-cred inspect <id>；tracker schema_version=3。
  5. 需要回退二进制：直接用旧二进制启动同一 home（已实测 0 写入、可读迁移后会话）；迁移前旧二进制看不到 v2 布局会话（F5），这是升级前提，不是损坏。
  6. 需要恢复迁移前布局：停 serve → 用备份目录整体恢复 HIVE_HOME → 启动旧版本；不要手工改/删 .migrated-* markers。

05例外与回滚指南

5.1 已知例外（逐条）

编号例外性质 / 影响状态
P0-G2-1v1 exports/ 解析基准：Python migrate_v2 用 CWD 相对 exports/，Go 锚定 $HIVE_HOME/exportsPython 从 core/ 启动时给旧 v1 home 写 .migrated-v2 但不搬 colony（数据滞留风险）；Go 无此问题，替换方向更安全待用户决策
是否逐行为复刻 CWD 语义；本次未改 exports 行为，发布说明须注明
F4colonies/.migrations/ 被 hive colony list 当作 colony（Python 同行为）展示层；存在误 colony delete .migrations 的风险待决策
需两侧联合过滤点目录，单改 Go 破坏对齐
F5迁移前旧二进制看不到 v2 布局会话用户感知；非数据损坏。新版本启动迁移后可读，迁移后旧二进制仍可读文档化前提
F6CLI JSON 数字序列化：Python 1767225600.0 vs Go 1767225600值相等；严格字符串比对会差，读取无影响归 value-parity lane
R-G2-1colonies/alpha/worker.json 的 input_data.binding 键序排版级；字段/值一致，交叉消费不重写不修
R-G2-2新建/重建的 *.db 字节不同（SQLite 页布局）设计内；schema/行/触发器/user_version 全等按结构验证
R-G2-3/4/api/health.resources 运行期指标；读探针归一化时间戳/epoch非存储数据；展示值不纳入比较
R-G2-5provider_id：Python null vs Go ""空值语义；存储回写不丢，影响仅显示层已记录
R2/R3/R4JSON 排版（键序/缩进）、时间戳渲染（+00:00 vs Z）、凭据目录权限（Go 更严）值格式级/安全姿态；两侧解析互认不修

未验证边界：真实用户数据长尾（超大 parts、损坏 JSON、权限错误）、Windows/Linux 实机、真实 OAuth 刷新/第三方 token、sessions/history 的 HTTP 端点抓取。G2 双跑只覆盖 macOS arm64 与假凭据。

5.2 回滚指南（按场景）

场景操作
还没启动过新版本无需回滚；保留备份即可。旧二进制照常读旧 home。
已启动新版本，想换回旧二进制直接用旧二进制启动同一 home：实测 health 200、会话可读、0 写入。注意迁移前旧版本看不到 v2 布局会话（F5）。
已迁移，想恢复迁移前布局停 serve → 用完整备份恢复 HIVE_HOME → 启动旧版本。不要手工改/删 .migrated-* markers；迁移只新增 marker/tracker 与按布局搬移，不删除用户数据。
数据异常 / 读不到立即停 serve，保留现场（再 cp -a 一份），按 §5.1 逐条例外核对；无法解释时恢复备份再复现。不要继续在异常 home 上跑写入。
禁止：不备份就对真实 home 跑迁移；用「删 markers 再重跑迁移」代替恢复备份；在迁移进行中并发启动第二个 serve 或离线 janitor（serve 已写 maintenance/server.lock 做互斥）。
