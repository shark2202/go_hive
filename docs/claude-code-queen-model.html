00速览：四个"不是"

常驻？
不是进程
常驻的只有"配置 + 收件箱 + 会话记录"；每封信才 spawn 一次 claude -p，回合结束即退出。
共享会话？
按写信人各一条
conversations.json 是"peer → 一条 Claude session"；Ava 和 Ivy 不共享上下文。
colony 成员？
不是
不在 colony 的组织图里；不能当 colony 的 queen、不能派 worker、不能读写 tracker。
可以配多位？
可以
queen_mail.claude_code 是 id→配置 的 map；各自独立，共享全局并发上限。
一句话：她是"邮局里的外部同行"——按信件召之即来的专家席；Hive queen 才是"一直在线的常驻主管"。二者在 queen mail 里平权（都能收信/写信/受同一套限额与审计），但身体完全不同。

三个常见误解
  • "CC queen 是 colony 的 queen"：不是。colony 的 queen 只能从 queen 目录（profile / DEFAULT_QUEENS）里选；CC queen 不在该目录里（queen_profiles.list_queens() 不含她），只存在于 queen_mail.claude_code 配置与邮件名册中。
  • "她能指挥 colony 的 worker"：不能。她没有 run_worker，也没有 colony 绑定。
  • "worker 可以写信求助"：不能。邮件工具是 queen-only 注册（queen_lifecycle_tools.py:3994-3997）；worker 的升级通道是 doom-loop 自动升级 → list_worker_questions/reply_to_worker。

两条边（唯一的两种交互）

  1. Queen ↔ Worker（colony 内部）：下去 run_worker/inject_message/reply_to_worker；上来 report_to_parent → [WORKER_REPORT] + tracker 行。
  2. Queen ↔ Claude Code queen（跨 colony 边界，只走信件）：colony queen 用 message_queen 外包任务；她回合的最终文本作为回信进入 colony queen 会话；结果要由 colony queen 自己落 tracker。

Worker 与 CC queen 之间没有任何通道（worker 无邮件工具，CC queen 无 worker 句柄）。

03人类如何与她交互：没有"直接对话"入口

前端源码里写得很直白（claude-code-queen.tsx:8）："Read only: she lives in Claude Code, and her letters are her input."

能做怎么做边界
看组织架构图里她是虚线卡片（claudeIds 判定）；点进去是只读页：会话列表 + transcript（两个只读路由 /api/claude-code-queens、…/conversations/{sid}）只看，不能发消息
配改 configuration.json 的 queen_mail.claude_code.<id>：name/title/command/auth/api_key/api_base/config_dir/cwd/permission_mode/allowed_tools/disallowed_tools/add_dirs/model/timeout_minutes/system_prompt/envGo 在 serve 启动时读一次；上游每回合重读
自己进她的家CLAUDE_CONFIG_DIR=~/.hive/claude_code/<id>/config、工作目录 …/workspace，自己跑 claude（可 --resume <session-id>，session id 在 conversations.json/dashboard）这是绕过 Hive 直接用 Claude Code；会与她被写信时的回合共用同一 Claude 会话，注意并发与权限

为什么"必须通过其他 queen"

queen mail 只有两个写入口，都不是给用户的：

  1. message_queen 工具——只注册在"参与 queen mail"的 queen 会话里（Hive queen 的 queen_mail_tools.py；CC queen 的 MCP server）。
  2. POST /api/queen-mail/letters——要求头部 X-Queen-Mail-Token；token = HMAC(secret, ref)，secret 是 serve 进程启动时随机生成的 32 字节（queen_mail.py:97-102）。外部拿不到 → curl 也写不进去；这个路由是她往外写信的通道，不是人类控制通道。

因此要把信送进她的收件箱，from 必须是某个参与 queen mail 的 queen 会话——要么是一位 Hive queen，要么是另一位 Claude Code queen。你的实际路径：打开你的 Hive queen 会话，说"给 queen_claude 写封信，内容是……"。

如果要做"人类直接给她写信"：这是产品扩展，不是现有能力。需要新增 human→queen 的入口（例如 POST /api/claude-code-queens/{id}/letters，把用户当作 writer 开一条会话，并把回复投递回 UI），并明确它是否计入日限/链深、与 message_queen 的权限/审计关系。上游没有此设计，按"只对齐、不新增"原则不应擅自加。

04可以配置多个：`claude_code` 是 map

"queen_mail": {
  "enabled": true,
  "claude_code": {
    "queen_claude":   { "name": "Claude",   "title": "Engineer",     "api_key": "***", "permission_mode": "acceptEdits" },
    "queen_reviewer": { "name": "Reviewer", "title": "Code Review",  "auth": "subscription",
                        "cwd": "~/work/review", "permission_mode": "default", "model": "claude-sonnet-…" }
  },
  "max_parallel_turns": 2
}
独立共享（全局）
id、name、title；command/auth/api_key/api_base；config_dir/cwd（默认按 id 分开）；conversations.json/inbox//mcp/；permission_mode/allowed_tools/disallowed_tools/add_dirs/model/timeout_minutes/system_prompt/envenabled、daily_limit、max_depth（策略同值；日限按每位 queen 自己计数）、max_parallel_turns（默认 2，指所有 CC queen 同时在跑的回合总数）、同一个 Mail 服务与审计 mail.jsonl
  • 无硬编码数量上限；真实约束是 Anthropic 额度/订阅、机器资源与全局并发上限（配 10 位也只有 2 个回合同时跑）。
  • id 天然唯一（JSON 键）；name/title 不做唯一校验——建议别重复，否则 list_queens 里只能靠 id 区分。
  • 不要手动共用 config_dir，除非你确实想让两位共享 Claude 登录/会话；否则会话文件会混在一起。
  • Go 在 serve 启动时读一次配置：新增/删除一位 CC queen 需重启（上游每回合重读）——已登记差异（runner.md §8）。
  • 它们彼此也能写信：只要都在 claude_code 里、queen_mail.enabled=true，list_queens 会列出彼此。

05常驻性与会话模型

维度Hive QueenClaude Code QueenWorker

会话：每位写信人一条（不共享）

{"conversations": {
  "queen_ava": {"peer": "queen_ava", "reply_to": "session_ava", "started": true, "session_id": "…"},
  "queen_ivy": {"peer": "queen_ivy", "reply_to": "session_ivy", "started": true, "session_id": "…"}
}}
  • Ava 与 Ivy 各自一条 Claude 会话：她跟 Ava 聊过的内容，Ivy 那条会话里看不到（除非信里写了）——她没有全局共享上下文。
  • 同一会话内串行：同一 writer 连写两封，第二封等第一封回合结束；回合中到达的信合并进下一回合（runner.md §2.2）。
  • 不同 writer 可并行（不同 session），但受全局 max_parallel_turns（默认 2）限制。
  • 回合记录：Claude session 文件在 config_dir/projects/*/<session>.jsonl；dashboard 只读投影为 letter/text/tool/result。
准确说法："常驻的是状态，不是进程"——收件箱在磁盘、会话在磁盘、配置在磁盘；她的"在线"只是收件箱有信时的一次回合（最长 timeout_minutes，默认 30 分钟，超时杀进程树）。dashboard 的 running 仅回合进行中为 true。

06何时用哪个（设计含义）

Hive Queen
组织内的常驻主管
有记忆、有 colony、能派 worker、你能直接对话、你离开后还能继续工作（park/Sentinel/trigger）。她是你"团队"的一部分。
Claude Code Queen
邮局里的外部专家席
自带完整编码工具链与自己的工作目录/账号；适合"派一个能自己写代码/查资料的外部 agent 去干活，干完把结论寄回来"。不共享 Hive 记忆、colony 与生命周期工具。

设计原话（docs/key_concepts/the_loop.md:14）："A one-off task and a long-running business overseer are the *same* loop with different settings."——CC queen 是这条原则的外部延伸：Hive 不改变她的运行时，只把她接进同一套邮件与治理。
