00口径：什么叫「包级一致」

判定顺序（从强到弱）：open 缺口 → 登记册 bad 行（partial / missing / builder_only / const_only）→ 相位门 ungated → 维度 partial → 已对齐（所有列出维度均为已实测一致）→ 结构对应（无行为登记）。1 个 Python 包完全没有 Go 对应物不代表 25 个包都对齐：6 个包只有结构对应，1 个包在限定维度内已对齐，其余 15 个仍有已登记差异。
四个不要混淆的数字：① 包数（本页：Python 25 / Go internal 60）；② 包级判定（1 已对齐 + 15 部分 + 6 结构对应 + 1 仅测试）；③ 行为登记册（119 行可归属到包，另有 22 行 test_mapping、0 个 open 缺口）；④ 集成面（tools/src/aden_tools，866 个 MCP tool）不在 ①②③ 任何分母内，其逐 provider 覆盖为未计算（见 §05）。四者不是同一分母。
  • 结构对应：Go 侧有职责对应的包，但没有维度/登记册证据证明行为等价。只能说明「有实现」，不能说明「一致」。
  • 生产接线：统计 Go 包被包外非测试文件 import 的次数；0 说明该包可能是未接线的遗留代码。
  • 登记册锚点：登记册每行带 go_hive/go-hive/internal/<pkg>/… 锚点；本页按锚点把行归属到包，再按状态计数。共享 Go 包只计入主属 Python 包，避免同一行重复计数。
  • 相位门 ungated：工具在 Go 侧存在，但 Go 没有 Python 的 _QUEEN_*_TOOLS 相位成员表（24 个 phase 工具均属此类）；按包计为「部分（相位门）」，不当作工具缺失。
  • 开发工具：包内模块只被测试或开发命令引用，产品路径不消费；标为「开发工具（非产品面）」，不计产品缺口（当前：testing 的 llm_judge 被 skills/cli.py 引用，其余 7 个模块由隐藏 dev 命令 hive test-approval 调用）。
  • 规模比只用于发现「一边明显更薄」，不作为等价证据；Go/Py 行数比受语言表达力和测试位置影响。
边界：本页只对照 core/framework 的 24 个包 + (root) 与 go_hive/go-hive/internal 的 60 个包。core/hive 是公共再导出面；tools/src/aden_tools（324 个 py / 866 个 MCP tool）与 core/frontend 不逐包展开，也不计入任何 unported 数字；集成面覆盖是未计算状态，见 §05。go_hive/browserbridge 与 go_hive/go-hive-cloud 是独立模块，另有专项矩阵。
为什么维度矩阵有 6 维已实测一致，包级只有 1 个？两者分母不同：维度回答「这个对外面是否等价」，包回答「这个源码包的全部已登记行为是否都干净」。例如 api-routes 已实测一致，但 server 包仍有 6 个相位工具未设门；sse 已实测一致，但 eventbus 所在的 host 行仍有 22 条 partial 事件。维度绿不能替代包级收口。

03模块级归属（源码文件）
