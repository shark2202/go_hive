Computer-use 移植评估 非对齐项

把 oh-my-pi 的 scriptable computer use 作为外部能力样本，评估 go_hive 能否、以及应该以什么方式移植。结论先行：技术上可以，但当前不应把它加入 go_hive 1.0；全量实现需要独立 native sidecar，而不是纯 Go 核心。

02上游能力边界

oh-my-pi 的 computer 不是浏览器 DOM API，而是控制宿主机桌面的 Eval prelude。它和 browser prelude 的分工是：

域负责不负责
computer原生窗口/显示器、截图、原生输入、AX tree、剪贴板网页 DOM 选择器、页面 JS、CDP tab 控制
browser网页 DOM/ARIA、页面 JS、CDP tab原生应用、桌面窗口、系统级键盘鼠标

关键 API 摘要（详细语义见源文档；这里只用于评估移植面，不作为完整 API 契约）。

能力API 例子作用
窗口与显示器windows(app?, title?) / window(idOrFilter) / focusedWindow() / display(active|all|id)枚举、选择、等待目标窗口或显示器；窗口句柄带 id/app/title/pid/bounds。
截图screenshot({silent?}) / zoom({x,y,width,height})全窗口或显示器截图；坐标基于最近一次全量截图；区域放大不替换点击帧。
原生输入click / doubleClick / drag / holdMouse / type / press / holdKeys按键、鼠标、按住、拖拽；坐标输入必须先有截图。
AX 无障碍ax() / find() / ref() / elementAt(x,y) / focusedElement()读取 OS Accessibility/AX 树，按角色/标题/描述定位元素；引用有 stale-ref 语义。
元素动作el.click() / el.type() / el.press() / el.setValue() / el.perform()优先语义动作，不依赖截图；支持后台与 takeover 两种投递路径。
菜单win.menu.items() / win.menu.select([...])按标题选择菜单路径；不猜快捷键。
剪贴板computer.clipboard.read() / write()读写系统剪贴板。
应用computer.apps.list() / open(idOrNameOrPath, {activate?, reveal?})枚举/打开应用；部分能力仅 macOS。
批量脚本computer.run(fnOrCode, {args?, read_only?, timeout?})同一 worker session 内运行多步操作；返回结构化值，截图作为 Eval 图像。
能力探测computer.capabilities()报告 capture/input/AX/permission/screenLocked/displayAsleep 等能力。
安全控制control.acquire() / release() / state()请求显式前台控制；需要人工确认或策略批准。
等待wait(fn, {timeout?, interval?})等待窗口/元素/条件出现。
重要：它是一个带状态的 worker/session：截图帧、窗口句柄、AX 引用、输入锁、权限、审批和超时都属于语义的一部分。只复制几个函数名不构成移植。

03平台后端与差异

平台原生 backend必须接受的限制
macOS x64/arm64ScreenCaptureKit（14+）/ CoreGraphics（12/13）+ native AX + input需要 Screen Recording + Accessibility；由启动 omp 的终端/IDE 授权；部分 apps.open 能力仅 macOS。
Linux X11 x64/arm64X11 capture/input + AT-SPI需要可读 display、RandR/XTEST；后台输入依赖 XI2、/dev/uinput、udev/libinput 与 toolkit/window manager。
Linux Wayland x64/arm64RemoteDesktop portal / LIBEI + AT-SPI；ScreenCast portal/PipeWire逐窗口后台输入不可用；需要 PipeWire/libpipewire；compositor 限制；权限会话级。
Windows x64/arm64Win32 display/window capture + Win32 input + UI Automationbackground type/press 对无窗口元素会 BackgroundUnavailable；UIA/COM 与 DPI 适配。
其它已发布目标Unsupported unless native addon reports capabilities没有 backend 就不能假装可用。

所以“跨平台一致”应定义为 每个平台按自己的能力矩阵正确工作，不是所有平台拥有完全相同的 API/行为。仅凭 Cargo/Go 条件编译不能保证语义一致。

04go_hive 当前约束

当前判定：不进入 1.0。Hive 上游没有 computer-use，go_hive 也没有桌面层。把它加入核心等于新增产品面，而不是补齐 Hive。
  • Hive 上游没有 computer-use；这是新增能力，不是 go_hive 的 parity 项。
  • go_hive 当前约束是纯 Go、CGO_ENABLED=0；macOS ScreenCaptureKit/CoreGraphics/AX 通常需要 cgo/ObjC/Swift。
  • 现有 go_hive 只有浏览器域（Browser Bridge / browser_*）与 terminal_exec；没有窗口枚举、AX tree、原生鼠标键盘注入。
  • 当前发布规则：先完成 Hive 对齐，未完成前不新增功能；因此不能把 computer-use 塞进 1.0 对齐范围。
  • 安全模型不可省略：屏幕是不可信输入，原生输入要审批、可中断、可回滚，最好在专用账号/VM 中运行。
  • 跨平台一致性是 per-platform 能力矩阵，不是同一套语义；oh-my-pi 自己也列出了 Wayland/Windows/macOS 差异。

现有相近能力

现有能力能做什么不能替代 computer-use 的原因
Browser Bridge / browser_*网页 DOM、标签页、CDP、页面 JS不能操作原生应用；不是桌面截图/AX/系统输入
terminal_exec运行 CLI，可间接调用系统命令没有窗口枚举、AX tree、坐标输入、权限/审批模型
screencapture + attach_file人工截屏后作为附件不是 agent 可连续控制的桌面 runtime

05可选移植方案

方案形态收益代价/结论
A. OS CLI 包装调用 screencapture / osascript / grim / xdotool / PowerShell快；不改 Go 依赖没有 AX tree、后台输入、权限/审批；Linux/Wayland/Windows 差异大；不能称 computer-use 对齐
B. 独立 native sidecar（推荐，若以后做）Go core ↔ JSON-RPC/stdio ↔ Swift/ObjC/Rust/C++ helperGo 主二进制仍可 CGO=0；平台能力隔离；可独立签名/授权新增发布产物、安装/公证、TCC、Linux 桌面矩阵、Windows UIA/DPI、安全审计
C. 全部塞进 Go corecgo/native bindings 直接进核心单一二进制违反 CGO_ENABLED=0；平台条件编译复杂；安全边界差；不建议
D. 不移植（当前建议）继续使用 Browser Bridge / terminal；需要截图时人工 screencapture + attach_file不扩大攻击面；不违反对齐约束不能控制原生应用；不是 computer-use
推荐顺序：当前选 D（不移植）；若未来产品明确需要，先做 B（独立 native sidecar）的 macOS 单平台 spike，再决定是否扩到 Linux/Windows。不要先做 A 然后宣称“已支持 computer-use”。

为什么 sidecar 比 cgo 核心更合适

  • Go 主二进制继续满足 CGO_ENABLED=0，不把原生 ABI 带进核心。
  • macOS 的 ScreenCaptureKit/AX、Windows 的 UIA/COM、Linux 的 X11/AT-SPI 可以各自编译、签名、测试。
  • 权限/审批/崩溃隔离在 helper 边界；helper 不可用时返回明确 Unsupported，而不是伪造截图。
  • 升级和发布可以按平台独立灰度，不影响 go_hive 核心 slot。

06若未来实施：验收清单

  1. 默认关闭，显式配置开启；capabilities() 必须报告当前平台真实能力，而不是假设可用。
  2. 截图必须明确目标显示器/窗口、坐标帧、DPI/缩放；resize/display layout change 后必须重新截图。
  3. 每次输入先校验坐标来自最近一次同目标全量截图；AX 引用要能报告 stale ref。
  4. 审批/权限：读操作与写操作分级；对话式批准；Escape/中断释放按键与鼠标；前台 takeover 必须可回退焦点。
  5. 不得把屏幕内容当作用户授权；危险操作（发送、购买、删除、权限变更）要二次确认。
  6. 每个平台单独 E2E：macOS Screen Recording/Accessibility、Linux X11、Wayland portal、Windows UIA/DPI；无 backend 时返回明确错误。
  7. 不在没有浏览器的 headless 服务器上伪造成功；返回 Unsupported/Unavailable，而不是空截图。
安全底线：屏幕内容是不可信输入，不能授权动作；高风险操作必须二次确认；优先专用账号或 VM。缺少审批、Escape 停止、输入锁和权限失败路径的实现，不算 computer-use。

07决策

当前决策：不把 computer-use 加入 go_hive 1.0；不为它改 CGO_ENABLED=0、不新增原生依赖、不把它登记为 Hive 对齐项。

重开条件：Hive 对齐封版后，若出现明确的原生桌面自动化需求，再按“独立 native sidecar + 默认关闭 + 显式审批 + 每平台 E2E”立项；先做 macOS spike，用真实窗口/AX/输入证据决定是否扩平台。

复用方式：把本页作为需求评估和架构决策输入；不要把本页的 API 摘要当作已实现契约，实际实现必须另立 schema、权限和测试。
