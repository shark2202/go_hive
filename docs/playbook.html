GO_HIVE · PLAYBOOK RUNTIME

Python Playbook（.play.py）支持

go_hive 现在可以直接执行上游格式的 Python playbook：外部 python3 子进程 + stdio 行式 JSON-RPC，脚本字节不变，主二进制保持纯 Go / 无 cgo。
上游契约：core/framework/host/playbook/runner.py（PlaybookRun）、core/framework/tools/playbook_tools.py（run_playbook）。

01结论

入口
run_playbook · inline / path / saved
playbook 正文、playbook_path、playbook_name（playbooks/<name>.play.py）三条入口都已接通。
脚本契约
与上游一致
meta dict + async def run(args)；注入 converge / worker / tracker_query / tracker_count / lane / deadletter / log / phase。
解释器
外部 Python 3.8+
按 HIVE_PYTHON → python3 → python 解析；找不到时返回 status="unsupported"、dispatched=0，不假成功。
实现边界
不链接 libpython、零 cgo
Python 只是按需启动的子进程；六平台交叉编译不受影响，无新 Go 依赖。
重要口径：“已实现”指代码路径与本机真实 python3 测试通过（19 个桥用例 + 5 个工具层用例），不等于所有宿主环境已验证。未验证项见 09：Windows 无 Python 行为、真实 LLM worker 经桥派发、超大结果、全 Python 版本矩阵。

02运行架构

Queen / run_playbook tool (Go)
  → RunPlaybook (internal/colony/playbook_tools.go)
      → isPythonPlaybook? (.play.py / 非 JSON 正文)
      → StartPythonPlaybook (internal/playbook/python.go)
          → 解析解释器 (HIVE_PYTHON → python3 → python)
          → 临时目录写内嵌 bootstrap.py
          → exec python3 -u bootstrap.py
          → 发送 init(script)     ──────────────┐
          ← loaded(meta) / load_error          │ 行式 JSON-RPC
          → 校验 meta concurrency（Go 侧策略）  │ stdin/stdout
          → 发送 run(args, concurrency_cap)     │
          ← {"id":N,"method":"query_rows"}      │
          → 查 tracker → {"id":N,"result":rows} │
          ← {"id":N,"method":"dispatch_one"}    │
          → spawn 1 worker + 等报告             │
          → {"id":N,"result":report}            │
          ← result{meta,result,logs,deadletter,dispatched}
      → 落盘 colony.db 的 playbook_runs
  • 只有两个可调用体跨进程：dispatch_one（派一个 worker 并等终态报告）与 query_rows（tracker SELECT）。与上游 runner 注入面相同；converge、重试退避、lane、deadletter、log、phase 在 bootstrap 内实现。
  • RPC 并发：Go 对每个 dispatch_one 请求开独立 goroutine，脚本侧 chunk / lane 并发是真正并行；响应按 id 关联。
  • stdout 专用：bootstrap 把脚本 sys.stdout 指向 stderr，print() 不破坏协议；非 JSON 行明确报 cannot parse interpreter output。
  • 一次性进程：每次工具调用 = 一次 python3 子进程；load（编译 + 执行模块级代码 + 校验 meta/run）在 loaded 应答前完成，语法/契约错误在任何 worker 派发前返回。

04脚本契约（与上游一致）

meta = {"name": "fix-ci-failures", "description": "...", "concurrency": 4}

async def run(args):
    await converge(
        pending=lambda: tracker_query("SELECT id, job FROM ci_failures WHERE status='open'"),
        dispatch=lambda row, i: worker(
            task=f"Reproduce and fix CI job {row['job']}",
            data={"id": row["id"]},
            retries=1,
            backoff="exp",
            timeout=600,
        ),
        max_rounds=3,
    )
    return {"remaining": tracker_count("SELECT id FROM ci_failures WHERE status='open'")}
Hook语义跨进程
converge(pending=, dispatch=, max_rounds=1, circuit_breaker=None, chunk=None)每轮查 pending → 并发派发 → 再查；未解决行进入 deadletter否（bootstrap 内）
worker(task, *, profile, lane, skill, retries, backoff, timeout, schema, phase, data, goal)派一个 worker 并等报告；仅生命周期失败重试；每次尝试计入 dispatched是（dispatch_one）
tracker_query(sql) / tracker_count(sql)同步查询，返回行 dict 列表 / 行数是（query_rows）
lane(name, *, concurrency=1, rate_per_min=None)并发上限 + 启动速率门（≥ 60/rate_per_min 秒一个）否
deadletter.add(item) / .list() / .size / len()否
log(message) / phase(title)运行日志与阶段否
{
  "meta": {"name": "...", "...": "..."},
  "result": "<run() 的返回值>",
  "logs": ["phase: ...", "round 1: ...", "..."],
  "deadletter": [{"row": {...}, "reason": "unresolved after 1 round(s)"}],
  "dispatched": 3
}

05解析与保存规则

输入判定
playbook_path 以 .play.py 结尾Python（即使正文以 { 开头）
playbook_path 以 .play.json 结尾原生 JSON（正文不合法也报 JSON 错误）
inline playbook 正文是 JSON object原生 JSON
inline playbook 其它正文Python
playbook_name先找 playbooks/<sanitized>.play.json，再找 .play.py
  • inline Python 在 load 成功后按 meta["name"] 保存为 <colony>/playbooks/<sanitized>.play.py（与上游 _persist_script 一致），下一次 run_playbook(playbook_name=…) 即 resume：done 行不在 pending 查询里。
  • 原生 JSON playbook 仍保存为 .play.json，两条路径互不影响。

06生命周期、取消与安全

  • 进程组：python3 以独立进程组启动；run 结束/取消时先对进程组 SIGTERM，2s 后 SIGKILL，并 Wait 回收；脚本自己 fork 的子进程也在组里。
  • 临时目录：内嵌 bootstrap 写入 os.MkdirTemp("", "hive-playbook-*")，Close 时删除；PYTHONDONTWRITEBYTECODE=1 避免 __pycache__。
  • 最小环境：子进程只拿 PATH、HOME、locale、TMPDIR 等基础变量与解释器变量；不继承 HIVE_* 开关、provider API key 或凭据。
  • 加载超时：load 阶段最长 120s（模块级死循环兜底）；run 阶段没有人为总时限，靠 action="stop" / 会话取消终止。
  • 信任模型：与上游一致——playbook 是 Queen（可信作者）写的进程内代码，exec/子进程都不是安全沙箱；不要执行不可信来源的脚本。
  • 协议失败：非 JSON 输出、意外退出、无结果退出都返回 PythonBridgeError，附退出码与 stderr 尾部，不当作成功。

08已知差异（有意）

  1. 同步工具调用：本移植在工具调用内跑完整个收敛循环并直接返回结果/失败；上游先返回 started + run_id，后台完成后再注入 [PLAYBOOK_COMPLETE]。长批次会占住一轮工具调用；action="status" 看历史、action="stop" 可按 run_id 取消（取消后已 done 行保留，重跑即 resume）。
  2. colony 并发上限不临时抬高：上游在 run 期间把 colony max_concurrent_workers 抬到 max(原值, meta concurrency) 后恢复。Go admission 通道在 runtime 构造时固定；meta["concurrency"] 仍决定 chunk 默认值与 lane 警告，实际同时运行的 worker 数受 colony max_concurrent_workers 约束（超出排队）。与原生 JSON playbook 相同的现有边界。
  3. schema 未落到 worker spawn spec：BatchTask 没有 report_schema 字段；worker 仍拿到原生 report_to_parent 面。上游会把 schema 注入 worker prompt/工具。
  4. 结果值 JSON 化：非 JSON 类型（datetime、set 等）传输时用 str() 转换；上游快路径会因 json.dumps 失败报错。这里选择让 run 成功返回字符串化结果。
  5. print() 去 stderr：防止破坏 RPC；上游 print() 直接进宿主 stdout，不进 logs。

09未验证项

  • Windows 无 Python：查找与 HIVE_PYTHON 逻辑已写好，但未在无 Python 的 Windows 上实跑；Windows 清理只用 Process.Kill()（无进程组语义），脚本 fork 的子进程可能残留。
  • 任意第三方 import：bootstrap 不做包枚举，脚本继承宿主 python3 的 sys.path / site-packages；未验证某个特定第三方包可用性。
  • 其他模型 / provider：真实模型 E2E 只跑了本机配置的 deepseek-flash-1017（OpenAI 兼容网关）；其他 provider 的工具调用格式未逐一验证。
  • 超大结果 / 超长单行：协议单行上限 32 MiB，未做压力测试。
  • Python 3.8/3.10/3.12 等全版本矩阵：本机实测 3.9.6 与 3.14.7；bootstrap 只断言 >= 3.8。
真实 LLM 端到端已跑通（2026-11-21）：RunPlaybook → Python bridge → dispatch_one → colony worker → 真实 LLM → report_to_parent → bridge result。本机 HIVE_HOME=~/.hive-go、模型 deepseek-flash-1017；真实模型返回 tool_calls=[report_to_parent {"status":"success","summary":"REAL_LLM_E2E_OK","data":{"marker":"REAL_LLM_E2E_OK"}}]，bridge 信封 status=completed, dispatched=1, receipt={"marker":"REAL_LLM_E2E_OK"}，测试 PASS。该测试 opt-in，默认 skip。同一模型也已独立验证多模态输入：512px 字母图返回「H，绿色」；playbook 目前没有自动把图像传给 worker 的入口。
进程内多模态链路（真实模型，2026-11-21）：会话 session_20261121_012728_ea41d806，模型调用 attach_file({"paths":["…/shot.png"]})，工具结果 inline=image_block，下一轮输出「图片里是一个绿色的字母 **H**」。
