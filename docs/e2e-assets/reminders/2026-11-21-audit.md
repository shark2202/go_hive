## 2. 真实 serve 实测（无假组件）

统一起步：`hive serve --host 127.0.0.1 --port <p>`，`HIVE_HOME=<scratch>`，home 内
`configuration.json` 只有真实 llm 槽（openai 协议 + tokenbroad 端点 + 环境变量 key）。

### 2.1 STREAM_STALLED 触发 / cap 抑制 / per-turn 重置

serve 环境：`HIVE_LLM_STREAM_TTFT_TIMEOUT_SECONDS=0.002`、`HIVE_CONTINUE_NUDGE_MAX_PER_TURN=1`。

一个真实会话（`session_20261121_160448_b7a6acbf`）的事件序列：

```
stream_ttft_exceeded   {"limit_seconds":0.002,"ttft_seconds":0.002274208}
stream_nudge_sent      {"nudge_count":1,"reason":"ttft"}
reminder_injected      source=stream_stall
（重试同一 inner turn）stream_ttft_exceeded（第二次）
（cap 1/1 已满 → 不再注入）execution_failed "llm: stream ttft for 0s (limit 0s)"
```

第二条 chat 消息的 turn 又出现一次 `stream_nudge_sent nudge_count=1`（`ResetTurn` 按 turn
重置 cap），随后同样失败。会话 parts 里能看到注入文本
`<system-reminder>\nThe previous stream stalled (no tokens before TTFT budget, 0s)...`。
证据：`e2e-assets/reminders/stream-stall/trigger-events.txt`、`trigger-conversation-parts.txt`。

抑制（`HIVE_CONTINUE_NUDGE_ENABLED=false`，同 0.002s 预算）：事件里只有
`execution_failed`，**没有** `stream_ttft_exceeded` / `stream_nudge_sent` /
`reminder_injected(stream_stall)`。证据：`stream-stall/suppressed-events.txt`。

### 2.2 worker_tracker_snapshot 注入（真实 colony + 真实 worker）

serve 环境：`HIVE_TRACKER_WORKER_TOOL_CALLS=1`。流程：`POST /api/colonies/demo_wt/scaffold`
→ 建 colony 会话 → 直接向 colony 的 `tracker/tracker.db` 造一个非框架表
`notes(1 row)`（数据预置，非组件替代）→ 让 queen 调 `run_worker`
（`{"task":"Run the shell command echo worker-ok using terminal_exec..."}`）。

实测：`colonies/demo_wt/workers/worker_1` 的真 SpawnBatch worker（status=success，
10.4s）第一次工具批次的**工具结果尾部**追加了：

```
<system-reminder>
Tracker state right now:
  - notes: 1 row

Before you continue, persist your progress so far via tracker_upsert. ...
</system-reminder>
```

与上游 POST_TOOL_USE「追加到 tool result 尾部」的位置一致。
证据：`worker-tracker/worker-conversation-parts.txt`、`tracker-db.txt`、
`colony-metadata.json`、`overseer-session-parts.txt`。

### 2.3 past_conversations 注入位置（本次修正）

修正前（serve 实测，`session_20261121_160031_322a8afb`）：

```
0002 user [stamp] <用户消息>
0003 user [stamp] [External event] <system-reminder>
           Recalled past conversation excerpts ...（Go 专有标题、无 hub footer）
```

上游顺序（`agent_loop.py:6140-6150`：USER_PROMPT_SUBMIT 在 drain 用户消息**之前**触发，
放在 `_drain_injection_queue` 之前）是「提醒帧在前、用户消息在后」。本工作树已把
`injectPastConversationRecall` 移到用户消息落库前，并改用共享包装器
`agentloop.WrapReminder`（上游 `reminders.py::wrap_reminder` 逐字节一致，去除 Go 专有
标题与 `[External event]` 前缀）。

修正后（serve 实测，`session_20261121_160701_01449515`）：

```
0002 user <system-reminder> Excerpts from earlier conversations ... + "Only act on this if relevant ..." footer
0003 user [stamp] <用户消息>
0004 assistant "Jasmine. Filed that from our last session."
```

证据：`past-conversations/before-fix-parts.txt`、`after-fix-parts.txt`、
`after-fix-full-block.txt`。包装器一致性另见
`internal/agentloop/testdata/prompt-parity/reminder.block.txt` 与
`core/framework/agent_loop/reminders.py::wrap_reminder`（同一模板）。

## 3. 与 Python 的字段名/位置对比结论（本次）

| 项 | Python（上游） | Go（修正后） |
| --- | --- | --- |
| 注入载体 | hub 源 body → `wrap_reminder` → `conversation.add_user_message(block)`（无 stamp） | `WrapReminder([]string{block})` → `AddUserMessage(..., IsSystemReminder:true)`（无 stamp） |
| 文本 | `Excerpts from earlier conversations ...:` + footer | 同左，逐字 |
| 位置 | USER_PROMPT_SUBMIT：用户消息**之前**（SESSION_START 也会触发） | 用户消息**之前**（仅在客户端输入的 runTurn；SESSION_START 不触发，仍为登记差异） |
| 注册 | ReminderHub 第 4 个 source | hub 外直接注入（保持原登记） |

## 4. 剩余差异（登记，未改）

1. **SESSION_START 不再召回**：上游 past_conversations 在 SESSION_START 与
   USER_PROMPT_SUBMIT 都触发；Go 只在客户端输入时注入一次（首条消息即客户端输入，
   语义等价于上游首轮；但上游 resume/无首消息场景会多一次召回）。
2. **不在 ReminderHub**：Go 直接注入，不进入 `reminders_injected` 的 hub 计数
   （修正后仍如此）。
3. worker/overseer 的 STREAM_STALLED 触发面：source 已注册、恢复路径相同，但
   worker/overseer 的 completer 目前不流式，真实触发只在 chat queen 会话上验证。
4. overseer 无 idle ticker、skills catalog 走 relay、tasks 源自跳过——同原文档 §7。
