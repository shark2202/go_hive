## Where the 3 correctness disagreements came from (all answer/judge variance)

- `gpt4_194be4b3` (multi-session): Go answered "Three ..." (judge `no`),
  Python answered "Four ..." (judge `yes`). The queen's enumeration varied run
  to run; neither harness dropped evidence (`searched=true`, evidence=true both).
- `80ec1f4f_abs` (abstention): both answered the abstention correctly
  ("Zero ..." / "there is no record"); the judge accepted the Python phrasing
  (`yes`) and rejected the Go phrasing (`no`). Judge phrasing sensitivity, same
  judge model.
- `afdc33df` (single-session-preference): Go's personalized answer passed
  (`Yes`), Python's failed (`no`) under the rubric judge.

The `searched` column also differs question by question because the answering
model chose different tool paths per run (e.g. Go answered some single-session
questions from the auto-injected excerpts without calling `search_messages`).
No harness-level difference was observed in the field semantics:
`searched`/`evidence_retrieved`/`search_calls`/`tools`/`seconds` all behave as
documented on both sides.

## Field-level check (same question, both harnesses)

`smoke/go-smoke-results.jsonl` vs `smoke/py-smoke-results.jsonl` (question
5a4f22c0) carry the same keys and JSON types:
`question_id, question_type, abstention, question, answer, hypothesis, correct,
judge, judge_model, reader_model, searched, search_calls, evidence_retrieved,
tools, seconds` (optional `error` / `judge_error`).

- `answer` keeps the dataset's JSON type on both sides (32 of 500 S answers are
  numbers; see `2026-11-21-dataset-and-split.txt`).
- `summary.txt` is byte-identical between the two smoke runs once the
  `median seconds per question` line is normalised (same text format).
- Go additionally writes `summary.json` and keeps `homes/` (per-question
  `HIVE_HOME`, deleted after each question unless `--keep-homes`); Python's
  harness relies on pytest `tmp_path` for the homes. Both documented.

## Command surface actually exercised

```
# Go: run (real queen + real judge)
/tmp/hive-longmemeval run --data <s_cleaned> --questions <20 ids> \
  --model deepseek-flash-1017 --api-base https://token.tokenbroad.com/v1 \
  --judge-model deepseek-v4-pro --judge-api-base https://token.tokenbroad.com/v1 \
  --run-dir runs/go-20-subset --timeout 420 --verbose

# Go: rejudge (real judge, second pass)
/tmp/hive-longmemeval rejudge runs/go-smoke --judge-model deepseek-v4-pro \
  --judge-api-base https://token.tokenbroad.com/v1 --verbose
# -> runs/go-smoke/rejudged-deepseek-v4-pro/results.jsonl, original_judge set

# Go: reference reader (oracle), real reader + judge
/tmp/hive-longmemeval reference oracle --out runs/go-ref-oracle \
  --questions 5a4f22c0 --reader-model deepseek-flash-1017 \
  --reader-api-base https://token.tokenbroad.com/v1 \
  --judge-model deepseek-v4-pro --judge-api-base https://token.tokenbroad.com/v1

# Python: same 20 ids, xdist -n 4
cd core && HIVE_LIVE_API_BASE=https://token.tokenbroad.com/v1 \
  HIVE_LIVE_MODEL=deepseek-flash-1017 HIVE_LIVE_API_KEY=$KEY \
  HIVE_LME_JUDGE_MODEL=deepseek-v4-pro HIVE_LME_JUDGE_API_BASE=https://token.tokenbroad.com/v1 \
  HIVE_LME_JUDGE_API_KEY=$KEY HIVE_LME_QUESTIONS=<20 ids> \
  HIVE_LME_RUN_DIR=../runs/py-20-subset \
  uv run pytest tests/e2e/test_longmemeval.py -m live -n 4
# -> 20 results rows, 18 passed / 2 failed (the assert is the per-question verdict)
```
