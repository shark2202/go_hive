01导入路由

注册位置：internal/server/routes_colonies.go:42-58。六条路由对应 routes_colonies_import.go 的六个 handler。

方法路径handler用途
POST/api/colonies/importhandleImportColony一次性 multipart 导入，返回 201
POST/api/colonies/import/inithandleInitUpload初始化分片上传，返回 upload_id 和 received=0
PUT/api/colonies/import/chunk/{upload_id}?offset=NhandleChunkUpload按 offset 顺序写入分片，单片 ≤128 MiB
GET/api/colonies/import/status/{upload_id}handleUploadStatus查询已接收字节数，可断点续传
POST/api/colonies/import/finalize/{upload_id}handleFinalizeUpload校验 sha256、解包并落盘，返回 201
DELETE/api/colonies/import/{upload_id}handleCancelUpload取消未完成的上传并清理 staging

02小包：一次性 multipart

适合不需要断点续传的小归档。先打 tar，再 POST；归档里保留一个顶层 colony 目录。

tar -czf /tmp/mycolony.tar.gz -C /Users/mac/hive/go_hive/.hive_go/colonies mycolony

curl -sS -X POST 'http://127.0.0.1:8787/api/colonies/import' \
  -F 'file=@/tmp/mycolony.tar.gz' \
  -F 'name=mycolony_imported' \
  -F 'replace_existing=false'

成功返回 201：

{
  "name": "mycolony_imported",
  "path": "/Users/mac/hive/go_hive/.hive_go/colonies/mycolony_imported",
  "files_imported": 123,
  "replaced": false
}

字段

字段必填说明
file必填归档文件；tar / tar.gz / tar.bz2，最大 2 GiB
name可选导入后的 colony slug；不传就用归档顶层目录名
replace_existing可选true 覆盖已存在的目标；false 时冲突返回 409

03大包：分片上传

超过单次上限、网络不稳定或需要断点续传时使用。分片必须按 offset 顺序发送；服务端检查 Content-Length 和累计字节数。

  1. POST /api/colonies/import/init，提交 filename / total_bytes / sha256 / name / replace_existing。
  2. PUT /api/colonies/import/chunk/{upload_id}?offset=N 逐片上传；offset 必须等于服务端已接收字节数。
  3. GET /api/colonies/import/status/{upload_id} 查询进度。
  4. POST /api/colonies/import/finalize/{upload_id} 校验 sha256 并解包。
  5. DELETE /api/colonies/import/{upload_id} 可取消未完成上传。

1. 初始化

curl -sS -X POST 'http://127.0.0.1:8787/api/colonies/import/init' \
  -H 'Content-Type: application/json' \
  -d '{
    "filename": "mycolony.tar.gz",
    "total_bytes": 123456789,
    "sha256": "<64 位十六进制 sha256>",
    "name": "mycolony_imported",
    "replace_existing": false
  }'

2. 上传分片

curl -sS -X PUT \
  'http://127.0.0.1:8787/api/colonies/import/chunk/<upload_id>?offset=0' \
  -H 'Content-Type: application/octet-stream' \
  --data-binary '@/tmp/chunk-000'

3. 查询与完成

curl -sS 'http://127.0.0.1:8787/api/colonies/import/status/<upload_id>'

curl -sS -X POST \
  'http://127.0.0.1:8787/api/colonies/import/finalize/<upload_id>'

4. 取消

curl -sS -X DELETE 'http://127.0.0.1:8787/api/colonies/import/<upload_id>'

04归档布局与限额

单 colony
mycolony/
  metadata.json
  worker.json
  tools.json
  skills/
  ...
顶层目录名默认作为 colony id；可用 name 覆盖。
多根布局
colonies/mycolony/...
queens/...
memories/...
多根导入要求存在 colonies/<name>/。
限制值说明
归档上限2 GiB单次一次性上传的最大字节数
分片上限128 MiB单次 PUT 的 Content-Length 上限
并发上传32超过限制返回 429
staging TTL24 小时超时未完成的上传会被回收
支持格式tar / tar.gz / tar.bz2xz / zstd 明确拒绝

05常见错误

状态含义处理
409目标 colony 已存在加 replace_existing=true，或换 name
400归档格式/路径非法、缺少 file、字段非法检查 multipart 字段和 tar 内容
413归档或分片超过上限使用分片上传或缩小归档
429并发上传达到 32完成或取消一个上传后重试
415不是 multipart/form-data一次性导入必须用 multipart，不要直接 PUT tar
500staging 或解包 IO 失败查看 serve 日志；失败会回滚目标目录
覆盖语义：目标存在且没有 replace_existing=true 时返回 409，不会隐式覆盖。覆盖会先删除目标；解包失败会回滚，不留下半成品。

06为什么没有入口

前端
  • frontend/src/api/colonies.ts 没有 import 方法
  • frontend/src 没有 /api/colonies/import 调用
  • Sidebar / colony 页面没有 Import 按钮
CLI
  • contracts/cli-surface.json 的 hive colony 只有 list / info / delete
  • 没有 hive colony import 这样的命令；不要按伪命令操作
不要把 API 能力当成产品入口：服务端能导入，不代表用户在页面上能点到。当前只能 curl / API，或让 queen 用 terminal_exec 执行 curl。

07导出：不存在，不是未接线

路由、CLI、前端三层都没有 export/download；唯一接近的是 POST /api/colonies/{id}/reveal，它只在 Finder 打开目录，不产生可下载字节。

  • 没有 export / download 路由
  • 没有 CLI export
  • 没有前端导出入口
  • POST /api/colonies/{id}/reveal 只是在 Finder 打开目录，不产生可下载字节
  • 要导出只能自行 tar/zip 目录，或后续新增 export 能力
结论：当前是“能进不能出”。要真正导出，需要新增服务端 tar/zip 下载路由（含权限、大小、路径过滤），再补 CLI/UI；仅靠前端按钮无法完成。
