01

认识 Hive：一个 Queen，一群 Worker，一个账本#

先建立正确的心智模型，比记按钮重要。

你告诉 Hive 一个结果（“把这 5 个产品在 Hacker News 的发布情况查清楚，做成表”）。 Hive 不会让你先去画工作流图；它把任务交给一个有角色、有记忆的 Queen。 她先自己做一遍，摸清方法，然后把重复的部分拆给多个 Worker 并行做， 结果写进一个共享的 Tracker。你随时能看到进度、纠正方向、检查结果。

Queen

女王：你对话的那个人

长期存在的 agent，有身份（Growth、RevOps、Content…）、自己的记忆和工具。她负责理解目标、做试点、拆活、验收。

Colony

殖民地：一个可部署的工作单元

一个目录，装着 Queen、多个 Worker、Tracker、任务计划、Skills 和定时器。可以打包搬走，也可以按计划自己醒来。

Worker

工蜂：一次只做一件事

Queen 的克隆，任务单一、预算更紧、没有长期记忆、不能提问也不能再派活。做完必须回报。

Tracker

账本：完成的唯一真相

每个 Colony 一个 SQLite。Queen 定表结构和可写列，Worker 一行一行 upsert，Queen 用 SQL 验收。

它和“普通聊天机器人”差在哪

场景普通 ChatHive
一个一次性问题合适也能做，但没必要建 Colony
200 条线索，同一套流程你复制粘贴 200 次Queen 做一条，写成 Skill + Playbook，剩下交给 Worker 并行
跑几个小时 / 每天定时页面关了就停状态落盘、触发器唤醒、崩溃可恢复
要查“做到哪了”翻聊天记录直接查 Tracker 的行
决策需要你拍板你不知道它卡住了Queen 停车提问；Sentinel 可把问题发到 Telegram / Slack
核心机制

Hive 只有 一种执行原语：agent loop。Queen 是一个 loop，Worker 是同一个 loop 的克隆，只是任务更窄、工具更少、预算更紧。所以崩溃恢复、上下文压缩、用量计量、卡死检测只实现一次，每个 agent 都继承。

什么时候值得用 Colony

适合

  • 有很多结构相似的单位：线索、账户、工单、仓库、文档。
  • 要并行做，而且每次做法要一致。
  • 要跑几小时或按计划，重启后不能从头再来。
  • 结果要能查、审、导出，不只是读一段话。
  • 关键决策仍然要人来拍板。

不必用

  • 只有一句 prompt、一次回答。
  • 一次性脚本，5 分钟跑完。
  • 你还没想清楚“完成”的标准。
  • 没有可重复的单位，只有一件独特的大活。

安装与第一次启动#

官方推荐 quickstart；已经有 Python 环境的人也可以从 PyPI 装。

你需要什么

依赖要求说明
Python3.11+（推荐 3.12 / 3.13）quickstart 会建一个独立的 uv 环境
Node.js20+构建 Web Dashboard
git任意近期版本拉仓库、装 skill
uv / ripgrep可选缺失时 quickstart 会尝试自动安装

路线 A：从仓库安装（推荐）

macOS / Linux
git clone https://github.com/aden-hive/hive.git
cd hive
./quickstart.sh
Windows PowerShell
git clone https://github.com/aden-hive/hive.git
cd hive
.\quickstart.ps1

quickstart 会做这些事：

  • 建一个覆盖整个 workspace 的 Python 环境；
  • 把模型 API Key 加密存到 ~/.hive；
  • 问你用哪个模型（或订阅、Ollama）；
  • 构建前端；
  • 启动服务并打开 http://127.0.0.1:8787。

路线 B：从 PyPI 安装

终端
pip install "aden-hive[tools]"
hive open
注意

在仓库根目录执行 pip install -e . 装到的是一个占位包，跑不起来。仓库场景请用 quickstart；独立安装用上面的 aden-hive[tools]。

第一次打开

首次进入会看到欢迎对话框。它带一个 5 步的新手引导；你可以走完，也可以直接 Skip tour。跳过不影响任何功能。

确认服务在跑

终端
curl -s http://127.0.0.1:8787/api/health
# {"status": "ok", "sessions": 0, ...}

日常启动只需要：

终端
cd hive
hive open            # 启动服务并打开浏览器
# 或
hive serve --port 8787
hive serve --open    # 等价于 open

停止：在运行 hive serve 的终端按 Ctrl+C。服务默认只监听 127.0.0.1，本机以外访问不到。

模型怎么配

装完之后，Models 页面是模型的总开关。它把模型分成几个槽位：

槽位作用建议
Main model所有 Queen 默认用它思考选你预算内最强的通用模型
WorkersColony 派出的 Worker 用可以选更便宜的模型；不设则跟 Main 一样
Vision fallback给看不了图的模型描述图片主模型不支持视觉时再设
Judge回答是/否问题（卡死判断等）高级项，默认不设也能跑
省事做法

如果你已经在环境变量里放了密钥（比如 ANTHROPIC_API_KEY、OPENAI_API_KEY），Hive 能直接用；也可以在 configuration.json 里写 api_key_env_var，避免把密钥写进文件。详见 §16。

订阅登录

Claude Code、Codex、Kimi Code 等“订阅登录”可以被 Hive 检测并用于主模型。但把订阅计划无人值守地跑在其他 agent 后面，可能违反计划条款，账号可能被限流或关闭。官方支持的路径是 API Key；用订阅请自担风险。

03

第一个任务：从一句话到真实回答#

这一段照着截图做，5 分钟能走完。

在首页写下任务

输入框提示是 “Describe a task for the hive…”。用自然语言写清结果，不用写给 AI 的咒语。示例：

任务示例
用三句话介绍你能帮我做什么，并举三个适合你的业务场景。

这是本手册实机用过的任务；你也可以换成自己行业里的一件真事。

选择 Queen

点发送后，Hive 不会用分类器猜，而是弹出 “Who do you want to talk to?”，让你选。默认 6 位：Growth、RevOps、Content、Lead Generation、Outbound、Brand & Design。

在对话里等她的回答

进入 Queen 的 DM 后，你会看到用户消息、模型思考（Thought，默认折叠）、工具调用标签，然后是正式回答。回答过程中可以 Stop；也可以继续排队消息，或点 Steer 立刻插话改变方向。

看懂这几个按钮

  • Action Plan：她的任务计划，右侧栏也能看到；会随进展更新，重启后还在。
  • Start Colony：把当前这件活升级成一个 Colony；你也可以等她在判断需要并行时主动提议。
  • Queue a message：她正在干活时，消息默认排队；点 Steer 才是立即插入当前回合。
  • Sessions：同一 Queen 的多个对话；每个会话独立保存，可切换历史。
判断标准

如果她开始问“你有多少条数据 / 要不要并行 / 输出成表还是文档”，说明这活已经具备 Colony 的形状。别急着说“都可以”，先把范围、数据位置、交付形式说清，能省掉一半返工。

她问你问题时，长什么样

当决策需要你拍板，Queen 会停车，弹出一张多问题卡片：每题有预设选项，也允许自由输入；全部答完后点 Submit All，她继续。Worker 不会直接问你，只有 Queen 会。

04

第一个 Colony：把一条活变成一条产线#

两种入口：Queen 提议，或你直接建。

入口 A：Queen 提议，你确认

她在对话里判断“这需要并行 / 需要定时 / 会跑很久”，会给出一个 Colony 提案。只有你确认后才会真正落盘，不会背着你 fork。确认后对话会切到 Colony 页面，她进入 colony 阶段。

入口 B：侧边栏直接创建

点侧边栏 COLONIES 旁的 +，填三样东西：

字段怎么填注意
Queen Bee选谁当这个 Colony 的负责人必须选；决定人格、模型和工具集
Colony Name短、英文、能当目录名实机输入 growth-lab，落盘为 growth_lab
Goal（可选）这个 Colony 要持续追求的结果建议写；它会成为 Queen 的长期目标

Colony 页面长什么样

Data

Tracker 表格

Queen 建表，Worker 写行。UI 里可以浏览表、筛选、看单条记录；Queen 用 SQL 验收。

Plan

任务计划

Queen 的 to-do，持久化、可编辑。它记“打算做什么”，Tracker 记“已经做成了什么”。

Automations

无人值守

Sentinel 在你离开时盯住停车的 Queen；定时器让 Colony 按 cron / interval 自己醒来。

Workers

并行工蜂

看谁在跑、跑了多久、属于哪个批次；可以停单个，也可以全部停。

磁盘上是什么

Colony 是一个自包含目录：~/.hive/colonies/<name>/。里面有 metadata.json、worker.json、tracker/tracker.db、skills/、triggers.json，以及 Queen 和 Worker 的会话状态。Open colony folder 可以直接在文件管理器里打开它。

实机里，Growth Lab 创建后 Queen 先要了 4 个澄清问题，然后才会开表、派工。这很正常：她宁可先问清楚，也不愿拿“最佳实践”糊一份清单。

Org Chart：组织不是装饰

Org Chart 把“谁向谁汇报、谁负责哪个 Colony”画出来。新人默认 6 位，点 Leader Catalog 可以雇佣其余角色，或新建一个职位。点某位 Queen 的卡片进入她的档案。

Queen 档案：六个面

点进任一 Queen，会看到她的 dossier（档案）。左边是统计（记忆数、聊天数、模型），右边是六个部分：

部分是什么你能做什么
Persona她是谁：人格、背景、行为准则整段编辑，或按章节改
Soul她“变成了谁”：自己写的自我认知审阅每日提案、手改、恢复历史版本
Mind她用哪个模型思考单独给她换模型（不影响别人）
Memory她跨会话记住的笔记查看、编辑、删除
Craft她能用的 Skills 和 Tools按 Queen 配置工具集
Colonies她负责的 Colony跳转、打开

Settings：不需要一开始就动

头像菜单里的 Profile & settings 有五个区：Profile（显示名、主题、密度、动效）、AI Model、Rate Limits、Walkthrough、Developer。Developer 里有调试信息；Rate Limits 用于社交平台工具的限额，不是模型费用。

不要找 TUI

当前版本没有终端 TUI。早期的 Textual 三栏界面已从代码中删除，roadmap 把 “The terminal UI” 列在 Retired in V1，并建议使用 hive open 的 Web Dashboard。终端里能做的只有命令（§15），不是交互界面。

06

让 Colony 定时跑：Triggers + Sentinel#

“我不在的时候，它也能自己干活。”

打开任一 Colony，右侧 Automations 标签。这里有两块：Sentinel（停车时盯住 Queen）和定时任务（按计划唤醒 Colony）。

建一个定时任务

点 Create schedule

弹出 New schedule，填名称、触发方式、时间、任务文本。任务文本是每次触发时 Queen 收到的指令，要写成可独立执行的一句话。

选触发方式

模式适合注意
Daily每天固定时间，如早报按你的本地时区显示
Weekly工作日/每周几可多选星期
Interval每 N 分钟 / 小时巡检从创建后不久开始算
Advanced任意 5 段 croncron 按 UTC 解析，界面会换算成本地时间预览

创建后看卡片

任务会立刻出现在 Automations 里，显示名称、计划、active 状态和下一次倒计时。实机用 cron 0 9 * * * 创建，UTC 09:00 在东八区显示为 Daily at 5PM，下次在 5 小时后。

三个硬约束

1. 服务必须一直运行。触发器是 hive serve 进程里的 asyncio 任务，不是系统 cron；终端关了、服务停了，就不会触发。

2. Colony 会话必须在运行中的服务里加载。触发只会注入到已加载的 Queen 会话；冷会话不会被自动拉起。

3. 错过的时间点不会自动补跑。当前 Python 实现在下次加载时会把错过的 tick 静默跳过（并推进 last_fired_at），另有 /colony/resolve_missed 接口供 UI 选择 fire_latest / skip / reschedule。不要把它当“保证送达”的调度器。

手动触发与排障

API 提供 POST /api/sessions/{id}/triggers/{trigger_id}/run，可以强制立即跑一次；activate / deactivate 控制启停。UI 的卡片会显示 active 和 next-fire。若卡片一直倒计时但从不触发，先检查服务日志里有没有 Timer trigger … tick failed，再确认 Colony 会话仍在（§22）。

Sentinel：停车时把你叫回来

Queen 需要你拍板时会停车（loop 被持久化到磁盘，等几天也行）。Sentinel 是可选的看护者：Queen 一停，分类器判断该 nudge 她继续、标记完成，还是升级给你。默认发到 Hive Inbox；在 Automations → Manage Sentinel 里可以接 Telegram 或 Slack，并设置“阻塞多久后升级”。你回复后，答案被注入，Queen 从停下的地方继续。

建议

先只开 Hive Inbox 跑一天，确认它不会为琐事打扰你；再接 Telegram/Slack。连接 bot 的 token 存在加密凭据库里，不在配置文件里。

07

写好任务简报：决定成败的一半#

Queen 很能干，但她不能替你想清楚要什么。

不要写“帮我做增长”。写清楚下面七件事，Queen 的输出质量会立刻不同：

要素问自己示例
结果完成后我应该拿到什么？一张 5 行的对比表 + 一段结论
范围包括什么，不包括什么？只查原始发布帖，不算顺带提及
输入数据在哪？格式是什么？CSV 在 /data/leads.csv；或“我可以给你看 dashboard”
约束时间、预算、合规、不能碰的东西不要给未验证的线索发邮件；只用公开数据
交付形式表、文档、图表、还是直接改文件？先给表，再给一页纸结论
验收标准什么算“对”？每一行都有来源链接；缺数据的行标 not found，不写 0
停止条件什么情况下不要继续烧钱？同一来源连续失败 3 次就停，报给我

差的写法

反例
帮我研究一下这几个产品，写个报告。

范围、数量、来源、格式、验收全是空白。Queen 只能猜，最后你会得到一份“看起来很努力”的泛泛之谈。

好的写法

正例
研究这 5 个产品在 Hacker News 的发布情况：
- 只算 Show HN / Launch HN / YC 官方发布，不算顺带提及
- 每个产品给：标题、日期、点数、评论数、链接
- 用 HN API 核对数字；找不到就标 not found，不要填 0
- 最后给一张对比表和三条结论
- 同一产品连续 3 次请求失败就停下告诉我

让 Queen 先做试点，再放大

Colony 的正确节奏是 execute first, then systematize：

先做一条

让她自己完成一个单位（一条线索、一个产品、一份文档），把方法和坑摸清。

把方法写成 Skill / Playbook

试点成功后，让她把步骤固化。之后每个 Worker 都按同一套方法做，结果才可比。

再 fan out

用 run_worker / run_playbook 并行；每个 Worker 写 Tracker，Queen 用 SQL 验收。

一句话原则

如果你不能用三句话说清“什么算完成”，先别建 Colony。先用 Queen 的普通对话把问题想清楚，再升级。

08

管理 Queen：人格、模型、记忆、工具#

Queen 不是通用调度器，她是一个有岗位的负责人。

默认 6 位在岗：Growth、RevOps、Content、Lead Generation、Outbound、Brand & Design。Org Chart 的 Leader Catalog 里还有 Finance、Legal、Talent、Operations、Product Strategy、Technology、Market Research 等角色，可以按需雇佣；也可以新建一个自定义职位。

给她换模型

进入她的档案 → Mind，从同一个模型列表里选。她的运行中会话会在下一次模型调用时切换；她的上下文窗口跟着她的模型走。主模型变更不会影响已经单独设了模型的 Queen。

她的记忆与人格

  • Persona：你写的“她是谁”。修改会影响之后所有对话。
  • Memory：她从对话里反思出来的长期笔记；可查看、编辑、删除。
  • Soul：她每天从聊天里读自己、用第一人称写的“我变成了谁”。默认 review 模式，提案等你批准；也可以设 auto。

Soul 的配置在 configuration.json 的 soul 段：每日几点反思、最多改几条、每个部分的字符上限、证据要求（比如“必须引用两个不同的人/会话”）。详见 §16。

给她配工具和技能

Queen 档案 → Craft，或 Configuration → Skills 里选 “Configuring: 某位 Queen”。工具可以按 Queen 授权；Colony 还可以有自己的允许列表，Worker 继承更窄的一组。

Queen 之间写信（Queen Mail）

开启 queen_mail 后，Queen 获得 list_queens 和 message_queen：她可以给另一位 Queen 写信，对方在自己的一个专门会话里收到，回复会唤醒写信人。默认关闭；可以限制参与者、每日封数与链深度。

还可以把一位 Queen 配成 Claude Code queen：她不是 Hive 的 loop，而是真正的 Claude Code 进程，在指定目录里跑，通过 queen mail 参与。她的 cwd 是 Hive 里唯一能“绑定任意目录”的入口，详见 §17。

Decommission

档案里的 Decommission 会让这位 Queen 退出在岗列表；不是删除数据。她的会话、记忆和 Colony 仍在磁盘上。想彻底清理，用 hive janitor 或手动处理目录（先备份）。

09

看懂 Colony：Data、Plan、Workers#

不要只读聊天记录。真正的进度在 Tracker 里。

Data：共享账本

每个 Colony 一个 SQLite：~/.hive/colonies/<name>/tracker/tracker.db。Queen 建表并声明 Worker 可以写哪些列；Worker 每个工作单位 upsert 一行；Queen 用 SQL 查询验收。UI 的 Data 标签是这张表的表格视图，可以浏览、筛选、看单条记录。

Tracker 的典型结构（示意）
-- Queen 建的表，Worker 只能写允许的列
CREATE TABLE products (
  id            TEXT PRIMARY KEY,
  name          TEXT NOT NULL,
  launch_date   TEXT,
  points        INTEGER,
  comments      INTEGER,
  url           TEXT,
  status        TEXT,          -- done / not_found / blocked
  notes         TEXT
);

-- Queen 验收：还有多少没做？
SELECT status, COUNT(*) FROM products GROUP BY status;

实际表结构由 Queen 按任务决定，不一定是这个形状。重要的是：结果是一行行数据，不是一段散文，所以可以查、可以审、可以重跑。

Plan：她打算做什么

Plan 是持久的文件型任务列表，会随会话重启保留。它和 Tracker 的分工：Plan 记 意图（要做什么），Tracker 记 事实（做成了什么）。你可以在右侧 Plan 面板里直接改，也可以在对话里让她调整。

Workers：并行执行者

Workers 面板把活动中的和历史的工蜂分开，按批次分组。每个 Worker 有自己的任务、预算和工具子集；默认同时最多 4 个（超出排队）。你可以停单个，也可以全部停；Worker 的终态报告会以 [WORKER_REPORT] 回到 Queen 的对话。

现象先看哪里动作
一直“在跑”但 Data 不增长Workers → 选中该 Worker看它卡在哪个工具；必要时停掉，让 Queen 重派
结果有缺口Data → 筛选空/异常行让 Queen 只重跑这些行，而不是全部重来
同一行被反复改Data → 记录详情检查 Worker 是否越权/重复认领；收窄任务范围
Queen 停车不动对话 / Sentinel回答她的问题；或让 Sentinel 升级给你

怎么问“做到哪了”

最有效的方式不是让她复述，而是让她查：

给 Queen 的话
查一下 tracker：按 status 分组给我数量；把 blocked 的行列出来，
说明每行为什么卡住；不要重跑已经 done 的行。

她会用 SQL 查，然后把结果和下一步动作一起给你。这比“进度如何”有效得多。

验收

要求她“逐行给来源链接”，并在 Data 里抽查 2–3 行。Hive 的强项是过程可审计；不要把它退回成“读一段总结就信”。

Skills：把一次成功变成每次都能复用#

Agent Skills 开放格式；Claude Code / Cursor 的 skill 可以直接用。

Skill 是一个带 SKILL.md 的文件夹，教 agent 怎么做一类任务。它按需加载：会话开始时只看到“名称 + 描述”的目录，判断相关时才读全文，再按需读脚本/参考资料。这让几百个 skill 也不会撑爆上下文。

放在哪里

范围路径用途
项目（Hive）<project>/.hive/skills/只属于这个仓库
项目（跨客户端）<project>/.agents/skills/Claude Code / Cursor 等共用
用户（Hive）~/.hive/skills/个人所有项目可用
用户（跨客户端）~/.agents/skills/本机所有兼容工具可见
框架内置随 Hive 发布操作协议类 skill

一个最小可用 Skill

~/.hive/skills/growth-experiment-brief/SKILL.md
---
name: growth-experiment-brief
description: Turn a growth bottleneck into a prioritized experiment brief. Use when a colony plans or reviews growth experiments.
---

# Growth Experiment Brief

## When to use
Use this when a bottleneck has to become a testable experiment.

## Steps
1. State the bottleneck and the metric it shows up in.
2. Write the hypothesis: change X for Y, metric Z moves by N% in D days, because …
3. Name the primary metric, guardrail metric, and minimum detectable effect.
4. Estimate sample size and run time; shrink scope, not rigor.
5. Define the stop rule before launch.
6. Record one row in the colony tracker: owner, status, metric, decision.

## Output
A one-page brief: bottleneck, hypothesis, design, metrics, sample size, stop rule.

描述（description）决定 agent 会不会在正确的时候想起它。写清“做什么 + 什么时候用”，不要写“帮助处理 XX”。

CLI 管理

终端
hive skill list                         # 按范围列出所有 skill
hive skill init my-skill                # 生成 SKILL.md 模板
hive skill validate ~/.hive/skills/my-skill/SKILL.md
hive skill install deep-research        # 从 registry 安装
hive skill install --from https://github.com/org/repo.git --version v1
hive skill trust /path/to/project       # 永久信任该仓库的项目级 skill
hive skill doctor                       # 健康检查：可解析、脚本可执行、工具可用
信任门禁

项目级 skill 来自你 clone 的仓库，可能往系统提示里注入指令。首次加载会要求你确认：仅本次 / 永久 / 拒绝。用户级和框架级 skill 始终受信。CI 里可用 HIVE_TRUST_PROJECT_SKILLS=1 跳过交互，但只在你信任仓库时这么做。

让 Queen 自己写 Skill

试点成功后，直接说：“把刚才这套方法写成 skill，放到这个 Colony 的 skills 目录，下一次让 Worker 按它做。” 她写出的 skill 会出现在 Colony 的技能目录里，后续 Worker 能直接加载。技能不是文档摆设，它是让并行结果保持一致的关键。

Memory：她记得你，但你可以检查#

不是向量数据库，是你可以打开读的 markdown。

Queen 的记忆按范围分：global（关于你和业务的通用背景）、per-queen（她自己的笔记）、per-colony（某个 Colony 的上下文）。每轮对话前，Hive 会把相关的记忆和最多几段过去对话的摘录放到她眼前；她也可以主动用 search_messages 搜索历史。

记忆是怎么写的

不是每句话都写。Queen 每几次回复做一次反思（默认每 6 次），读回最近对话，更新 memory 文件；每几次反思再做一次整理（合并、去重）。压缩上下文和会话结束时也会触发一次。频率和使用的模型在 configuration.json 的 memory_reflection 里配。

三种“记得”

类型怎么用在哪看
长期笔记每轮注入相关片段Memory 页面 / ~/.hive/memories/
过去的对话每轮自动放最多 6 段相关摘录；也可 search_messages会话历史 / Memory
时间线（可选）你说过的事件、事实、计划，按日期检索；search_timeline需要开启 memory_timeline 标志
实用习惯

第一次合作时，主动给她一段“公司/产品/客户/交付偏好”的背景，让她写进 global memory。后面每个 Queen、每个 Colony 都会受益。发现记忆过时，直接在 Memory 页面改，不要指望她自动忘掉。

隐私

记忆、会话、Tracker 都是本机文件，位置在 ~/.hive。没有云端同步（除非你显式接了云推送钩子）。备份和迁移见 §19。

Credentials：密钥、OAuth 与告警通道#

一个加密库，所有 provider 和集成共用。

Credentials 页面分两块：Built-in Connections（Telegram / Slack 这类告警通道）和 API Keys（各家 provider 与业务集成）。实机是 0 active · 314 available，因为还没连任何外部账号；其中 312 个是 API Key provider，2 个是内置连接。

三种放密钥的方式

方式适合注意
Credentials 页面日常使用加密存在 ~/.hive/credentials；需要 HIVE_CREDENTIAL_KEY
环境变量CI / 临时如 ANTHROPIC_API_KEY、OPENAI_API_KEY；不要写进仓库
configuration.json 的 api_key_env_var自定义网关 / 私有端点文件里只有变量名，没有密钥本身
安全

不要把 key 发给 Queen 让她“记一下”。她写下的任何内容都可能进入会话、记忆或日志。用 Credentials 页面或环境变量；read_file 对凭据目录有拒绝列表，但最稳妥的是根本不把密钥放进工作区。

Telegram / Slack 的 bot token 用于 Sentinel 通知，不会自动给 Queen 开 Slack/Telegram 工具权限。反过来，给 Queen 开 Slack 工具是另一套 OAuth/凭据。别把“能给你发告警”和“能以你的身份发消息”混为一谈。

Sentinel：无人值守时的最后一层#

它不是另一个 agent，是一个看护流程。

Sentinel 按 Colony 开关。Queen 停车（提问、被阻塞、结束回合）时，分类器判断三种结果：

Nudge

推她一把

她只是犹豫或漏了一步，Sentinel 给一个提醒让她继续。

Done

标记完成

工作已经结束，不需要打扰你。

Escalate

升级给你

真的需要人拍板，发到 Hive Inbox / Telegram / Slack。

怎么开

  1. Colony → Automations → Manage Sentinel。
  2. 先确认目的地在 Hive Inbox 能收到；需要手机提醒就接 Telegram 或 Slack（填 bot token，点验证，检测 chat/channel）。
  3. 设置“阻塞多久后升级”。太短会被琐事打扰，太长会真的卡住。
  4. 保存并启用。Queen 停车后，你会在选定渠道收到一条消息；直接回复即可把答案注入，她继续。
权限边界

如果 Queen 能通过聊天应用接收陌生人的消息，再配合 Claude Code queen 的 bypassPermissions 或 Bash，陌生人就离“在你的机器上执行命令”只有几条消息的距离。用 queens、max_depth、daily_limit 限制谁能找到她，以及她一天能说多少。

Sentinel 的价值在“异常升级”，不是“全自动”。把常规路径做成 Skill/Playbook，把例外留给它和你。

ANTHROPIC_API_KEY / OPENAI_API_KEY / OPENROUTER_API_KEY / HIVE_API_KEY模型密钥；也可用 api_key_env_var 指向自定义变量
BRAVE_SEARCH_API_KEY / EXA_API_KEY网页搜索工具
HIVE_MAX_CONCURRENT_WORKERS若你的版本读取该变量，可控制并发上限；以实际构建为准
HIVE_ENABLE_LLM_LOGS开启本地 LLM 调试日志，供 hive debugger 查看
换机器

只复制 configuration.json 不够。HIVE_CREDENTIAL_KEY 必须一起搬，否则加密凭据解不开；模型 key 若在环境变量里，也要在新机器上重新设置。

工作目录与 Git：Hive 在这里和 coding harness 不同#

先看清限制，再决定怎么接你的仓库。

Claude Code、Codex CLI、Pi 这类工具是“进程即会话”：你 cd 到项目里启动，工作目录就是进程 cwd；Codex 还提供 --cd/-C，Claude Code 提供 --add-dir / /cd。Hive 是常驻 Web 服务 + 多个会话，普通 Queen 会话没有“工作目录”这个可设置字段。

能力Python Hivego_hive
会话级工作目录没有；工具默认用会话目录没有；queen 工具根 = 启动 cwd，Colony = Colony 目录
任意绝对路径读写可以（凭据目录等 deny-list 除外）文件工具受限在 sandbox root；terminal 可到任意路径
内置 git 工具没有；只能用 terminal 跑 git没有；同上
绑定任意目录只有 Claude Code queen 的 cwd不支持
Agent/Colony 目录支持（受允许根限制）支持（同一套允许根）

Python 版：工具默认在哪

每次会话，框架把 session_cwd 设为该会话的目录，并强制注入给声明了这个参数的工具；模型不能覆盖它。DM 会话在 ~/.hive/queens/<queen>/sessions/<id>/，Colony Queen 在 ~/.hive/colonies/<colony>/queens/<queen>/sessions/<id>/。文件工具对绝对路径是放行的（只挡凭据目录等），所以你可以让它直接处理某个仓库：

给 Queen 的话
这个仓库在 /Users/me/code/my-repo。
先读 README 和 package.json，再运行测试；
所有改动都留在这个目录里，不要碰其他路径。
需要 git 操作时用 terminal_exec 执行，并在提交前把 diff 给我看。

这不是“绑定”，是指路。会话的默认相对路径仍然在会话目录里，所以要么给绝对路径，要么在命令里 cd。

唯一真正的目录绑定：Claude Code queen

在 queen_mail.claude_code.<id> 里设 cwd，Hive 每轮用这个目录启动真正的 Claude Code 进程；add_dirs 追加目录，allowed_tools 里放开 Bash(git:*) 就能跑 git。她通过 queen mail 参与，不是普通聊天会话；UI 只能只读查看她的 transcript。

configuration.json 片段
"queen_mail": {
  "enabled": true,
  "claude_code": {
    "queen_claude": {
      "name": "Claude",
      "api_key": "sk-ant-...",
      "cwd": "/Users/me/code/my-repo",
      "permission_mode": "acceptEdits",
      "allowed_tools": ["Read", "Edit", "Bash(git:*)", "Bash(npm:*)"],
      "add_dirs": ["/Users/me/code/shared-lib"],
      "timeout_minutes": 30
    }
  }
}
权限

permission_mode: "bypassPermissions" 会让 Claude Code 几乎不受限制。再加上 Queen 能接收外部消息，就等于把 shell 暴露给能给她写信的人。默认用 default 或 acceptEdits，只放开必需的 allowed_tools。

今天想让它做仓库工作，怎么做

  1. Python 版：给绝对路径，要求用 terminal_exec 跑 git status / diff / commit；先让它读仓库说明和测试命令。
  2. go_hive：从仓库根目录启动 hive serve，Queen 会话的文件工具根就是该目录；或者 serve --colony <colony-dir>，根是 Colony 目录。
  3. 要稳定的目录绑定 + git 自动化：用 Python 版的 Claude Code queen，配 cwd 与 allowlist；这是目前唯一的一等公民实现。
没有 git 工具

Hive 两边都没有 git_status / git_diff / git_commit 之类的内置工具。Git 只有三种用法：terminal 里跑 git；hive skill install --from <git-url> 安装 skill；GitHub 远程 API 集成（需要凭据，和本地仓库是两回事）。

REST 与 SSE API：把 Hive 接进你的系统#

本地无鉴权；只绑 127.0.0.1 时是安全的默认。

服务默认 http://127.0.0.1:8787。前端就是这套 API 的消费者，所以能力基本都在。下面是最小集。

方法 / 路径作用
GET /api/health健康检查；返回会话数、资源状态

POST /api/sessions/{id}/chat发消息；body {"message": "…", "images": [...]}
GET /api/sessions/{id}/eventsSSE 事件流；?types= 过滤
GET /api/sessions/{id}/triggers列出触发器（含 next-fire、火计数）
POST /api/sessions/{id}/triggers创建定时触发器

终端

# 3) 跟 SSE（另开一个终端；-N 关闭缓冲）

创建一个定时任务（等价于 UI）

终端
curl -s -X POST "$BASE/api/sessions/$SESSION/triggers" \
  -H 'Content-Type: application/json' \

    "name": "morning-growth-check",

成本与安全：把油门和刹车都装上#

Hive 给你计量和硬预算，但不替你设美元上限。

成本控制

  • 每个 Worker 有硬预算：回合数、工具调用数都有上限，卡住的 Worker 会自己停。
  • 并发有上限：默认同时 4 个 Worker，其余排队。任务再大也不会瞬间打满。
  • Worker 可以用更便宜的模型：在 Models 页单独设 worker_llm，Queen 仍用强模型。
  • 每次模型调用都计量：用量在会话/运行记录里可见。
  • 没有美元止损：roadmap 明确说还没有按金额中止的 cost_guard。要控成本，靠模型选择、任务范围、并发和人工巡检。

安全清单

  • 默认只监听 127.0.0.1；不要把无鉴权的 API 开到公网。
  • API Key 放加密凭据库或环境变量；不写进仓库、不贴进对话。
  • 项目级 Skill 首次加载要确认；不信任的仓库不要用 HIVE_TRUST_PROJECT_SKILLS=1 一把梭。
  • 按 Queen / Colony 配工具允许列表；写权限（邮件、CRM、GitHub）单独授权。
  • Claude Code queen 不要随便给 bypassPermissions 和裸 Bash。
  • 把网页抓取结果当不可信输入：里面可能藏着让 agent 执行命令的提示词。敏感操作要人工确认。
  • 定期跑 hive janitor，避免旧 transcript 和日志无限增长。
威胁模型

Hive 的 agent 有真实的 shell 和文件能力。最大的风险不是模型“变坏”，而是它被网页、邮件、聊天消息里的内容诱导，去执行了你没授权的动作。把工具权限收窄、把外部输入当敌意、把关键步骤留给人确认，比换一个“更安全的模型”有效。

附录：go_hive（Go 移植版）现在能做什么#

如果你在评估纯 Go 版本，先把预期放对。

./go_hive/go-hive 是 Python 版的纯 Go 复刻，模块在 go_hive/go-hive。它已经有可运行的 serve + 会话创建 + chat + SSE + 内置工具 切片，但 colony 运行时和触发器生产链路没有闭合。

能力状态说明
hive serve / hive chat可用P0 会话切片：创建会话、POST chat、SSE 事件、持久化 transcript
Web Dashboard可用前端已 vendor 到 frontend/，由 Go 服务托管
CLI 命令集基本对齐serve / open / queen / colony / session / chat / skill / mcp / janitor / debugger
触发器（cron / interval / webhook）未接线数据结构、cron 解析、REST 路由、定时循环和单测都在；但生产代码从不给 Session.QueenExecutor 赋值，也没有 InjectTrigger 实现，tick 只会更新倒计时，不会真正注入；triggers.json 启动时也不恢复
提醒中枢 ticker未接线Hub.Start 生产零调用；idle nudge 等 source 未注册
Colony 运行时（worker 调度）部分代码和单测在，生产入口（Host.Start / SpawnBatch）没有调用者
终端 TUI没有与 Python 版一样，只有 CLI
工作目录绑定没有Queen 工具根 = 启动 cwd；Colony 会话 = Colony 目录；无 session 级字段
Claude Code queen可用（运行器 + dashboard）qmail 运行器已实现：cwd/权限/会话/超时/回复闭环/MCP 注入；真实 claude -p 已验证；/api/claude-code-queens 已接真实配置与 transcript
内置 git 工具没有与 Python 版相同，只能 terminal 跑 git

自己构建 / 运行

终端
cd go_hive/go-hive
CGO_ENABLED=0 GOPROXY=off GOSUMDB=off GOFLAGS=-mod=mod go build ./cmd/hive
./hive serve --port 8788

Go 模块不依赖 cgo；SQLite 用 modernc.org/sqlite。完整门禁是 make ci（fmt / vet / test / cross / parity）。

结论

现在要把 Hive 用于真实工作，选 Python 版。go_hive 适合作为移植/性能/单二进制分发的评估对象；在触发器、Colony 运行时和工作目录这些关键能力接线之前，不能把它当等价替代。

如果你只记三件事

01

Queen 是入口，不是搜索框

给她结果、范围、验收标准，她会先做一条再放大；不要一上来就“帮我研究一下”。

02

进度在 Tracker，不在聊天里

看 Data、让她用 SQL 查；不要靠滚动聊天记录判断做到哪了。

03

定时不是系统 cron

服务要常驻、会话要加载、错过不补；把它当“应用内闹钟”，不是“保证送达的调度器”。
