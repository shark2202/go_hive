GO_HIVE · HTTP_TOOLS · 需求 → 设计

原生 HTTP curl 家族

为 go_hive 增加一组模型可调用的 HTTP 工具（http_request / http_download / http_upload），用 Go 标准库 net/http 直接发请求，不依赖 curl、不经过 shell。本页先冻结工具契约、出站策略（SSRF/重定向/代理）、按 Hive 会话隔离的 Cookie、结果信封与验收链。使用与配置见 http-tools-usage.html。

状态：implemented决策：用 net/http 原生实现三支扁平工具（http_request、http_download、http_upload），共享 internal/nativehttp 与 internal/netguard；不依赖 curl、不经过 shell、不新增第三方依赖。Cookie 状态按 Hive chat session 硬隔离：每个会话 catalogue 一个内存 host-only jar，不跨会话共享，v1 不落盘。所有用户路径输入必须是绝对路径且在会话根内。目标：CGO_ENABLED=0 · 六平台

00问题与价值

问题
go_hive 没有通用 HTTP 请求工具。agent 只能用 terminal_exec 调 curl，而最小 Windows/容器镜像往往没有 curl；即使有，也会把密钥写进 argv 与 shell 历史，且没有 SSRF 守卫、响应上限和结构化结果（状态码/响应头/耗时）。
为什么不是当前 parity 项
上游 Hive 没有 http_request 工具，因此不属于 parity 面。冻结的 39 个默认会话工具面与 14 个 builtin 定义保持不变；本工具家族只进入 lazy/searchable 层，作为 go-only 增量。

用户价值

  • 不装 curl、不开 shell 也能调 JSON API、Webhook 和需要认证的端点。
  • 拿到结构化结果（状态码、响应头、耗时、TLS、重定向链），而不是原始 stdout。
  • 内存与上下文有界：小响应内联，大响应落盘，二进制/未知编码不被静默丢弃。
  • 请求、下载、上传共享同一套出站策略（SSRF、重定向、代理、TLS）。
  • 同一 Hive 会话内保持登录态，同时与其他会话硬隔离。
  • 六平台 CGO_ENABLED=0 纯 Go 构建。

非目标

  • v1 不做 HTTP/3、WebSocket 或 SSE 流式；http_download 落盘，不向对话流式输出。
  • 不支持 ftp/gopher/file/data 协议、unix socket、--resolve、--connect-to、--interface；这些会绕过出站策略。
  • 不做浏览器渲染或 HTML 抽取；那是 web_scrape 的职责。
  • v1 不做跨会话 cookie 共享，也不落盘：恢复会话必须重新认证。
  • 没有全局 cookie jar，colony worker 也不继承 queen 会话的 cookie。
  • 不承诺 Python parity：本工具家族与 ast_grep、lsp 一样是 go-only 能力。
  • 默认不重试非幂等方法，除非显式 retry_non_idempotent。

03设计链

D1

工具家族与命名

http_request（任意方法，响应有界内联）、http_download（流式落盘，支持续传与校验）、http_upload（multipart 或原始文件体）。http_* 前缀保留。没有 action 开关：每支工具一个精简 schema，search_tools 可以只加载任务需要的那一支。

D2

包边界

internal/nativehttp 是只依赖标准库的核心：请求构建、策略、传输、重定向/重试、有界落盘与结果渲染。internal/netguard 拥有 SSRF 策略与拨号期 IP 固定，从 scrape.go 与 pdf/ssrf.go 抽取，旧封装保留、现有测试继续钉住行为。适配器 internal/tools/builtin/http_tools.go 负责 schema 与强制转换；internal/cli/session_tools_http.go 负责门控与分发。核心不 import server/cli/builtin，因此无需会话即可测试。WithRoot 会为 colony worker 重新挂根（路径包含与 cookie jar 跟随worker 存储目录），与 toolbox/taskTools 一致；catalogue 的 Close 负责关闭空闲连接。

D3

注册与工具面

通过会话 catalogue 以独立适配器注册（ast_grep/lsp 先例），不进入 builtin.Defs()（保持 14），也不进入冻结的 39 个参考面。默认启用；http_tools.json 可关闭。工具进入 lazy/searchable 层，HIVE_TOOL_SURFACE=grouped 时同样可见。类别：新增 http_core；**不加入** web_core/research 成员，保持参考 manifest 的 chart_render + web_scrape 两名清单。CategoryAdditions[web_core] 在发布版本（拟 1.0.27）愈合已保存的 tools.json sidecar。三支工具都标记 ConcurrencySafe=false：方法与请求体逐调用变化，且 cookie jar 是会话内共享状态。

D4

出站策略（SSRF）

仅允许 http(s)；裸主机自动补 https。每次请求与每一跳重定向都解析主机，拒绝回环、私网、ULA、链路本地、CGNAT、组播、未指定、文档/基准网段、IPv4 映射 IPv6、NAT64 本地段，以及 metadata 主机名（169.254.169.254、fd00:ec2::254、metadata.google.internal、*.local、*.internal、kubernetes.default.svc）。DialContext 校验后直接拨已验证 IP，DNS rebinding 无法在校验与连接之间换成私网地址。代理模式下只能做预检，作为残余风险登记。优先级：denied_hosts 高于 allowed_hosts，allowed_hosts 高于私网 IP 拒绝表；allow_private_hosts 才显式关闭 IP 拒绝表（会记日志）。https→http 重定向默认拒绝，除非 allow_https_to_http。

D5

重定向与认证

最多跟随 max_redirects（默认 10，上限 20），记录每一跳。301/302/303 把 POST 改写为 GET 并丢弃请求体；307/308 保留方法与请求体。跨主机跳转剥离 Authorization、Cookie、Proxy-Authorization 与显式 auth；代理凭据绝不转发给源站。用已访问 URL 集合检测环。每一跳前重新执行出站策略。

D6

请求体

body（原始）、json（任意 JSON 值）、form（urlencoded）、multipart（内联部件）四选一；冲突返回 invalid_input。Content-Type 默认：application/json、application/x-www-form-urlencoded 或生成的 multipart boundary。显式头优先于推导值。内联模式在内存构建；文件模式通过 io.Pipe 流式发送。不开 shell、不进 argv，密钥不会出现在进程列表里。

D7

响应处理

有界读取：response.max_inline_bytes（默认 64 KiB）内联；更大的响应落盘到 response.path （必须是绝对路径且在会话根内）或确定性的会话 tool-output 文件，结果带 saved_to + sha256 + 预览。二进制用 Content-Type + NUL 扫描识别，小体积才 base64，否则落盘。gzip 解码；未知 Content-Encoding 如实报告，不静默篡改。文本只按 UTF-8 解码，非 UTF-8 以 base64/文件返回并记录 charset。响应头有上限（100 头 / 64 KiB），敏感值脱敏。

D8

下载

流式写入 <path>.part，fsync 后原子 rename；overwrite=false 默认。resume=true 发送 Range: bytes=<size>- 并带 If-Range（ETag/Last-Modified），校验 206 + Content-Range，不匹配则重下。max_bytes 限制传输；始终计算 sha256；expected_sha256 可选。path 必须是绝对路径且在会话根内（跟随 symlink，逃逸拒绝）。失败时保留 .part，重试可续传。

D9

上传

multipart 部件从会话根内的绝对路径流式读取，文件名净化；body_file 以绝对路径流式发送原始 body（curl -T，默认 PUT）。fields/files 与 body_file 互斥。max_bytes 限制请求体；响应按 D7 有界。不做临时拷贝，1 GiB 上传不会占用 1 GiB 内存或磁盘。

D10

超时与重试

分阶段截止时间：连接（默认 10s）、TLS（10s）、响应头（15s）、总预算（请求默认 30s，下载/上传默认 300s；请求上限 300s，下载/上传上限 1800s）、空闲连接 90s。context 取消会传到传输层。默认只重试幂等方法（GET/HEAD/OPTIONS）的 408/425/429/500/502/503/504，遵守 Retry-After ≤ 30s，指数退避 + 抖动，并受总预算约束；retry_non_idempotent 需显式开启。每次尝试都记日志。

D11

结果与错误

三支工具共用同一个 JSON 信封，键名稳定、snake_case。非 2xx 默认是正常结果（带 status/body），除非 fail_on_http_error=true，语义等同 curl 不带 -f。失败时携带 error + error_kind（闭集），有响应时附 status/body_preview。二进制或未知编码绝不静默丢弃。

D12

配置

配置只从会话沙箱之外读取：<HIVE_HOME>/http_tools.json（运维/用户级）。**不自动发现** <sessionDir>/.hive/http_tools.json：会话目录是文件工具的沙箱根，agent 可写，自动发现等于允许 agent 放宽自己的出站策略（提权）。配置只允许收紧（更小上限、更严 allow/deny、enabled=false），不允许放宽。文件缺失即默认启用；格式错误或不可读即关闭（fail closed）。HIVE_HTTP_TOOLS=0 是进程级硬开关。字段：enabled、allow_private_hosts、allowed_hosts、denied_hosts、max_inline_bytes、max_response_bytes、max_download_bytes、max_upload_bytes、default_timeout_seconds、max_timeout_seconds、connect_timeout_seconds、follow_redirects、max_redirects、allow_https_to_http、user_agent、proxy、redact_query_keys、cookies {enabled, host_only, allowed_domains, max_cookies, max_value_bytes}。v1 故意没有 store_dir 或跨会话 profile 配置。

D13

可观测性与脱敏

每次尝试一条结构化日志：tool、method、host、status、bytes、duration_ms、redirects、retries、error_kind。绝不记录头、body、cookie 或 userinfo；查询串中命中 redact_query_keys 的值替换为 [redacted]；结果中的 Authorization/Cookie/Set-Cookie 默认脱敏，除非 include_cookies。Cookie jar 在内存中、归会话 catalogue 所有、加锁保护，v1 不落盘、不是全局。

D14

测试策略

httptest.Server 覆盖方法/请求体/重定向/重试/超时/压缩/二进制；假解析器覆盖 SSRF 与 rebinding；拨号器测试证明拨的是已验证 IP；表驱动适配器强制转换测试；catalogue 测试证明名称注册、lazy 层存在、配置门控，以及 builtin 14 / 冻结 39 面不变；CGO_ENABLED=0 交叉构建矩阵。

D15

Cookie 隔离（按 Hive chat session）

jar 是 newSessionToolCatalogue(sessionDir, ...) 创建的每会话适配器上的字段，其中 sessionDir = chatSessionDir(home, queenScope, sessionID) 按 Hive 会话唯一。没有 package-level jar、没有按模型提供的 name 共享的 sync.Map、没有 http.DefaultClient/Jar、v1 也没有磁盘 jar：恢复的会话从空开始。WithRoot 为 colony worker 克隆适配器时新建空 jar（不继承 queen 或其他 worker）。默认 host-only：带 Domain 的 Set-Cookie 一律拒绝，除非 http_tools.json 的 cookies.allowed_domains 显式列出；同时校验 __Host-/__Secure- 前缀；SameSite 只记录不强制（非浏览器客户端）。jar 由 cookiejar 内部锁与 wrapper 自身锁保护（Clear 换新 jar），并发调用跑 -race。catalogue 拥有每会话的 http.Client/Transport，Close 调 CloseIdleConnections，因此连接与 cookie 状态都不跨会话存活。

D16

路径语义（绝对路径）

go_hive 没有项目 cwd，只有会话沙箱根 c.root，因此用户路径输入一律必须绝对：response.path、http_download.path、http_upload.body_file、files[].path、tls.ca_file、tls.client_cert_file、tls.client_key_file。相对路径返回 path_not_absolute；绝对路径仍必须在 c.root 内，越界/../symlink 逃逸返回 path_escape。写文件父目录自动创建（0700），临时文件 + fsync + 原子 rename；读文件通过 os.Root 打开，防止解析后被 symlink 换向。自动落盘（未给 path）仍由内部生成 c.root/data/tool-output/ 下的相对路径，不经过用户输入。saved_to/path 在结果里永远是绝对路径。

包边界：internal/nativehttp（核心，stdlib-only）· internal/netguard（SSRF/拨号策略）· internal/tools/builtin/http_tools.go（schema/适配）· internal/cli/session_tools_http.go（门控/路由）。internal/nativehttp 拥有请求构建、出站策略、传输、重定向/重试、有界落盘与结果渲染，只依赖标准库，不得 import internal/server、internal/cli 或 internal/tools/builtin。internal/netguard 拥有共享的 SSRF 策略与拨号期 IP 固定；scrape.go 与 pdf/ssrf.go 保留薄封装，其现有测试继续钉住旧行为。适配器负责 schema 与输入强制转换，catalogue 负责门控与路由。 维护：核心包必须能脱离会话与工具注册表独立测试：httptest.Server 夹具 + 假解析器 + 假拨号器；每条策略分支都有表驱动测试；单测不访问真实网络。

处理流水线

  1. 归一化并校验 url/method/请求体来源/响应选项
  2. 应用 http_tools.json 策略（启用开关、主机白/黑名单、私网门控、容量上限）
  3. 构建 client：代理、TLS、超时、HTTP 版本、会话 cookie jar
  4. 解析并校验目标主机；在 DialContext 中固定已验证 IP
  5. 构建唯一一个请求体（raw / json / form / multipart / 文件流）
  6. 执行并处理重定向：每跳重新校验、跨主机剥离认证头、记录重定向链
  7. 在总预算内对有资格的尝试做退避重试并遵守 Retry-After
  8. 在内联预算内读取响应；溢出落盘并计算 sha256
  9. 解码 gzip/文本/二进制，脱敏敏感响应头与查询值
  10. 渲染 JSON 信封（status、headers、body/saved_to、耗时、TLS、重定向、error_kind）
  11. 关闭空闲连接并输出一条结构化日志

06安全与配置

威胁模型

模型控制 URL、头与 body，因此本工具是出站原语。默认拒绝私网地址可防止误触内部服务；脱敏防止秘密回显；容量上限防止内存/上下文耗尽。terminal_exec 对恶意 agent 仍是绕过通道，所以这是护栏而不是沙箱边界；高安全部署应同时限制 terminal 工具。

控制项

  • 协议白名单：http/https
  • DNS 解析 + 拨号期 IP 固定（防 rebinding）
  • 每一跳重定向重新校验
  • 跨主机剥离 Authorization/Cookie
  • 默认拒绝 https→http 降级
  • 私网/回环/链路本地/CGNAT/ULA/metadata 拒绝表
  • 可选 allowed_hosts / denied_hosts
  • 响应/请求字节上限与响应头上限
  • 分阶段超时与 context 取消
  • 结果与日志中的秘密脱敏
  • 每 Hive 会话一份内存 cookie jar（host-only 默认；无跨会话、无磁盘 jar）

残余风险

  • 代理模式下目标由代理解析：客户端只能预检，代理可能触达本应被客户端拦截的内部名称
  • 恶意 agent 仍可用 terminal_exec 跑 curl；策略落地依赖同时限制 terminal 工具
  • 运维显式设置 allow_private_hosts 或 insecure=true 是有记录的安全降级
  • 内存 jar 在进程重启或会话恢复后丢失；v1 用重新登录换取“绝不跨会话持久化”

http_tools.json

  • <HIVE_HOME>/http_tools.json（运维/用户级；在会话沙箱之外）

只读 <HIVE_HOME>/http_tools.json；缺失即默认值，低信任层只允许收紧，不允许放宽。格式错误或不可读即关闭（fail closed）。 HIVE_HTTP_TOOLS=0 对进程硬关闭；=1 仅在配置未关闭时生效。

10风险与来源

风险影响缓解
SSRF 被 DNS rebinding、重定向或代理绕过agent 触达内部服务解析-校验-拨号 IP 固定、每跳再校验、拒绝 https 降级；每种向量都有测试；代理残余风险登记。
URL、头或结果泄漏秘密凭据进入日志或模型上下文按键名与头名脱敏、不记录头/body、不回显 userinfo、cookie 值默认不可见。
大响应或二进制撑爆上下文/内存回合失败 / OOM64 KiB 内联预算、硬抓取上限、落盘 + 预览、二进制识别、响应头上限。
重试放大非幂等请求重复副作用默认只重试幂等方法、显式 retry_non_idempotent、总预算与状态白名单。
冻结面漂移（builtin 14 / flat 39 / 契约清单）parity 门禁与 golden 失败独立适配器、只进 lazy 层、catalogue 不变量测试、同一次变更里重新生成清单与 diff 文档。
跨平台 TLS 根与路径语义Windows/容器上校验或下载失败默认系统根、ca_file 覆盖、路径解析到会话根、Windows 路径测试。
Cookie 串会话不同会话读到彼此的登录态jar 挂在每会话 catalogue、无全局/静态 jar、WithRoot 新建空 jar、无磁盘持久化、A15 隔离测试。
早期输出格式漂移模型侧行为不稳定本设计冻结信封；适配器 golden；只做加法演进。
