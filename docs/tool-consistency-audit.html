01口径与方法

  • Python 侧：tools/src/aden_tools 的 register_all_tools 真实注册结果（FastMCP get_tools()）——全量 857（含 unverified），默认 270；harness 组（files/terminal/chart/memory/hive_tools）从 core/framework/tools/harness_tools.py 枚举。
  • Go 侧：临时探针构建真实 newSessionToolCatalogue，dump Defs() —— 137 个默认会话工具；另 dump builtin.Defs() 与集成注册表。
  • 模型可见口径：Python 在 tool_registry.py:1417 把 CONTEXT_PARAMS（session_cwd、agent_id、profile、colony_id、principal、data_dir、profile_display_name）从 properties/required 中剥离后再给模型；本次比对按同一口径处理。
  • 类型归一（JSON Schema / protobuf）：integer ↔ int32/int64/uint32/uint64；number ↔ float/double；boolean ↔ bool；string(format=byte/binary) ↔ bytes；array ↔ repeated；object/map ↔ message/map；enum 比值集合。可选性由 required 表达；anyOf[T,null] 记 nullable（与「非必填但非 null」不是同一语义，单列）。
  • Skill 逐字：对 core/framework/skills/{_default_skills,_preset_skills} 与 go-hive/internal/skills/ 逐文件 sha256 比对，不规范化、不改行尾。
基准数字：Python AST 源计数 865 个 @mcp.tool / 103 模块；实际注册 857（8 个未进注册表：重复名与未接线模块，例如 openmeteo_tool）；默认开启 270。Go 默认会话 137（含 87 个分组集成工具 + 内置/任务/技能等）。

关键差异（按严重度）

工具差异影响
terminal_execGo 仅 command + timeout_seconds；Python 还有 cwd、env、shell、stdin、limits、max_output_kb、auto_background_after_sec（8 项）P0 同名工具输入契约严重不一致；模型按 Python 习惯传参会被 Go 忽略/拒绝

集成层（Go 分组 schema）

  • Go 每个模块工具只声明 action 必填；其余参数的 required 仅存在于 description 文本（(required: …)）。
  • action 级 required 与 Python 一致 665；Go 无注解且 Python 也无需填 166；不一致 3：cloudflare_create_firewall_rule（Python 用 action，Go 用 rule_action）、freshdesk_get_agent、outlook_send_mail。
  • 无注解但 Python 必填 3：maps_geocode、maps_place_search、salesforce_soql_query。
  • 联合 schema 的类型放宽：20 个模块存在 ARRAY<ANY> 对 ARRAY<STRING>/<OBJECT>、STRING 对 enum 的差异（apollo、arxiv、attio、calcom、calendar、csv、email、exa、hubspot、jira…）。按 protobuf/JSON Schema 语义：这是接受更宽，不是等价。

07缺陷清单（按修复顺序）

级别项事实 / 建议
P0terminal_exec 输入 schemaGo 缺 8 个参数；先补齐 schema，再核对执行路径是否真的支持这些参数（描述里写死 /bin/bash -lc 也是平台缺陷）。
P0context 参数泄漏Go 的 session_cwd 出现在 4 个终端工具 schema；与 Python CONTEXT_PARAMS 剥离规则不一致，需在 Go 侧同样剥离（或确认注入路径）。
P0名称形状87 分组 vs 857 扁平。若目标是逐工具同名，只有两条路：Go 改为扁平注册（保留分组为别名），或 Python 改为分组。前者对现有 agent prompt 兼容性更好。
P1描述逐字同名工具 0/36；集成 action 747/837。需要决定「逐字复用 Python docstring」还是「允许改写但建立语义映射」；当前文档没有声明例外。
P1required 缺失 / 注解不一致4 个工具 required 为空；3 个 action 注解不一致；3 个 action 无注解但必填。schema 层应在 Go 侧补 required。
P1类型放宽20 个模块 ARRAY<ANY> / 裸 STRING；按 JSON Schema 语义不等价。需要按 action 拆 schema，或在 Go 侧做 per-action 校验。
P2extra / 未注册Go 多 2 个 openmeteo action；Python 侧模块未注册。属于「Go 超前」而非缺失，但同样破坏逐字对齐。
P2输出契约双方 0 个 outputSchema；补声明或 golden fixture。
