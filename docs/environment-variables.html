01口径与方法

  • 扫描两侧源码中的 "HIVE_..." 字符串字面量；排除 tests/、testdata/、*_test.go、test_*.py。
  • 这样能覆盖"包装函数读取"（例如 Go 的 envFeatureFlag("HIVE_EMAIL_SENDERS")），比只 grep os.Getenv 更准；纯 os.Getenv 扫描会把 Go 的凭据 env 全部漏掉。
  • "引用"不等于"生效"：大量变量在两侧都是代码内 fallback（无 JSON schema、无默认值字段），本页只登记名字、用途与读取点；默认值需看调用点。
  • 凭据类 env 用两侧 credentials spec 对照：Python CREDENTIAL_SPECS 114 条；Go /api/credentials/specs 123 条（实测）。

05凭据类 env（114 ⇄ 123）

Python 每个集成模块直接读自己的 env（如 AIRTABLE_PAT），同时有 114 条 credentials spec；Go 用 catalog 的 Requires 元数据 + integrationkit.Getenv（或模块 token helper）解析，/api/credentials/specs 实测 123 条。两侧都能用 env 提供凭据，但命名与条目集合不完全相同。

08影响与缺口

级别项影响
P1Python 独有 22 个开关资源守卫（HIVE_RESOURCE_*）、GCU memtrace（5）、日志/调试（4）、迭代上限、历史读取线程数等在 Go 设置无效；同一份 env 文件不能等价迁移。
P1凭据 env 命名cloudflare vs cloudflare_api_token；按 Python env 名配置的自动化在 Go 上可能不命中（Go 还会检查 credential store）。
P2默认值口径两侧都常用代码 fallback（如 HIVE_HISTORY_READ_WORKERS=8、HIVE_GCU_SCREENSHOT_CONCURRENCY=2、HIVE_PLAYBOOK_FAST_GRACE=1.5、HIVE_TRACKER_WORKER_TOOL_CALLS=20）；没有统一 schema，无法机器校验默认值一致性。
P1非 HIVE_ 控制变量Python 的 GCU_*/端口类/日志格式在 Go 不存在；Go 的 CHROME_PATH、ANTHROPIC_BASE_URL、PG* 在 Python 不存在——env 文件跨端迁移仍需逐项核对。
P2测试变量混入两侧都存在测试专用 env；统计时必须过滤，否则会把 harness 变量误判为生产面。
