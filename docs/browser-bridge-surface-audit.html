05结论：哪些维度可以宣布对齐，哪些不能

总口径：不能写「Browser Bridge 已整体对齐」。22/22 active 工具名与 46/46 control RPC 能对上，但返回契约（D08）未对齐，且 CLI、面板、/status、帧上限、并发隔离存在可观察差异。任何「整体已对齐」的表述都会掩盖这些差异。
维度结论可以怎么写 / 不能怎么写
D01可宣布对齐可以写：「模型可见 browser 工具面在两边都只有 browser_setup，name/schema/description 一致」。限定：只到工具定义层；其 payload 的截图承诺在 Go 不成立（R12）。
D02部分可以写：「22/22 active 工具名都有 Go handler，13 个 interact action 全实现」。不能写「工具定义已完全对齐」——参数默认值、activeTabId、group 摘要、描述层都不同。
D03部分可以写：「扩展无需改动即可连两边；hello/帧/应用层心跳/4002 顶替一致」。不能写「协议完全等价」——WS ping、帧上限 50MiB vs 16MiB 不同。
D04部分可以写：「14830 是超集：Python 的 10 条全有，Go 加 4 条」。不能写「HTTP API 已对齐」——/status 字段集不同、无 9230、/command /health 是 Go-only。
D05可宣布对齐可以写：「14831 的 46 个 RPC 方法、帧形状、client_hello、notify、reaper 与上游一致（fake-extension + 单测证据）」。不能写「已用旧版 Python CLI 交叉实测」——没做。
D06部分可以写：「命令树覆盖 22 个 active 工具，另加 5 个 legacy 动词」。不能写「CLI 契约一致」——3 个退出码分歧、flag 位置更严、输出形状不同。
D07部分可以写：「adopt/release notify 文本、14831 推送、serve 注入与上游一致」。不能写「面板已对齐」——3 条路由字段缺失/503、status 恒 offline。
D08不可宣布只能写：「截图/快照返回契约未对齐：无缩放/注解/artifact/_image，无 refs/href/DOM fallback，坐标动作无图」。这是当前最大缺口。
D09部分可以写：「默认 30s、17 个错误码、pending dialog→7 一致」。不能写「错误语义完全一致」——结构化 bad_request 在 Go 映射 6，上游落到 1。
D10部分可以写：「空闲 10s/30s、exit 0 语义一致；父死 0.8s 比上游 5–10s 更快」。不能写「父死时序已对齐」——是更快，不是同值。
D11部分可以写：「全部 loopback、无鉴权/TLS、同 label 4002、多 profile 路由一致」。不能写「隔离等价」——Python 有 per-tab CDP 锁，Go 没有；has_public_listeners 未移植。
D12部分可以写：「Go 有可复现的真 Chrome 19 步证据；上游仓库内没有同等级脚本」。不能写「两边都经过真机验证」——证据不对称，且 Go 只覆盖单 profile/单主机。
D13部分可以写：「文档总体准确，但有 5 处口径漂移（/health /command 归属、面板形状、type_focused active、父死 ≤2s、残差清单过窄）」。不能写「文档已同步」。

  • 可以宣布对齐：D01 模型可见工具面（仅定义层）、D05 control RPC 14831（仅协议与单测证据）、D07 面板/status（R03/R04 修复后，真桥 + 假扩展实测）。
