GO_HIVE · CHANNELS · WEBSOCKET · REQUIREMENTS → DESIGN

channel WebSocket 需求—设计链

为 internal/channels 增加一个可选的 WebSocket 入站传输：语言无关的 JSON-RPC、实时双向输出，复用现有 hive serve 和会话后端。默认仍是 stdio；ws route 默认按 channel 名区分，令牌只在 Authorization header。

状态：design需求：14设计项：12验收：17传输：WebSocket (RFC 6455), text frames

00可行性判断

结论：可行，但不是按当前配置示例原样可行。
原因：The current host is process-oriented: every enabled channels entry must have command/args, Host.Start spawns one stdio child, and Host.handlePluginRequest is only reachable from that child. The example has type=ws, no command, and no route, so today it would be reported failed with 'no command configured'. There is also no WebSocket route in hive serve and no WebSocket server dependency in go.mod. The protocol layer, however, is already a transport-neutral JSON-RPC contract, so the work is an inbound transport adapter plus route/auth/lifecycle work, not a new session model.
当前卡点
  • internal/channels/config.go PluginConfig has Name, Enabled, Command, Args, Cwd, Env and Section; it does not read type or path.
  • internal/channels/host.go startOne requires Argv(); an enabled entry with no command is failed, as the existing nocommand test proves.
  • There is no /channel/websocket route; internal/server/app.go registers API routes and a GET / SPA fallback, and go.mod has no WebSocket server module.
  • internal/channels/subscription.go hard-codes *pluginProcess in delivery; the output path needs a transport-neutral sink.
  • internal/server/app.go desktopAuth checks every path except /api/queen-mail/ when HIVE_DESKTOP_TOKEN is set; channel auth must not piggyback on it.
  • hello carries the whole config section and an absolute state_dir, while Output.Files carries absolute host paths; those are not usable by a remote language client.
可复用部分
  • hive-channel/1 JSON-RPC envelopes and method names in internal/channels/protocol.go.
  • Host.handlePluginRequest and the SessionBackend interface, which already wrap open_session, send, subscribe, unsubscribe, set_title and judge.
  • Output kinds, subscription queue, drop-oldest policy and seq gaps in internal/channels/subscription.go.
  • GET /api/channels state map in internal/server/routes_credentials_channels.go.
目标之外：Make a channel implementable in any language that has a WebSocket and JSON client, without putting a process on the Hive host, while keeping the existing stdio channel path and its upstream-compatible session semantics intact. The channel becomes a remote peer of the same ChannelHost contract instead of a Go-specific child process.

A channel is currently a local implementation detail: the server owns the child process, the child talks JSON-RPC on stdin/stdout, and the plugin must run on the same host to read files and state. That is not language-neutral for remote implementations and it does not give a remote client a real-time duplex link. A WebSocket endpoint is the natural transport, but the existing config example does not describe the identity, path, authentication, lifecycle or file semantics needed to make it safe.

用户价值
  • Any language with a WebSocket client can implement a channel; no Go process, no stdin framing, no child lifecycle.
  • The server can push message, question, error, files and idle outputs in real time over the same socket.
  • The existing session methods and queen semantics stay identical, so a port is a transport port rather than a second channel model.
  • The stdio wxbot path remains the default and needs no migration.
  • The route is opt-in and can be mounted without a second port or a separate daemon.
为什么不是当前 parity
This is a Go-only extension; upstream Hive exposes channel plugins as in-process packages and has no WebSocket channel transport. It must stay at design status until path, auth, attachment and single-connection decisions are accepted.

非目标

  • Do not add a second HTTP listener, a sidecar daemon or an external WebSocket proxy requirement.
  • Do not expose MCP semantics or MCP tools through this endpoint; this is the channel host protocol.
  • Do not add Hive-to-Hive federation, remote channel discovery or a second identity store.
  • Do not add hot reload; configuration is read at serve startup like the current channels section.
  • Do not support multiple active plugin connections for one channel in v1; one bot identity, one connection.
  • Do not add replay, an inbox or a cursor in v1; a disconnected client must re-open and re-subscribe.
  • Do not add channel tools to the local model tool catalogue.
  • Do not change the stdio child protocol or the existing wxbot configuration contract.

前提

  • The Hive process is the server; a language client is the channel plugin and connects to /channel/websocket/<name>.
  • The endpoint is off unless an enabled ws entry exists; no command is spawned for a ws entry.
  • A channel token is supplied through an environment variable named by token_env and is never printed.
  • The ws client can send an Authorization header. Browser clients that cannot set one need a same-origin BFF or a cookie design; that is an open decision.
  • Remote deployment terminates TLS at a trusted reverse proxy and uses wss; plaintext remote WebSocket is unsupported.
  • The client accepts at-most-once output semantics with seq gaps and re-subscribes after reconnect; durable delivery is a later feature.
  • The channel client owns its local state; an absolute server state_dir is neither useful nor safe to send.

02方案决策

ID方案结论理由
O1type=ws route on the existing hive serve listener, reusing hive-channel/1chosenMatches the user request, gives language-neutral real-time transport, avoids a second port and keeps the session backend and protocol vocabulary. Requires a new inbound transport adapter and auth, not just a config field.
O2Separate WebSocket listener on a dedicated portrejectedThe request explicitly says to share hive serve; a second port adds deployment, discovery, proxy and state-sync surface for no protocol benefit.
O3Keep stdio and run a local WebSocket-to-stdio bridge processrejectedStill requires a process on the Hive host; the remote language client would depend on a Go bridge and the host would still own the child lifecycle.
O4Adopt an approved pure-Go WebSocket library instead of hand-rolling RFC 6455deferredThe library is safer and shorter, but it changes go.mod and needs explicit approval under the no-new-dependency rule. The transport contract is independent of this choice.
O5Expose MCP over WebSocket instead of the channel JSON-RPCrejectedMCP is an agent/tool protocol, not the ChannelHost object model. Reusing MCP would create a second session/tool layer and break the existing channel semantics.
O6One shared /channel/websocket/ path for every channelrejectedThe path alone cannot identify the configured channel or its token. A later subprotocol or first-frame selector is possible, but it makes pre-upgrade 404/401/403 impossible and increases ambiguity.
选择：Add type="ws" as an inbound transport for channels.<name> and mount it on the existing hive serve listener at a fixed route derived from the channel key: /channel/websocket/<name>. The path is not a config field and a path key is rejected; there is no custom or shared path. Reuse the existing hive-channel/1 JSON-RPC methods and SessionBackend semantics, authenticate each connection with a channel-specific bearer token, and allow exactly one active connection per channel. stdio entries remain the default and are unchanged.

03设计链

D1

Route placement

Mount one handler per enabled ws entry at /channel/websocket/<name> on the existing http.Server. Register the route before the GET / SPA fallback. The handler upgrades only after path, token and Origin checks; the route is not under /api and does not inherit the desktop token policy. No second listener is opened.

D2

Configuration and validation

Extend PluginConfig with Type (stdio default), TokenEnv, AllowedOrigins, MaxConnections, Takeover and timeout/limit fields. Parse type before the stdio command checks. For ws, do not require command, do not spawn a process, validate the name and derive the route as /channel/websocket/<name>; a path key is rejected. Require token_env and a unique route. Invalid entries are startup failures, not silent disables. Read at serve startup; changing an entry requires restart.

D3

Authentication and connection identity

The client sends an Authorization header with the bearer scheme; the token is read from token_env. The server compares in constant time, binds the token to the configured channel name and rejects a token presented on another channel. Missing/wrong token is 401/403 before 101. If Origin is present it must match allowed_origins; native clients without Origin are allowed only with a valid token. HIVE_DESKTOP_TOKEN is never accepted as a channel token and the token never appears in the URL, query string or hello config.

D4

Wire protocol

Use WebSocket text frames carrying one UTF-8 JSON-RPC 2.0 object each. Negotiate subprotocol hive-channel/1 during the upgrade. Reuse hello, start, output, open_session, send, subscribe, unsubscribe, set_title and judge exactly as internal/channels/protocol.go defines them. Binary frames are rejected. No MCP methods and no per-channel custom model are introduced.

D5

Backend and request reuse

The ws transport calls the same request dispatcher as the stdio host instead of duplicating session logic. Extract the unexported handler behind a small handler/sink seam so both transports share open_session, send, subscribe, unsubscribe, set_title and judge. The channel backend remains SessionBackend; the ws layer must not import internal/server, internal/cli or internal/tools/builtin.

D6

Lifecycle and close semantics

States are CONNECTED, HELLO_SENT, START_SENT, READY and CLOSED. After 101 the server sends hello (id srv-1); the client must answer within handshake_timeout_seconds; the server sends start (id srv-2); the client answers; only then are client requests accepted. A request before READY gets -32000 with kind not_ready. On stop, send a bounded stop request then close 1001. Disconnect closes every subscription and releases the channel slot.

D7

Output and backpressure

Reuse Output and outputParams. Each subscription has one ordered queue of queue_size and one writer; when the queue is full, drop the oldest output, increment drops and let seq gaps tell the client. A slow ws peer must never block the event bus. v1 is at-most-once: no replay buffer and no cursor. Reconnect means open_session/subscribe again.

D8

Remote attachments

For ws, do not expose Output.Files as absolute host paths. Add an optional file_refs array with an opaque id, name, size, mime and sha256; the client downloads through an authenticated GET /channel/artifacts/<id> route scoped to the session attachment root. Input send.images stays the existing base64 form. If attachment transfer is not accepted, v1 must return a typed unsupported_attachment error instead of a useless path.

D9

State and observability

Extend GET /api/channels entries for ws with transport=ws, connected, connections and last_error while keeping name and state. state is off when disabled, running when the route is mounted, failed on config/auth/listener errors. Logs contain channel name, connection generation, close code and counts, never Authorization, token, text or attachment bytes.

D10

Limits and liveness

Enforce max_frame_bytes before JSON decode; reject binary frames; no permessage-deflate; require masked client frames; send ping every ping_interval_seconds and require pong within pong_timeout_seconds; bound in-flight requests and handshake time. One active connection per channel by default. These are transport checks, not new channel semantics.

D11

Hello redaction and remote safety

Build the hello config from a safe projection: enabled, type, path and non-secret plugin options only. Omit state_dir for ws and omit token_env's value, Authorization, env values and absolute paths. Validate the channel name before joining it to the route. Remote use must be wss behind a trusted proxy; do not bind 0.0.0.0 as a shortcut and do not reuse the desktop token.

D12

Package and dependency boundary

Keep the transport-neutral protocol and host seam in internal/channels (ws_*.go in the same package is acceptable to reuse unexported helpers); mount it from a thin server adapter. Do not import internal/server, internal/cli or internal/tools/builtin from the channel transport. The default choice is a minimal standard-library RFC 6455 server; the approved-library option is recorded in O4 and needs explicit dependency approval before code.

包边界：协议与 host seam 留在 internal/channels；server 只做薄适配器；transport 不得 import internal/server、internal/cli 或 internal/tools/builtin。默认选择标准库最小 RFC 6455 实现；新增库需批准。

04WebSocket 协议

传输

WebSocket (RFC 6455), text frames

端点 /channel/websocket/<name>；子协议 hive-channel/1。

帧

Text / JSON-RPC 2.0

one UTF-8 JSON object per text message; binary messages are rejected; no NDJSON

认证

Authorization header (Bearer)

token 不在 URL；每个 channel 独立绑定。

连接顺序

  1. HTTP GET /channel/websocket/<name> with Upgrade, Origin (if any), Authorization and Sec-WebSocket-Protocol
  2. HTTP 101 Switching Protocols with the selected subprotocol
  3. server -> client hello request (srv-1)
  4. client -> server result with plugin_version
  5. server -> client start request (srv-2)
  6. client -> server start result; state READY
  7. client requests open_session/send/subscribe/unsubscribe/set_title/judge
  8. server -> client output notifications with subscription seq
  9. server stop request on shutdown; close 1001

服务端帧

  • hello: JSON-RPC request with id and params.protocol, params.name, params.config (redacted)
  • start: JSON-RPC request with id and empty params
  • output: JSON-RPC notification with subscription_id, session_id, kind, text/questions/files and seq
  • stop: JSON-RPC request on shutdown, bounded by StopTimeout

客户端方法

  • open_session {queen_id, session_id?, title?}
  • send {session_id, text, images?, display_text?, correlation_id?}
  • subscribe {session_id}
  • unsubscribe {subscription_id}
  • set_title {session_id, title}
  • judge {question, state, criteria?}

09风险、待拍板与来源

风险影响缓解
The derived /channel/websocket/<name> URL is not what an existing client expectsa remote client cannot connect with a custom pathdocument the one canonical route; do not add a path key; a future shared-path selector needs its own pre-upgrade identity design and tests.
A hand-written RFC 6455 server has parser/security bugsinvalid frames, DoS or protocol confusionkeep the frame subset minimal, test masking/fragmentation/close/ping, fuzz frames, and prefer an approved library if the dependency gate opens.
The ws route is outside /api and bypasses desktopAutha new unauthenticated route on a remotely bound servermandatory per-channel token, Origin check, TLS boundary and a startup refusal when token_env is absent.
Remote clients cannot read absolute Output.Files pathsimages/documents silently break or leak host pathsfile_refs + authenticated download, or a typed unsupported_attachment error; never send host paths.
At-most-once output with drop-oldest loses real repliesa slow or disconnected channel misses messagesdocument seq gaps; resubscribe after reconnect; durable inbox/replay is a later design.
hello carries the whole configuration sectiontokens, env values or absolute paths leak to a remote clientbuild a safe config projection and omit state_dir for ws; test captured hello.
Single active connection becomes a reconnect racetwo clients write to one channel or a reconnect is refusedgeneration ids, explicit takeover policy and a test for both refusal and replacement.

待拍板

  • Should the server be hand-written on net/http Hijacker (no dependency) or use an approved pure-Go WebSocket library? O4 is deferred until dependency approval.
  • How should a browser client authenticate, given that the WebSocket API cannot set an Authorization header? A same-origin BFF/cookie design is different from the native-client header path.
  • Is file transfer in v1 required? If yes, choose file_refs plus an authenticated GET /channel/artifacts/<id>; if no, v1 must return a typed unsupported_attachment error for Output.Files.
  • What is the second-connection policy: reject with 409, or replace the old connection with close 4004? The default proposal is reject; takeover needs an explicit config.
  • Should a mounted ws route with no connected client report state running (endpoint ready) or off? The proposed contract keeps state=running and adds connected=false.
  • Do you need replay/inbox/at-least-once delivery? The current design is at-most-once with seq gaps and no cursor, because the existing channel queue is drop-oldest.
