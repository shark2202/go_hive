Hive · Credentials CLI

hive-cred：按需取用凭据

hive-cred 是给脚本（以及经 terminal_exec 调它的 agent）用的 CLI：在用到的那一刻现取一张新鲜凭据，值只在 stdout，不进对话、不落长期文件；OAuth 过期会先刷新。本页记录它的设计语义、命令、Python 源码位置、Go 移植差异，以及一个必须知道的安全边界。

取用时机
调用时
不是脚本开头取一次；官方建议每次请求前调用

落盘

“瞬时”要精确：它不生成一次性 token；它返回当前有效的凭据值（OAuth access token 过期会先刷新）。值的生命周期由 provider 决定（如 Google access token 约 1 小时），所以必须“用前现取”，而不是“取一次用一天”。

01为什么存在

旧路径只有一个：credentials reveal —— 把明文 OAuth token 放进对话，agent 再粘进 /tmp/send_*.py。后果是：值进了日志/转录，token 一过期脚本就 401，一个长会话里反复 reveal。hive-cred 把方向反过来：

# 旧：值进对话（已移除）
TOK=<agent 从 reveal 结果里复制>

# 新：脚本在用到时自己取
TOK=$(hive-cred token google --account email3)
curl -H "Authorization: Bearer ***" https://gmail.googleapis.com/...

配套改动（v1.0.6 release notes）：credentials 工具只保留 collect/attach/detach；browse/inspect/reveal 动作改成“回复你要跑的命令”；queen 的 list_credentials 删除，由 hive-cred browse 取代。

02命令

命令作用输出
hive-cred token <id> [--account ALIAS] [--key NAME] [--json]打印新鲜值；OAuth token 过期会先刷新默认 stdout 只有值；--json 给 value/expires_at/expires_in_seconds
hive-cred browse [query] [--json]已连接账号 + 可连接 provider只有元数据（别名/身份），无值
hive-cred inspect <id> [--account ALIAS] [--json]某凭据的账号、键名、类型无值
# 典型用法（每次请求前取）
TOK=$(hive-cred token google --account email3)
curl -H "Authorization: Bearer $TOK" ...

# 看能连什么（安全，可给 agent 看）
hive-cred browse --json
hive-cred inspect google --account email3 --json

退出码：校验错误/找不到/需重连/不可用分别有稳定码（Python EXIT_UNAVAILABLE、EXIT_REAUTH；Go 走 tracker 的 validation/not_found/reauth_required/unavailable）。

03语义细节

  • 解析顺序（Python resolve.py::resolve_secret）：本地已收集账号（LocalCredentialRegistry）→ 加密 store；命中 store 时用 get_credential(..., raise_on_refresh_failure=True)，即 refresh-on-access。
  • 刷新失败：返回 reauth_required（“expired and could not be refreshed. The user must reconnect it; do not retry.”），不会给空值。
  • 超出/过期信息：--json 带 expires_at 与 expires_in_seconds，调用者可据此决定何时再取。
  • stdout 纯净：Python _render 只打印值；日志走 HIVE_CRED_LOG 文件（否则 NullHandler），避免污染 $(...)。
  • 多账号：同一 provider 多账号时必须 --account；browse 给出别名。
  • 谁能用：人类脚本；agent 经 terminal_exec（queen/worker 提示词明确要求这样做）。

05Go 移植与差异

层Pythongo_hive
入口hive-cred console scriptcmd/hive-cred/main.go（12 行）→ internal/cli/cred.go（// Parity: framework/credentials/cli.py）
命令token/browse/inspect同名三命令；--json/--account/--key 同名
解析resolve_secret + store 适配器credentials.ResolveSecret；SecretNotFound/CredentialExpiredError 同语义，错误码走 tracker
密钥HIVE_CREDENTIAL_KEY（env → secrets 文件 → shell）internal/credentials/keys.go:28-45 同顺序，并持久化到 $HIVE_HOME/secrets/credential_key
额外机制无（工具在调用时用 adapter 解析）envsync（Go-only，Parity-exempt）：serve 启动时（cli/loader.go:280）和每次凭据写入后，把 store 值按 spec 的 env_var 用 os.Setenv 镜像进进程环境，供读 os.Getenv 的移植工具使用
envsync 规则—已有非空 env 不覆盖；只刷新自己上次写入且未被改动的值；空值视为未设置；无密钥时整段跳过；日志只记数量/变量名，不记值
一句话：hive-cred 是“拉”（脚本按需取）；Go 的 envsync 是“推”（启动/写入时把 store 灌进进程 env）。两者互补，但 Python 只有“拉”，没有“推”。

06安全边界（必须知道）

  • 它保护什么：值不进入模型上下文/对话转录；不落长期文件；browse/inspect 永远只给元数据；刷新失败不会产出空值或旧值。
  • 它不保护什么：调用它的脚本/进程能看到值；如果脚本把值写进文件或日志，hive-cred 管不了。
  • Go 的额外暴露面：envsync 注入的是服务进程环境，而 terminal_exec 子进程继承整个环境（只剥 ZDOTDIR/ZSH_*，见 Go internal/tools/builtin/terminal_guard.go:126-148、Python tools/src/terminal_tools/common/limits.py:204-214）。因此在 Go 上，store 里已被注入的凭据对 agent 的 shell 子进程可见（跑 env 即可）。Python 不把 vendor 凭据放进 env，这个暴露面不存在。
  • 加固方向：terminal 子进程 env 过滤凭据变量（仅保留 hive-cred 解密所需的密钥），或让 Go 工具也改走按需解析，撤掉 envsync。
