03"一致吗"——分三层看

第一层 · 表面
一致
工具名与 API 面按平台统一：Windows 上 PTY 工具照样注册、返回同一条错误文案（Python 与 Go 逐字相同），这是刻意设计——模型看到的工具面不随平台变化。
第二层 · 行为
有意差异
shell 解析链、进程终止语义、路径/权限模型、可执行位校验、认证后端（Codex Keychain 仅 macOS）都按平台分支。这是上游的有意行为，不是缺陷。
第三层 · 验证
差最多
Python 在 Windows 有真实 CI（另有 Windows 专用测试）；Go 的 Windows/Linux 只有交叉编译。Go 的 Windows 属于"未达标"——terminal_exec 在原生 Windows 不可用。

04缺口清单（PLAT-01 … PLAT-10）

编号问题影响证据 / 修法
PLAT-01Go terminal_exec 硬编码 /bin/bash原生 Windows 核心工具不可用internal/tools/builtin/exec.go:54；修法：走 terminalResolveShellSpec(true,"")（job 已在用）
PLAT-02Go 无 Windows/Linux 运行时测试（无 CI，release 只 build）平台行为回归无人守主仓 ci.yml 无 Go job；release.yml 矩阵只编译
PLAT-03PTY 在 Windows 双端不支持能力差异，有意Python pty/tools.py:88；Go terminal_pty_windows.go；文案一致
PLAT-04Python 无 macOS CI jobmacOS 回归靠本机ci.yml matrix = ubuntu + windows
PLAT-05Codex Keychain OAuth 仅 macOSWindows/Linux 该功能不可用agent_loader.py 三处 platform.system() != "Darwin"
PLAT-06Claude Code Skills 路径要求 Unix shellWindows 需 WSLdocs/getting-started.md 明示
PLAT-07Go 发布无 Windows 安装脚本Windows 手动解压 ziprelease.yml 只产 install.sh；Python 有 quickstart.ps1
PLAT-08进程终止语义不同（孙进程）Windows 上后台进程可能残留exec_windows.go（Go）；Python 用 taskkill /T 覆盖 Claude Code 树
PLAT-09技能 scripts/ 可执行位校验在 Windows 跳过检查项差异（无 POSIX 位可查）skills/validator.py:128
PLAT-10Browser Bridge 未在 Windows/Linux 实测loopback + 扩展理论跨平台，未验证Go 侧主服务已接线并在 macOS + 真实 Chrome 实跑；Windows/Linux 仍未实机
PLAT-01 是唯一"明确不可用"级别的缺口；其余要么是有意差异（PLAT-03/08/09）、要么是验证/打包缺口。在 PLAT-01 修复并上 Windows 运行时 CI 之前，不能说 go_hive 支持 Windows。
