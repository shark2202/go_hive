配置根与 cwd 语义

go_hive 没有“项目 cwd”这个概念。代码里的 cwd 参数实际是会话沙箱根（session directory），不是 hive serve 的进程 cwd，也不是 queen/colony 根。本文冻结这条知识，并记录 2026-11-27 的行为修正：ast_grep.json 与 lsp.json 只从 $HIVE_HOME 读取，不再读取会话目录下的 .hive/*.json。

状态：已实施日期：2026-11-27范围：ast_grep · lsp · http_request 家族

00结论

没有项目 cwd。不要把 <cwd>/.hive/*.json 理解成“项目级配置”。在 go_hive 中，这个 cwd 就是当前 Hive 会话的沙箱根；会话目录对 agent 的文件工具可写，因此它不能作为安全门控。

目录概念有六个，含义各不相同：

名称路径用途
进程 cwdos.Getwd()（hive serve 启动目录）仅少量回退：零值 Toolbox、MCP CLI、attach_file 回退、旧凭据路径。不是配置根。
HIVE_HOMEhome.Root（如 ~/.hive）全局状态：configuration.json、凭证、mcp_registry、queens/、colonies/。配置只应从这里读。
queen home<HIVE_HOME>/queens/<queen>queen 级状态与 profile。
colony 根<HIVE_HOME>/colonies/<colony>colony 级状态、worker 目录、queen 会话树。
会话目录（c.root）<HIVE_HOME>/queens/<queen>/sessions/<id> 或 <HIVE_HOME>/colonies/<colony>/queens/<queen>/sessions/<id>文件工具沙箱根、注入的 session_cwd、ast_grep/LSP 的 workspace 根。agent 可写。
worker 目录<colony>/workers/<id>colony worker 的沙箱根；WithRoot 重新挂根。

02为什么原设计是缺陷

原设计（ast-grep-design.html / lsp-design.html）把 <cwd>/.hive/*.json 称为“project”配置，并允许它覆盖用户级配置。问题在于：

  • 会话目录可写。agent 的 write_file 能以会话目录为根创建 .hive/ast_grep.json 或 .hive/lsp.json；新建文件不触发“先读后写”守卫。
  • 恢复会话会重读配置。会话恢复会重建 catalogue，于是 agent 写的文件生效。
  • ast_grep：agent 可自行开启/关闭工具，与“operator opt-in”矛盾（危害较小，只读搜索）。
  • LSP：lsp.json 可写 command/args，等于模型可写文件 → 进程启动，与“Server command and args never come from model input”直接冲突（危害严重）。
  • HTTP 工具：若照搬该模式，agent 可写 enabled=false 或 allow_private_hosts=true，放宽 SSRF 策略（提权）。

03修正后的契约

能力配置来源（只读）workspace 来源
ast_grep<HIVE_HOME>/ast_grep.json会话目录（c.root）
lsp<HIVE_HOME>/lsp.json会话目录；定义可 pin 绝对 rootDir
http 工具家族<HIVE_HOME>/http_tools.json会话根；所有路径输入必须是绝对路径且在根内；自动落盘在根内；cookie jar 按会话隔离
规则：配置与 workspace 是两个维度。配置决定“能不能用、能用多大、能连哪里”；workspace 决定“相对路径落在哪”。前者只能从会话沙箱之外读取；后者必须是会话目录（或显式 pin 的 rootDir）。

明确不支持

  • <sessionDir>/.hive/ast_grep.json、<sessionDir>/.hive/lsp.json、<sessionDir>/.hive/lsp.local.json：一律不读。
  • 没有“项目 cwd 自动发现”，没有父目录向上查找。
  • 低信任层不允许放宽策略；v1 也没有项目级覆盖（需要时用显式绝对路径环境变量）。

04迁移

  • 把原会话目录下的 .hive/ast_grep.json 移到 <HIVE_HOME>/ast_grep.json。
  • 把原会话目录下的 .hive/lsp.json / .hive/lsp.local.json 合并到 <HIVE_HOME>/lsp.json；settings.enabled、servers、rootDir 语义不变。
  • 会话恢复后不再继承旧位置配置；这是有意的安全收紧。
  • 测试：go test ./internal/lsp ./internal/tools/builtin ./internal/cli 覆盖“会话目录配置被忽略”的回归用例。

05信任边界

terminal_exec 仍可写 HIVE_HOME（它不经过文件工具沙箱），所以本文描述的是防误用护栏，不是沙箱边界。高安全部署应同时限制 terminal 工具，或把 HIVE_HOME 设为 agent 不可写。真正的隔离来自：

  • 配置只从会话沙箱之外读取；
  • LSP 的 command/args 只来自 operator 级配置；
  • HTTP 的 SSRF/上限策略只由 operator 级配置放宽；
  • cookie jar 按 Hive 会话隔离（见 http_tools 设计）。
