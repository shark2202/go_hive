§3 设计回路（概念；Python 当前未自动执行）

trigger（timer / playbook）
   → queen marshal（goal 分解为任务 / 派 worker）
   → worker 执行（worker.json 可带 success_criteria）
   → OutcomeAggregator 聚合（OutcomeAggregator.__init__, OutcomeAggregator.record_decision, OutcomeAggregator.record_outcome, OutcomeAggregator.evaluate_goal_progress, OutcomeAggregator.get_stats）
   → agentloop goal_eval 按成功标准×权重判定（加权比例，LLM judge 可参与）
   → 设计意图：未达标 → 重试 / 升级；达标 → 推进 / 结束
（宿主 = colony runtime：core/framework/host/colony_runtime.py 持有 overall goal 与 get_goal_progress）

重要：Hive Python 当前把 Goal 作为声明式 prompt 上下文；Goal.is_success() 无生产调用，OutcomeAggregator 是 stub，get_goal_progress() 恒返回空/0，未达标重试与达标收工是设计意图，不是当前自动行为。实际流转见 §6.6。

orchestrator 侧方法：Goal.is_success · Goal.to_prompt_context（to_prompt_context 把目标与约束注入模型上下文）。

§6 何时创建 / 何时生效 / 怎么使用

一句话：Goal 是 colony 的内部执行模型，不是每次聊天创建的对象，也没有 /goal 或 goal tool。

6.1 三层对象，不要混

对象存储/来源谁创建用途
Colony Goal
schemas.Goal		colony 的 worker.json 里的 goal block；运行时对象不单独落盘colony 初始化 / fork 时写定义；session 加载时构造对象criteria 判定、prompt context、goal_progress / goal_evaluation
Task plan goalsession 的 tasks.json 的 meta.goal第一次 task_create(goal=...)；后续可继承/覆盖；pivot 必须提供task reminders、task list、pivot
Worker display goalworker 状态/结果字段queen 调 run_worker(goal=...)UI 标题/描述；不参与 Goal 评估

6.2 何时创建

  1. 新建空 colony：POST /api/sessions 发现 colony 目录没有 metadata.json，走 ensureMinimalColony()；它写出的 worker.json 带默认 goal：{"description":"Work on tasks for colony <id>"}。随后 newColonyHost() / LoadAgentSpec() 构造内存 schemas.Goal。
  2. 从源会话 fork / pivot 新 colony：接受 task_create(new_colony=true) 的 pivot 时，writeColonyFromSession() 用 pivot 的 goal（没有则用 initial_prompt，再没有则用默认句）写 worker.json 的 goal.description；新 colony 加载时构造 Goal。
  3. 已有 / 导入 / 手工配置的 colony：只在该 colony 第一次构建 session runtime 时读取 worker.json；如果 worker 配置里的 goal 已存在，不重写。
  4. 每次 session/runtime 启动：Goal 是内存对象，重新从 worker.json 构造；没有单独的 goal.json，也没有 Goal CRUD API。

上游 session_manager.py 还会为 session-level ColonyRuntime 创建 colony_goal_<session> 默认 Goal；Go 当前 colony host 直接采用 worker.json 的 Goal。这是实现口径差异，不要把两者当成同一份持久化数据。

6.3 什么情况下真正生效

Goal 对象总是会被构造，但 description-only 的 Goal 不会进入 prompt，也不会触发评估：Goal.ToPromptContext() 只有在存在 success_criteria / constraints / context 时才返回内容；EvaluateGoal 在没有 success_criteria 时直接返回 nil。

worker.json:
{
  "goal": {
    "description": "检查 20 个账号的收款状态",
    "success_criteria": ["列出全部 20 个账号", "每个账号给出状态"],
    "constraints": ["不要修改账号配置"]
  }
}
        │
        ▼
LoadAgentSpec → Goal{ID:"<colony>-goal", Status:"draft", criteria:[sc-0, sc-1], constraints:[c-0]}
        │
        ├─ 非 persistent worker: GoalContext = ToPromptContext()
        ├─ success_criteria → AgentSpec / judge 配置
        ├─ worker 完成后 EvaluateGoal(final text + explicit report)
        └─ goal_progress 事件 / goal_evaluation / improvement signals

默认 fresh colony 的 goal 只有 description，所以它是惰性的：不会注入 worker prompt，不会构建 judge，也不会产生 goal_evaluation。

6.4 怎么用 / 输出

  • prompt context：Goal 的 description、criteria、constraints、context 进入非 persistent worker 的 system prompt / 首轮上下文；empty context 不追加。
  • criteria 判定：worker.json 的 criteria 转成 metric=llm_judge、weight=1 的 SuccessCriterion；最终输出和显式 report 一起交给 EvaluateGoal。支持 output_contains、output_equals、llm_judge、success_rate；custom 标 unsupported。
  • 成功线：按权重计算，满足权重达到 90% 时 Goal.IsSuccess() 为 true；score 通过 goal_progress 事件发布。
  • 结果：goal_evaluation 写进 worker result / report 的 data；未满足 criteria 生成 improvement signals。
  • 状态：GoalStatus 有 draft/ready/active/completed/failed/suspended 枚举，但 Go runtime 不自动写 Status；评估只生成 evaluation / signals，不凭分数直接重跑或结束 worker。

6.5 使用入口

  • 单聊不跑 colony Goal：queen DM 是对话驱动；Goal 体系只在 colony 多体场景生效。
  • 配置入口：当前只能编辑 colony 的 worker.json（或走 fork/pivot 写入 description）；没有 Goal 管理页面/API。
  • 没有 /goal / goal tool：hive 现有 10 个子命令（serve、open、queen、colony、session、chat、skill、debugger、mcp、janitor），不含 goal；工具注册表也没有名为 goal 的工具。
  • Task goal 是另一条线：task_create(goal=...) 写 tasks.json；run_worker(goal=...) 只是 worker 展示标题，两者都不进 colony Goal 评估。

代码锚点：internal/server/routes_colonies.go::ensureMinimalColony（默认 goal）、internal/cli/colony_worker_definition.go::writeColonyFromSession（fork goal）、internal/agents/agent_spec.go::LoadAgentSpec（构造 Goal）、internal/cli/loader_colony_host.go::newColonyHost（注入 runtime）、internal/agentloop/goal_eval.go::EvaluateGoal（评估）、internal/colony/goal_outcome.go::evaluateWorkerGoal（结果/事件）。

6.6 Hive 上游（Python）的实际流转

Hive 源码里有两条 Goal 路径，schemas.Goal 是 colony 路径；graph / exported agent 走另一份 orchestrator.goal.Goal。

  ColonyRuntime._goal

  NodeContext（graph）
    └─ goal_context = goal.to_prompt_context()

“完成”/进度
  Goal.is_success()          ← 有定义，生产路径未调用
  GoalStatus                 ← 有枚举，生产不推进
  OutcomeAggregator          ← stub，progress 恒 0.0
  get_goal_progress()        ← 返回空进度
  emit_goal_progress()       ← 有 API，生产无调用
  colony stop/delete         ← 无自动触发
  • 创建：colony 默认 Goal 由 session_manager._start_queen 构造；graph Goal 由 AgentLoader 构造。没有 /goal、没有 goal tool、没有 Goal CRUD 文件。
  • 应用：AgentContext.goal_context / NodeContext.goal_context 进入 prompt；to_prompt_context() 只对非 stub Goal 生效。worker 共享 colony Goal；overseer 拿 goal 但 goal_context 为空。
  • 完成：is_success() 无生产调用；GoalStatus 无自动转换；OutcomeAggregator.evaluate_goal_progress 是 stub，get_goal_progress() 恒返回 0.0 / 空 criteria；没有 goal_achieved 生产事件，也不会自动停 colony。
  • 结果：schemas.Goal 主要是声明式目标 + prompt 上下文 + 评估数据模型，不是自动工作流状态机；colony 完成后继续存在，除非显式 stop/delete。

Go 扩展：internal/agentloop/goal_eval.go::EvaluateGoal 与 internal/colony/goal_outcome.go 增加了 criteria 执行、goal_progress / goal_evaluation / improvement signals；这是 Go 侧扩展并标了 Parity-exempt，不能把 Python 上游说成已有同样执行闭环。代码锚点：schemas/goal.py::Goal.is_success、host/outcome_aggregator.py::OutcomeAggregator.evaluate_goal_progress、host/agent_host.py::AgentHost.get_goal_progress、agent_loop/agent_loop.py 的 goal_context 拼接、host/colony_runtime.py 的 _build_worker/start_overseer。
