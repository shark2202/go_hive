01

定位与核心机制

全系统只有一个执行原语：Agent 循环。Queen 是它，每个 Worker 也是它的克隆。 编排发生在运行时，是一次工具调用，而不是预先画好的图。

单一执行原语

V1

没有节点、没有边、没有数据缓冲区。持久化、上下文压缩、预算、停顿检测、断点恢复都内置在这一个循环里，因此 Queen、Worker、独立 Agent 自动共享同一套可靠性能力。

Queen（女王）

V1

面向用户的长期 Agent，拥有对话、计划、记忆和 Colony。可以是 13 个内置人格之一，也可以自己创建。

Colony（集群）

V1

自包含目录：Queen、Worker 规格、Tracker、技能、触发器都在其中。是部署、备份与移植的单位，可作为 tar 包导入。

Worker（工蜂）

V1

Queen 的 Agent 循环克隆：一个任务、更窄的工具集、严格预算、无长期记忆。不能派发其他 Worker，也不直接与用户对话。

Tracker（共享账本）

V1

每个 Colony 一个 SQLite 文件，是「做完什么、还剩什么」的唯一事实来源。Worker 逐行 upsert，Queen 用只读 SQL 验收。

先执行、再系统化

V1

Independent 阶段先当普通 Agent 做事；任务呈现并行、周期或长时特征时，Queen 调用 suggest_colony 提议建群，用户确认后进入 Colony 阶段，先试点（pilot）再沉淀方法。

02

集群编排与运行时

扇出、并发控制、超时、恢复、触发器与人在回路，全部围绕 Tracker 和一次工具调用展开。

run_worker 并行扇出

V1

一次调用提交多个任务并立即返回，Queen 可以继续和用户对话或继续派活。Worker 报告作为新回合回到 Queen 的对话。

  • 默认同时运行 4 个（HIVE_MAX_CONCURRENT_WORKERS 可覆盖），其余排队
  • 软超时默认 600 秒：要求 Workers 立刻汇报
  • 硬超时 = min(max(软超时 × 4, 软超时 + 600), 3600) 秒
  • 被停止的 Worker 可用 resume_worker_ids 从保存的对话恢复

Worker 预算与宽限回合

V1

默认 3 个工作回合 + 1 个宽限回合；宽限回合只允许汇报类工具，确保 Worker 耗尽预算也能交回结果。

  • 工具调用预算 30，硬上限 90，生命周期上限 200
  • Runner 可覆盖迭代数、宽限数、预算、上下文上限，并有上下界校验
  • Worker 阻塞时写 Tracker 并 report_to_parent，或通过 escalate 升级，而不是无限绕路

Tracker 数据流与写权限

V1

Queen 建表（DDL）并声明 Worker 可写列（tracker_register_writable），Worker 用 tracker_upsert 写入，Queen 用 tracker_query 只读验收。

  • 没有 Colony Binding 的 Tracker 调用会被拒绝，而不是猜路径
  • WAL 模式支持一写多读，契合「Worker 写、Queen 读」
  • 「剩余工作」永远是一次新鲜查询，崩溃不丢进度

run_playbook 方法重放

V1

把验证过的方法批量套用到 Tracker 的每一行，默认 8 个 Worker 并发，最多 32。Playbook 本身不拥有持久状态，重跑即续跑。

  • 重试与指数退避、限速车道（lane）、多轮收敛（converge）
  • 断路器防止系统性故障下无限重试
  • 死信列表单独列出持续失败的行

Task Plan 持久计划

V1

Queen 的执行步骤保存在会话目录 tasks.json，独立于 Worker 生命周期。工具包括 task_create、task_update、task_list、task_get，前端显示为 Action Plan 面板。

触发器：Colony 自己醒来

V1

Queen 用 set_trigger 写入触发器，支持三种类型：

  • cron：基于 croniter 的定时表达式
  • interval：固定分钟间隔
  • webhook：内置 webhook 服务器接收外部事件

Colony 重新加载时会计算离线期间错过多少次 tick，并报告给 Queen。

事件总线与报告回流

V1

运行时内部状态与外部可观测性的唯一通道：SUBAGENT_REPORT 回到 Queen 成为新回合，客户端事件通过 SSE 实时推送到浏览器。

Reminder Hub 长会话提醒

V1

在固定时点向上下文注入短提醒，让长会话保持连贯：Tracker 快照、正在运行的 Worker、可并行的提示、相关历史会话、可加载的工具与技能。这些是软约束，硬约束在工具层与预算层。

Sentinel 哨兵

可选

按 Colony 开启。Queen 停泊时，分类器根据现场决定：推她继续（nudge）、标记完成（done）、或升级给人类（escalate）。

  • 升级渠道：Hive inbox、Telegram、Slack
  • 用户回复后 Queen 自动恢复
  • 检测到用户就在界面前时避免打扰

Colony 导入

V1

通过 POST /api/colonies/import 从 tar 归档导入 Colony，便于迁移、分享和备份。

两阶段生命周期

V1

Queen 在 independent 与 colony 两个阶段之间切换：前者用普通工具并判断是否建群，后者获得 run_worker、Tracker、write_skill、run_playbook、set_trigger。切换需要用户在 Create Colony 对话框确认。

会话分支

V1

会话可以 fork 成新分支，也可以从源会话 fork 为 Colony；支持重命名、停止、快照与附件下载。

03

Queen 与交互

人格、提问、计划、提示词库与自我叙事，构成 Queen 面向人的工作界面。

13 个内置人格

V1

默认启用 6 个：Growth、RevOps、Content、Lead Generation、Outbound、Brand & Design。其余可在 Org Chart 雇佣，也可以创建自己的 Queen。

Org Chart 组织架构

V1

雇佣或移除 Queen，查看岗位目录（Position Catalog），并管理每个 Queen 的人格、模型、Soul 与工具配置。

ask_user 带选项提问

V1

Queen 可以停下来向用户提问，并给出可选项；前端提供 QuestionWidget / MultiQuestionWidget。提问期间会话停泊，用户回答后继续。

可见的任务计划

V1

Queen 的 Action Plan 在聊天界面实时显示，用户可以看见她要做什么、做到哪一步。

Prompt Library

V1

内置提示词库，每个提示词可以直接发送给为它设计的 Queen，省去每次重新描述任务。

Soul 自我叙事

V1

每个 Queen 维护一份第一人称的「她成为了谁」记录，每天根据聊天反思一次；修改需要用户逐条批准。区别于记忆（关于用户与业务的事实），Soul 是 Queen 自身价值观与风格的演化。

Queen 档案页

V1

集中查看和编辑 Queen 的人格、模型（queen_llm）、Soul、工具类别与技能。前端还提供 Claude Code 作为 Queen 的只读视图。

新手引导

V1

Dashboard 内置 Tutorial Overlay 与 Colony 演示步骤，引导新用户完成第一次任务。

04

记忆系统

纯文件、无向量数据库，三层作用域；召回便宜、可失败、不阻塞。另有端到端 LongMemEval 评测与公开的失败模式。

三层记忆目录

V1

全部是 Markdown 文件，可带 YAML frontmatter（name、type、description）：

  • ~/.hive/memories/global/：所有 Queen 与 Colony 共享
  • ~/.hive/memories/colonies/<name>/：某个 Colony 的上下文
  • ~/.hive/memories/agents/queens/<name>/：某个 Queen 自己的经验

每个目录最多 200 个文件，单文件最多 4 KB；全局记忆分为 profile、preference、environment、feedback 四类。

Reflection 反思写记忆

V1

每隔若干回合，Queen 把值得长期保留的结论写成增量 Markdown 文件，而不是重写一份大记忆。带冷却机制，避免每次模型调用都反思。

Recall 自动召回

V1

每回合开始前扫描记忆目录，读取 frontmatter 与前 30 行生成清单，用一次结构化 LLM 调用选出最多 5 个最相关记忆注入系统提示。只看当前查询字符串，任何错误都返回空列表，绝不阻塞主对话。

历史对话召回

V1

每回合前最多注入 6 段相关历史会话摘要（带日期），来源是按关键词检索的会话索引。Queen 也可以主动调用 search_messages 搜索消息。

Timeline 时间线

可选

由 memory_timeline 开关控制，默认关闭。从用户消息中抽取事件、事实与计划，解析「昨天」「上周」等相对日期，存为 timeline.jsonl，通过 search_timeline 查询，回答「什么时候」「多少次」这类问题。

Memory Library

V1

Dashboard 中的记忆库页面，提供记忆的查看与文件级管理 API（/api/memories、/api/memories/file）。

LongMemEval 基准

V1

端到端通过真实 Hive 存储与真实 Queen 回答，官方 judge 评分，回答模型 gpt-6.1-sol。同时公开了「同一模型读完整历史」的上界与各类失败模式。

05

技能体系

采用开放的 Agent Skills 格式；Queen 在方法验证后自己写技能，Worker 随即加载。技能来源受信任门控与审批保护。

SKILL.md 开放格式

V1

一个技能是一个目录，核心文件 SKILL.md，由 YAML frontmatter + Markdown 正文组成。字段包括 name、description、license、compatibility、metadata、allowed_tools、visibility。解析宽松，能修复常见 YAML 错误。

五种作用域

V1
  • framework/default：所有 Agent 可见
  • preset：预设场景
  • queen：某个 Queen 的所有会话与 Colony
  • colony：该 Colony 的 Worker
  • global：所有 Queen 与 Colony（需用户批准）

内置 12 个 default 技能 + 8 个 preset 技能。

write_skill 写技能

V1

Queen 独自面对用户时也能写技能。默认作用域为 colony（有 Colony 时）或 queen；global 不会直接写入，而是生成安装请求并在聊天页展示名称、描述、文件、正文与覆盖警告，用户批准后才落盘。请求持久化，重启后仍在；不覆盖用户手写技能。

技能信任门控

V1

framework 与 user 作用域始终可信；来自不受信仓库的 project 技能在进入系统提示前需要明确同意。信任仓库记录在 ~/.hive/trusted_repos.json；CI/无头环境可用 HIVE_TRUST_PROJECT_SKILLS 显式绕过。

技能注册表

有则用之

从 GitHub 拉取社区技能索引，缓存 1 小时；任何失败都优雅降级为空结果，不阻塞使用。

技能与工具门控

V1

技能可声明所需工具类别；未满足时工具可能被隐藏或提示。与工具的 eager/searchable 分层配合，控制上下文体积与能力边界。

Skills Library

V1

Dashboard 技能库统一管理所有技能，支持上传、查看、启用/停用与安装审批；MCP Tools 标签页同时管理工具白名单。

06

工具与集成

三类工具来源：进程内内置工具、外部 MCP 服务器、驱动你自己 Chrome 的浏览器桥。另有 104 个集成目录与统一凭证管理。

进程内内置工具

V1

启动时不需要任何工具服务器或子进程：

  • terminal-tools：shell 命令、后台 job、ripgrep 搜索、glob
  • files-tools：读、写、编辑文件与搜索
  • chart-tools：ECharts、Mermaid（Playwright 渲染）
  • memory-tools：会话搜索、recall
  • hive_tools：附件、PDF、网页抓取、CSV、图片生成

104 个集成目录

V1

覆盖协作沟通、CRM/销售、营销内容、工程 DevOps、数据库、财务电商、Google/Microsoft、搜索研究、安全扫描、文件媒体与可观测性。

代表：Slack、Discord、Telegram、HubSpot、Salesforce、GitHub、GitLab、Jira、Linear、PostgreSQL、Snowflake、BigQuery、Stripe、Shopify、Notion、Exa、SerpAPI、Langfuse 等。

MCP 工具模式

V1

hive mcp add 注册的服务器，其工具加入与内置工具相同的允许列表，schema 随每次模型调用发送。模型直接可见、调用简单，但工具多时 prompt 会膨胀。

MCP CLI 模式

V1

--as-cli 让服务器不出现在工具列表，只留一行说明；Agent 通过终端调用 hive mcp run <server>，由 mcp2cli 把 MCP 工具转成命令行。环境变量与 headers 通过环境传递，不暴露在命令行。

工具分层：eager / searchable

V1

允许的工具分为两层：eager 层的完整 schema 随每次请求发送；searchable 层只在清单里出现一行，Agent 用 search_tools("select:a,b") 或自由文本查询后提升为 eager。搜索是确定性的（名称 + 描述 token 重叠打分，最多返回 5 个），不额外调用模型。

工具类别与白名单

V1

每个 Queen 的 YAML 档案声明默认工具类别；一个工具可属于多个类别。支持 per-queen、per-colony 允许列表，Worker 有独立的常开类别集合，可在 configuration.json 覆盖。

浏览器桥

V1

Hive Browser Bridge Chrome 扩展让 Agent 在你自己已登录的浏览器里工作，无需为每个 SaaS 配置 API Key。

  • 通过 hive-browser CLI 驱动
  • 每个 Worker 获得独立 tab group，互不干扰
  • 桥接进程默认端口 14829，状态端口 14830（兼容旧版 9230）
  • browser_setup 工具让浏览器可发现、可门控

图片与视觉

V1

支持视觉的模型直接接收截图与附件；API 不支持在 tool result 里带图时，图片被搬到下一条用户消息。纯文本模型通过 vision fallback 模型生成描述，并做裁剪区域映射。

加密凭证库

V1

凭证存放在 ~/.hive/credentials/，Fernet 加密，由 HIVE_CREDENTIAL_KEY 控制。脚本可用 hive-cred token <provider> 按需取短期令牌，避免明文落盘；HubSpot 与 Zoho 支持 OAuth2 刷新。

凭证表单直写

V1

工具缺凭证时，前端弹出独立表单；凭证通过专用 POST 端点直接写入加密存储，不经过事件流或对话内容。

Tool Library

V1

Dashboard 工具目录展示可用工具与集成，配合类别、允许列表与 MCP 管理。

独立 MCP Server

V1

tools/mcp_server.py 可把集成库作为独立 MCP 服务器暴露给 IDE 等外部客户端。

07

模型与供应商

基于 LiteLLM，理论上支持其覆盖的所有供应商；Queen 与 Worker 可以使用不同模型。

广泛的供应商支持

V1

OpenAI、Anthropic、Google Gemini、Groq、Cerebras、OpenRouter、Hive LLM，以及任意 OpenAI 兼容端点（Ollama、vLLM、LM Studio、网关、Magpie）。另有原生 AnthropicProvider、AntigravityProvider 与 MockLLMProvider。

编码订阅

V1

可直接使用已有编码订阅：Claude Code、OpenAI Codex、Kimi Code、MiniMax、Z.AI、Antigravity，无需另买 API Key。

本地模型

V1

通过 Ollama 运行本地模型，无需任何 Key；quickstart 中可直接选择。也支持其他 OpenAI 兼容的本地推理服务。

按角色分配模型

V1

Queen 与 Worker 可使用不同模型（worker_llm），每个 Queen 也可以有自己的模型（queen_llm）。模型目录由 model_catalog.json 提供。

视觉回退

V1

纯文本模型可以通过视觉回退模型「看」图片，并保留裁剪区域到原图的映射。

模型与端点管理页

V1

Dashboard 的 Models 页面集中配置模型槽位（slot）与端点，对应 /api/models/overview、/api/models/slots/{slot}、/api/models/endpoints/{name}。

用量计量

V1

每次模型调用都有用量计量，便于观察消耗。

08

可靠性与运维

长时间运行、崩溃恢复、上下文控制与成本边界，都放在同一个 Agent 循环里。

状态落盘与断点恢复

V1

每个 Agent 把状态写到磁盘；遇到提问、停止、错误或崩溃后，从保存的游标与对话恢复，而不是从头开始。会话冷启动依赖「写穿 + 原子写 + 游标」。

上下文压缩

V1

长会话自动压缩；大的工具结果溢写到文件，而不是灌进上下文窗口。

卡住与死循环检测

V1

停顿检测（stall check）与 doom-loop 检测会捕捉「说要做却没做」或反复绕圈的回合并介入。

预算与并发上限

V1

每回合与每次运行都有工具调用预算；Worker 有硬停止；同时运行的 Worker 数量有上限，避免失控与成本爆炸。

软超时与硬超时看门狗

V1

先软超时要求汇报，再硬超时强制停止；显式报告优先于硬停止，被停止的 Worker 可以恢复。

阻塞隔离

V1

服务端为阻塞型处理器单独建立 32 线程池（HIVE_REQUEST_EXECUTOR_MAX），避免 Queen 的阻塞工具调用拖垮 Colony UI。

健康检查

V1

提供 /api/health、/api/health/resources、/api/startup-status 等端点，用于判断服务与资源状态。

运行日志抽屉

V1

Dashboard 内嵌 Runtime Logs Drawer，通过 /api/logs/* 查看运行时日志，并有 DebugPanel 与连通性横幅。

维护端点

V1

/api/maintenance/* 提供维护操作，便于清理与诊断。

数据本地化

V1

会话、Colony、Tracker、记忆都是 ~/.hive（或 HIVE_HOME）下的普通文件；没有外部数据库依赖，便于备份、审计与迁移。

安装与启动

前置条件：Python 3.11+（推荐 3.12/3.13）、Node.js 20+、git。quickstart 会自动安装缺失的 uv 与 ripgrep，并询问是否安装 Node。

从源码安装（推荐）

V1
git clone https://github.com/aden-hive/hive.git
cd hive
./quickstart.sh          # macOS / Linux
.\quickstart.ps1         # Windows PowerShell 5.1+

quickstart 会建立统一的 Python 虚拟环境，把 API Key 加密存到 ~/.hive，让你选择模型，构建 Dashboard 并打开 http://127.0.0.1:8787。之后在仓库目录运行 ./hive open。

从 PyPI 安装

V1
pip install "aden-hive[tools]"
hive open

适合不克隆仓库的用法。注意：仓库本身是 uv workspace，在仓库根执行 pip install -e . 只会装到无法运行的占位包，所以克隆仓库时务必走 quickstart。

可选的模型来源

V1
  • API Key：Anthropic、OpenAI、Google Gemini、Groq、Cerebras、OpenRouter
  • 已有编码订阅：Claude Code、OpenAI Codex、Kimi Code、MiniMax、Z.AI、Antigravity
  • Hive LLM
  • 本地模型：Ollama，无需任何 Key

验证安装：uv run python -c "import framework; import aden_tools; print('ok')"。当前工作区若没有 .venv，说明 quickstart 尚未运行过，此时 ./hive open 会提示先执行 quickstart。

边界、尚不支持与已退役

以下内容来自 docs/roadmap.md，用于区分「已经能用」与「还没做」。

尚未支持

Roadmap
  • 美元支出上限：每次模型调用有计量，但还不能按金额中止运行
  • 企业密钥管理：暂无 Vault、AWS/GCP/Azure Secret Manager 后端
  • Docker 镜像：官方安装方式是克隆 + quickstart 或 PyPI
  • 语义记忆检索：recall 与 search_messages 仍是关键词匹配，没有 embedding 检索
  • JavaScript/TypeScript SDK

V1 已退役

已移除
  • 图执行器（节点、边、共享数据缓冲区）：由 Agent 循环、run_worker 与 Tracker 取代
  • 终端 UI：改用 Web Dashboard
  • 随包启动的 MCP 子进程（包括 gcu-tools）：内置工具改为进程内运行，浏览器走 hive-browser
  • 自动 Queen 路由：现在由用户选择 Queen
  • 示例 Agent 模板与凭证测试器

它适合谁，不适合谁

适用边界

适合：大量同质工作单元（线索、账户、工单、仓库、文档）需要并行且每次做法一致；任务要跑数小时或按计划运行并能扛住重启；结果需要检查、查询、审计；人必须保留关键决策权。

不适合：单次提示或一次性脚本，用普通 Agent 更简单。
