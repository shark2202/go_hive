Tool 接口与 MCP 契约
装饰器只是入口，真正的规范是 Tool + Registry + JSON Schema

回答：Hive 的 tool 是怎么注册的？有没有 spec/interface？MCP 怎么接进来？结论：核心工具是显式 Tool 对象 + ToolRegistry.register；@tool 与 @mcp.tool 是两条装饰器入口；MCP 遵循标准 inputSchema，但 Hive 侧没有统一的 Tool 版本/结果契约。

0. 结论先行

不是“装饰器注册”。核心工具是 Tool(...) + register()；@tool 只用于 discover_from_module 的模块扫描；@mcp.tool 是集成 MCP server 的 FastMCP 装饰器；harness 用 _Collector.tool 模拟装饰器，把进程内函数收集成工具。规范是 OpenAI function-schema 形状的 Tool.parameters，不是一份独立 ToolSpec。

5. 缺口

结构性问题

  • 四条注册路径并存，没有统一清单/版本。
  • 没有输入 schema 校验与结果 schema；错误只有 is_error。
  • @tool 只给 metadata，不生成参数 schema；register_function 才推断类型。
  • MCP isError 被转成 RuntimeError，丢失结构化错误。
  • 工具名全局唯一靠约定；集成/框架/harness 可能重名。

建议

  • 定义统一 ToolSpec：schema version + input/output schema + error codes + danger + roles。
  • 为 registry 增加注册来源（framework/harness/mcp/cli）与冲突报告。
  • MCP 错误保留 code/data，不只转字符串。
  • 生成全量 tool manifest，进 CI 对比。
