Hive 的可观测性不是一套统一 telemetry，而是“每类问题一个文件”：服务日志、事件日志、LLM 日志、压缩日志、工具落盘、运行时日志、健康端点。本页把它们列成字典。

0. 结论先行

排障的关键不是“有没有日志”，而是“去哪找”：会话行为看 events.jsonl，模型调用看 llm_logs，压缩看 compaction_log，工具大结果看 tool-artifacts，服务异常看 hive-server.log，Sentinel 看 sentinel.log。没有统一 trace id 贯穿这些文件。

2. 字段与关联

会话事件

  • type / stream_id / node_id / execution_id / data / timestamp
  • 77 种 EventType（G-01）。
  • SSE 帧与磁盘 JSONL 同源。

LLM 日志

  • 每次请求/响应的 messages、system、tools、usage。
  • 失败请求单独 failed_requests。
  • 无统一 request id 跨日志。

3. 缺口

结构性问题

  • 没有 Prometheus/OpenTelemetry 导出；只有日志与端点。
  • 没有统一 trace id 把 event/LLM/tool/HTTP 串起来。
  • 字段没有 schema/字典，只有自由 JSON。
  • 保留策略分散在 config 默认与 janitor。

建议

  • 引入 trace_id/span_id，至少贯穿 event → LLM → tool。
  • 为 event/llm log 建字段 schema。
  • 提供 /metrics 或 OTLP exporter。
  • 把保留策略集中到一张表并进文档。
