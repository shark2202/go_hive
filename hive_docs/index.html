十个最重要的发现

结论摘要 · 每条的机制与证据在对应章节

01

只有一个执行原语

Queen、Worker、SDK Agent 都是 AgentLoop。可靠性能力只实现一次，代价是 7.5k 行核心文件。

02

磁盘是真相

parts + cursor 写穿；停泊数天后可精确恢复；user_stopped 跨重启保持。

03

协调靠四种基底

Tracker 事实、Plan 意图、EventBus 信号、Reminder 注意力；没有编译期拓扑。

04

预算是五层

回合 / 每回合调用 / 生命周期调用 / 上下文 / 时间。超额先 grace 收尾，不静默死亡。

05

控制平面提示化

9 个提醒时点、十余个源，把计划/Worker/Tracker/技能塞回上下文。独特也难测。

06

Tracker 是有护栏的 SQL 舞台

Queen 建表，Worker 只能 upsert 注册表；_ 前缀保护，危险 SQL 拒绝。

07

记忆可测量

markdown 笔记 + BM25 召回 + 可选时间线；公开 LongMemEval 与失败题型。

08

方法在运行中沉淀

pilot → write_skill → run_playbook。Playbook 无状态，重跑即续跑；不是沙箱。

09

自治有人的边界

建群必须确认；Sentinel 三选一；触发器只在会话加载时运行并补偿错过的 tick。

10

安全边界是操作系统

终端、Playbook、浏览器桥、外部渠道——能力上限等于运行用户权限。

优势与风险

分析见 14 章

真正的优势

  • 统一原语带来的可靠性复利：恢复、压缩、预算、停顿、视觉只实现一次。
  • 协调模型干净：Tracker 事实 + Plan 意图 + EventBus 信号 + Reminder 注意力。
  • 状态恢复认真：11 种停泊原因、游标、悬空工具修复、用户停止持久化。
  • 预算设计成熟：软检查点 → 中性硬停 → grace 收尾。
  • 对记忆诚实：公开成绩，也公开“整段历史更强”的差距。
  • 产品完整：Dashboard / CLI / Channel / Trigger / Sentinel / Mail 都有真实后端。

不能忽视的风险

  • 复杂度集中：7.5k 行循环 + 4k 行 Queen 工具，变更成本高。
  • 提示词即控制平面：模型换代可能改变行为，难单测。
  • 隐式契约多：前后端 JSON、工具描述、Worker 工具面推导。
  • 文件 + SQLite 的规模边界；单进程 SessionManager。
  • 能力 = 宿主权限；Playbook 非沙箱；默认 HTTP 无认证。
  • 没有美元级硬预算；无覆盖率/类型/性能门禁。
