3. 鉴权与边界

全局中间件

  • cors_middleware：只允许 localhost / 127.0.0.1 的任意端口。
  • desktop_auth_middleware：当 HIVE_DESKTOP_TOKEN 存在时，要求请求携带共享密钥。
  • no_cache_api_middleware：API 响应禁缓存。
  • error_middleware / access_log_middleware：错误包装与访问日志。

逐路由鉴权

  • 除桌面 token 外，没有统一的 per-route auth 层。
  • queen_mail / Claude Code Queen 使用各自的一次性 token（文件内校验），不是全局中间件。
  • 结论：API 的信任边界主要是“本机 + 桌面 token”；远程部署必须自己加反向代理鉴权。

4. 发现与缺口

漂移与结构

  • metrics.json 的 196 与 AST 222 不一致，说明“路由数”是人工统计。
  • 路径参数、请求体、响应体没有集中 schema；契约只能读 handler。
  • 一个文件可注册多条同前缀路由，按模块阅读比按 URL 阅读更清楚。

建议补齐

  • 为每条路由补 request schema / response schema / auth / SSE / side effects。
  • 用 aiohttp 路由表自动生成，不再手写数字。
  • 把 /api/events 的 SSE 事件白名单与 G-01 的事件字典交叉校验。
