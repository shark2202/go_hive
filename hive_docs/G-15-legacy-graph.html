2. 执行流

串行

  1. 校验 GraphSpec / NodeSpec / EdgeSpec
  2. 从 entry_node 开始，构建 NodeContext
  3. 执行 NodeWorker（内部仍是 AgentLoop）
  4. OutputValidator 校验 output_keys
  5. 按 EdgeCondition 选下一条边
  6. 写 DataBuffer / checkpoint / history
  7. 到 terminal/pause 停止

并行

  • 一个 source 多条边 → fan-out。
  • ParallelExecutionConfig：fail_all / continue_others / wait_all。
  • buffer 冲突：last_wins / first_wins / error。
  • branch timeout 默认 300s。
  • FanOutTag 追踪分支来源。

3. 与主路径的关系

仍在用

  • 独立 SDK Agent（AgentLoader/AgentHost）。
  • 导出/导入的 worker.json 单节点图。
  • 旧版 AgentConfig（YAML/JSON）加载。
  • 图节点 judge / phase compactor。

不在主路径

  • Queen DM / Colony Queen / 并行 Worker 都不经过 Orchestrator。
  • 它们直接构造 AgentLoop + AgentContext。
  • 因此有两套 prompting/judging/checkpoint 实现。

4. 缺口

结构性问题

  • 两套执行模型（AgentLoop vs Orchestrator）长期并存。
  • 图路径的提示词布局与主路径不同（focus 在后缀、日期戳）。
  • checkpoint/validator 只在图路径完整。
  • 文档容易把“图”当成历史遗迹，但 SDK 仍依赖。

建议

  • 明确图路径的定位：SDK/导出兼容层，不是主运行时。
  • 为图路径补一张与 AgentLoop 的对照表（状态/预算/提示/恢复）。
  • 若长期保留，补测试锁定行为；若废弃，给迁移路径。
