1. 定义与传输

先明确“事件”在系统里是什么

定义

  • EventType 是 StrEnum，定义在 core/framework/host/event_bus.py，共 77 个成员。
  • AgentEvent 携带 type / stream_id / node_id / execution_id / data / timestamp；data 是自由 dict。
  • 没有事件注册表、没有 payload schema、没有版本字段。

传输

  • EventBus.publish：写环形历史、写 events.jsonl、通知订阅者。
  • 流式 delta 会被合并（_STREAMING_DELTA_TYPES），LLM_TURN_COMPLETE 触发 flush。
  • SSE 路由把事件转成前端帧；部分事件只在全局 bus 上广播。
  • 磁盘回放：events.jsonl 是会话恢复与 UI 重放的来源。

4. 发现与缺口

已死 / 仅前端

  • 完全无引用：MISSED_TRIGGERS
  • 仅前端字符串：STATE_CONFLICT, GOAL_ACHIEVED, CUSTOM, TASK_LIST_REATTACH_MISMATCH
  • 后端有引用、前端无字符串：PAYMENT_REQUIRED, TOOL_CALL_REPLAY_DETECTED, EXECUTION_RESURRECTED

结构性问题

  • 没有 payload schema：同一事件在不同发布点的 data 键可能不同。
  • 没有版本：事件语义变化无法标记。
  • 没有统一的事件目录：前端用字符串、后端用枚举，靠约定同步。
  • 建议：为每个事件补 producer / consumers / data keys / persisted / sse 五元组，并由 CI 对照枚举。
