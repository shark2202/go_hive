C-11 · credentials

Credentials 管理与工具获取
provider/credential_id + account alias + key，不是 profile name

回答：凭证按什么标识管理？是 provider name 还是 profile name？工具怎么拿到需要的凭证？结论：主键是 credential_id / provider name；第二维是 account alias；key name 决定取哪个字段。Worker profile 只是把“provider → alias”绑定起来，profile 名本身不参与查找；该绑定对进程内工具生效，外部 MCP 子进程不会继承 contextvar。

0. 先纠正三个概念

概念例子作用
provider / credential_idgithub、slack、google、stripe第一维：你要用哪个集成。对应 CredentialSpec 的 credential_id / aden_provider_name。
account aliaswork、personal、email3第二维：同一 provider 的哪个账号。工具参数 account=<alias>；Worker profile 的 integrations 就是 provider→alias 映射。
key nameapi_key、access_token、refresh_token第三维：凭据对象里的哪个字段。默认按 value > api_key > access_token > first。
不是 profile name。 Worker profile 名（如 acct-1）只是“这组 integrations 绑定的容器”；真正查找时用的是 profile 里的 {provider_id: alias}。Queen 没有 worker profile，靠显式 account= 或 strict mode 让用户选。注意：该 alias 绑定通过进程内 contextvar 生效；外部 MCP stdio server 在子进程，不会自动继承，需显式 account= 或额外 env 传递。

1. 存储模型

加密文件

  • 每个 credential 一个 <credential_id>.enc（Fernet：AES-128-CBC + HMAC）。
  • 目录：~/.hive/credentials/credentials/；索引 metadata/index.json（无秘密值）。
  • key：~/.hive/secrets/credential_key（0600），优先 env HIVE_CREDENTIAL_KEY。
  • 本地多账号：LocalCredentialRegistry 用 credential_id/alias 作为 storage id。

组合存储与 Aden

  • CompositeStorage(primary=Encrypted, fallbacks=[EnvVarStorage])。
  • 设置 ADEN_API_KEY 时：AdenCachedStorage 包住本地存储，OAuth 走 Aden 同步/刷新，TTL 300s。
  • 没有 Aden 时：只用加密存储 + 环境变量回退。
  • Adyen/Provider 负责 refresh；过期刷新失败抛 CredentialExpiredError。

2. 管理入口

入口谁用行为
Integrations 页面 / POST /api/credentials/local用户手动添加 named local credential；可带 health check，写入 credential_id/alias。
credentials 工具（agent-loop synthetic）Queenhelp / collect / attach / detach；collect 弹安全表单，秘密直接进加密存储，不回 LLM。
POST /api/sessions/<id>/credential-form前端表单接收 {correlation_id,status,credential_id,account,keys}；保存后恢复 queen，回非秘密确认。
hive-cred browse/inspect/token用户/脚本/agent列账号、看键名（无值）、取 fresh token（OAuth 每次刷新）。
Worker profile integrationsQueen 配置{provider_id: alias}；spawn 时注入 account_overrides contextvar。

3. 工具怎么获取凭证：优先级

工具调用（例：github_list_repos(account="work")）
  → 工具内部 credentials.get_by_alias("github", "work")
      ├─ 1. 显式 account 参数（最高）
      ├─ 2. 当前 worker 的 account_overrides["github"]
      ├─ 3. 加密 store 的 alias 索引
      ├─ 4. LocalCredentialRegistry.get_key("github","work")
      └─ 5. 无 alias 时：store 默认 / 唯一 local account
  → 若凭证过期：get_credential(..., raise_on_refresh_failure=True) 先刷新
  → 刷新失败：CredentialExpiredError → 工具返回 credential_expired 结构化结果
  → 多账号且无 alias（Queen strict mode）：AccountSelectionRequiredError → 让用户选

无 account 参数的工具走 credentials.get(name)：先看 profile override，再看 store，再回退唯一 local account；>1 个 local account 时不猜。

4. 具体例子

GitHub 工具

def _get_token(account=""):
    if account:
        return credentials.get_by_alias("github", account)
    return credentials.get("github")
  • 每个 github_* 工具都有 account: str = ""。
  • CredentialSpec(credential_id="github", env_var="GITHUB_TOKEN", credential_key="access_token", ...)。
  • 未配置时返回 {"error":"GitHub credentials not configured", help:...}。

Slack 工具

  • 同样 account 参数 + get_by_alias("slack", account)。
  • Bot token vs user token 由 spec/health check 区分。
  • 多 workspace 用 alias：work、personal。

MCP 工具

  • MCP server 启动时 CredentialStoreAdapter.default()；工具在进程内自己取 key。
  • register_mcp_server 只做“凭据可用性过滤”，不把 secret 塞进工具参数。
  • account_overrides 是进程内 contextvar：对 harness/进程内工具生效；外部 MCP stdio server 不继承，需显式 account=（这是当前缺口）。

脚本 / Playbook

  • 不要粘贴 token；用 TOK=$(hive-cred token github --account work)。
  • OAuth token 约 1h；每次请求前取。
  • reauth_required 表示用户必须重连，不要重试。

CredentialSpec:
  env_var / tools / node_types / required / startup_required
  help_url / description
  aden_supported / aden_provider_name
  direct_api_key_supported / api_key_instructions
  health_check_endpoint / health_check_method
  credential_id / credential_key / credential_group
  • tools[] 建立 tool_name → credential_name 反向索引，用于 preflight 与工具可用性过滤。
  • credential_id 与 aden_provider_name 可能不同（Notion 是典型）；list_accounts 用 provider name，store 用 credential_id。
  • 当前 CREDENTIAL_SPECS 共 114 个；其中 5 个 aden_supported。

6. 错误与歧义

情况行为
未配置工具返回 {"error": "... not configured", "help": ...}，不抛异常。
OAuth 过期且刷新失败CredentialExpiredError；工具 runner 转 credential_expired / reauth_required，提示用户重连。
多个账号且无 alias（Queen）AccountSelectionRequiredError → 返回 account_selection_required，列出 aliases/identity。
多个本地账号且无 alias（Worker）不猜；唯一账号才回退，否则返回 None/错误。
spawn 时凭据不可用preflight 过滤对应 MCP 工具，worker 提示词里看不到它。
加密 key 丢失无法解密；不会静默生成新 key 覆盖旧数据（boot warning）。

7. 缺口

结构性问题

  • provider / credential_id / aden_provider_name 三套命名并存，容易错配。
  • alias 无全局唯一约束；不同 provider 可有同名 alias。
  • profile 的 integrations 只做默认绑定；live 路径的 prompt/tool 覆盖已有缺口（G-08）。
  • 外部 MCP 子进程不继承 worker profile 的 account_overrides，alias 绑定只在进程内工具可靠；MCP 依赖显式 account=。
  • env fallback 可能让“未在 UI 连接”的凭证仍然可用，状态不一致。

建议

  • 统一 CredentialRef(provider, alias, key) 类型，收口三套命名。
  • 为每个工具生成“需要哪个 spec/alias”的 manifest。
  • MCP 工具统一 account CONTEXT_PARAM，由框架注入 profile alias。
  • UI 明确区分“本地 key / Aden OAuth / env 回退”三种来源。
  • 给每次解析记录审计事件（provider/alias/key 名，不含值）。
