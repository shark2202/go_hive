G-08 · exhaustive inventory

Queen / Worker Profile Schema
13 个 Queen 人格 · 8 个 Worker 覆盖字段 · 两条分离的配置面

Queen profile 与 Worker profile 是两种不同的对象：前者是“人格 + 能力默认值”，后者是“同一次 fan-out 里的账号/工具/提示覆盖”。本页把字段、落盘位置、运行时消费点与“只写盘不生效”的字段分开列。

0. 结论先行

Queen 的“人格”和“能力”是分开的：profile.yaml 只存 persona（capability keys 被剥离），默认工具类别与 preset 技能保留在包内 YAML，运行时由 tools.json 与角色默认解析。Worker profile 的 prompt_override / tool_filter 只写进 worker.json，live 的 ColonyRuntime 不读；skill_name 未发现运行时消费点。

3. 能力配置的落盘位置

profile.yaml

  • 只存 persona：name/title/core_traits/hidden_background/psychological_profile/behavior_triggers/world_lore/skills/examples/portrait。
  • default_tool_categories 与 default_preset_skills 被显式剥离。
  • 首次加载时惰性 materialize；默认包是只读来源。

tools.json / skills_overrides.json

  • tools.json：enabled_mcp_tools（null=全放行，[]=全禁，list=白名单）+ updated_at + saved_on_version。
  • skills_overrides.json：enabled、tombstone、all_defaults_disabled、provenance。
  • 两者都是“人格之外”的机器管理配置。

5. 缺口

结构性问题

  • Queen 人格与能力分离，但没有一张“默认能力从哪来”的总表。
  • 所有默认 Queen 的 default_preset_skills 为空，preset 能力包完全靠用户开启。
  • DM Queen 的 SkillsManager 未传 default_preset_skills（21 章）。
  • Worker profile 的 prompt/tool/skill 覆盖在 live 路径不生效（21 章 §7.5）。

建议

  • 生成“Queen × 默认类别 × 预设技能”矩阵，进 CI。
  • 把 tools.json / skills_overrides.json 纳入 profile 导出/导入。
  • 让 Worker profile 的 prompt_override/tool_filter 在 spawn 时真正应用，或从 schema 移除。
  • 为 skill_name 补消费点或标记 deprecated。
