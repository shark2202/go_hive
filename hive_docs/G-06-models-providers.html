0. 结论先行

4. 能力判定

视觉

  • 目录字段 supports_vision 是 UI 提示。
  • 运行时用 supports_image_tool_results(model) 判断工具结果里的图片。
  • 纯文本模型遇图片：配置了 vision_fallback 就 caption；否则丢弃。
  • 图像工具会被 filter_tools_for_model 隐藏（有回退时例外）。

缓存 / JSON / 工具

  • cache_control 由模型名前缀判定，不在目录里。
  • JSON 模式由 provider 调用参数决定；不是目录能力位。
  • 工具 schema 兼容性没有目录标记；由 provider 适配层处理。
  • 目录里没有 reasoning / thinking 能力位。

5. 缺口

结构性问题

  • 目录只覆盖精选模型；自定义端点/本地模型不在表内。
  • 能力位不完整：没有 tools / json / reasoning / cache / streaming 标记。
  • 槽位优先级分散在多个模块，没有一张统一解析表。
  • preset 与 provider 的 model id 可能重复，UI 需去重逻辑。
  • Judge 槽位与 LLM 槽位混在同一配置面，语义不同。

建议

  • 把目录扩成 capability matrix：vision/tools/json/reasoning/cache/context/output。
  • 为每个槽位写一个解析函数与优先级测试。
  • 给自定义端点提供“能力探测”而非手工猜测。
  • 在 UI 明确标出“目录模型 / 自定义端点 / 本地模型”。
