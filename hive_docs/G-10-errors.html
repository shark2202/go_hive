0. 结论先行

4. 缺口

结构性问题

  • 没有统一错误基类/错误码命名空间。
  • 同一类失败在不同模块有不同类名（如 not found 至少有 4 种）。
  • 异常 → 用户文案 → 重试/回退的映射分散。
  • HTTP 只兜底 500，业务错误码靠 handler 自己编。
  • CLI 只有 0/1，除 hive-cred 外不区分失败类型。

建议

  • 定义 HiveError(code, kind, retryable, user_message) 基类。
  • 把现有家族映射到统一 kind：auth/not_found/validation/permission/busy/transient。
  • 让 HTTP/CLI/Worker 共用同一套 code → status/exit 映射。
  • 为每个错误补一条“用户可执行的下一步”。
