8 类外部输入，规模远大于 Python 依赖本身

Hive 的供应链不只是 pip 包：104 个集成目录、866 个工具、任意 MCP server、Chrome 扩展、技能脚本、Playbook、Go 双实现都属于“会被执行的外部代码”。本页把它们列成一张信任边界表。

0. 结论先行

Python 依赖有 uv.lock 锁定，但“真正的供应链”是 866 个工具、104 个集成、任意 MCP server、浏览器扩展、技能脚本与 Playbook。它们大多是用户主动安装/编写的，但一旦启用就继承宿主权限；目前没有 SBOM、没有 MCP 签名校验、没有技能脚本沙箱。

2. 信任边界

有锁定/校验

  • uv.lock 锁定 Python 依赖版本。
  • contracts/module-inventory.json 记录 Python→Go 归属。
  • 技能信任门禁（project scope）。
  • 凭据加密存储。

无锁定/无校验

  • MCP server 是任意命令，无签名/来源校验。
  • 技能脚本/Playbook 是任意 Python，无沙箱。
  • 866 个工具没有逐工具权限清单。
  • 浏览器扩展拥有用户完整登录态。
  • 没有 SBOM/依赖漏洞扫描门禁。

3. 缺口

结构性问题

  • “依赖”在文档里通常只指 pip 包，忽略工具/MCP/技能/扩展。
  • Go 侧有 DEPENDENCY_INVENTORY，Python 侧没有对应物。
  • 没有供应链事件响应流程（谁引入、何时、影响哪些工具）。

建议

  • 生成 Python SBOM（CycloneDX）并纳入 CI。
  • 为 MCP server/技能脚本加来源与哈希记录。
  • 建立“工具 → 集成 → 凭据 → 权限”的供应链图。
  • 对高危能力（terminal/browser/playbook）做默认关闭或显式授权。
