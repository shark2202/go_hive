0. 结论先行

基础工具分三类：编排类（run/stop worker、playbook、trigger、profile）改变运行时；数据类（tracker 四件套）改变业务事实；执行类（harness 的 terminal/files/chart/memory/hive_tools）直接触达宿主。最危险的是 terminal / files / hive_tools 的 web/PDF/Excel 组合——它们不受 Tracker denylist 与工具 allowlist 之外的沙箱约束。

2. 五组深入

编排：worker / trigger

  • run_worker：批量 spawn 或 resume；立即返回；每 worker 一个 SUBAGENT_REPORT。
  • stop_worker：先 [STOP REQUESTED] 再硬停；grace 受 60s 工具预算限制。
  • inject_message：优先注入等待中的节点；否则主 loop。
  • reply_to_worker：按 request_id 解除 escalation。
  • trigger 三件套：set/remove/list，写 triggers.json 并启停 timer/webhook。

编排：playbook / profile

  • run_playbook：解析/compile/exec；fast grace 1.5s；后台收敛；写 colony.db。
  • stop_playbook：停收敛 + 在飞 worker；已 done 行保留。
  • get_playbook_status / list_playbook_runs：live 与 run-log 两条读路径。
  • update_worker_profile：写 profiles/*.json；prompt_override/tool_filter 在 live 路径不生效（G-08）。

数据：Tracker 四件套

  • tracker_sql（Queen）：多语句、CTE、事务；denylist；row_cap 1–10000。
  • tracker_register_writable（Queen）：登记 worker 可写列与 key 列。
  • tracker_upsert（Queen+Worker）：按 key upsert；JSON 编码列表/对象。
  • tracker_query（共享）：SELECT/EXPLAIN only；禁止 ATTACH/PRAGMA/写。

执行：harness 五组

  • terminal-tools（10）：exec/job/PTY/rg/glob/output。
  • files-tools（4）：read/write/edit/search。
  • chart-tools（1）：ECharts/Mermaid 渲染。
  • memory-tools（1）：search_messages + 可选 timeline。
  • hive_tools（13）：web_scrape/PDF/attach/time/image/account/CSV/Excel/read/edit。

3. 共性与边界

维度现状
执行模型框架工具是 async 函数；harness 是进程内同步/异步混合；MCP 是子进程/远程。
超时工具调用 60s；browser 180s；MCP 结果 240s；background 235s；playbook 软超时 600s。
并发只读工具可并行（≤10）；写工具默认串行；Tracker 用 SQLite WAL。
权限Queen-only：tracker_sql/register、run/stop worker、playbook、trigger、write_skill、suggest_colony；Worker 继承 6 个 task/tracker 工具。
结果统一 {success/error} 或 JSON；大结果 30k 截断 + 落盘；无统一错误码。
测试write_skill/search_tools/run_worker/tracker_* 较充分；get_worker_status/inject_message/set_trigger/list_triggers 极薄（≤1 次引用）。

4. 缺口

结构性问题

  • 25 个工具没有逐工具的“危险等级/凭据/超时”元数据。
  • 动态 schema（tracker/ harness）无法静态校验。
  • 工具结果没有统一 error_kind；失败语义靠字符串。
  • run_worker/stop_worker 的并发与 grace 交互复杂，测试薄。
  • harness 与 MCP 两套执行路径，超时/截断行为不完全一致。

建议

  • 为每个工具加 danger / credentials / timeout / idempotent / roles 元数据。
  • 给 run/stop worker 与 trigger 补状态机测试（并发、崩溃、重复 stop）。
  • 统一工具错误码与可恢复建议。
  • 把 harness 的超时/截断/落盘对齐到 AgentLoop 统一结果处理。
  • 为动态 schema 生成快照测试，防止漂移。
