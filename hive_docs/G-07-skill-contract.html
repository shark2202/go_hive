0. 结论先行

Skill 系统的核心不是“Markdown 文件”，而是作用域优先级 + 覆盖存储 + 信任门禁 + 目录渲染。最容易被误认为安全边界的是 allowed-tools 和 visibility：前者只解析/校验，后者只影响 catalog 是否展示，都不限制实际工具调用或执行。

1. 字段字典

字段含义必需运行时行为
name技能名；必须与目录名一致必需目录名不匹配会报 SKILL_NAME_MISMATCH
description一行描述，决定模型是否读取必需catalog 截断到首句或 300 字符
license许可证可选仅元数据
compatibility兼容的客户端/环境列表可选仅元数据
metadata任意键值可选UI/注册表使用
allowed-tools允许调用的工具列表可选仅解析/校验，运行时不执行
visibility允许出现的 phase 列表（independent/colony）可选只影响 catalog 可见性，不限制执行
bodySKILL.md 正文（frontmatter 之后）实际内容按需 cat，不默认进 prompt

3. 信任门禁

状态判定行为
ALWAYS_TRUSTED无 project_dir / 无 git / 无 origin / localhost remote / own_remotes 命中直接加载
TRUSTED_BY_USERrepo_key 在 TrustedRepoStore直接加载
UNTRUSTED有远程且未信任交互式询问；headless 跳过
HIVE_TRUST_PROJECT_SKILLS=1CI 覆盖信任所有 project 技能

framework/preset/user/queen_ui/colony_ui 一律绕过；只有 project scope 需要信任。

4. 覆盖解析（5 步）

  1. Tombstone：deleted_ui_skills 中的名字直接丢弃。
  2. 显式禁用：enabled=false 丢弃。
  3. 显式启用：enabled=true 保留，压过 all_defaults_disabled 与 preset 默认关闭。
  4. Preset 默认关闭：除非在 default_preset_skills（角色默认）中。
  5. 其余：继承 SkillsConfig.is_default_enabled；all_defaults_disabled 只压 framework 默认。

5. 渲染与上限

Catalog

  • 先按 name 排序；按 phase 过滤 visibility。
  • description 截到首句或 300 字符。
  • 完整 XML 超过 5,000 字符 → compact（丢 description，保留所有名字）。
  • 作为 <system-reminder> 在首轮/变化/压缩后注入。

按需读取

  • 模型看到名字与描述，自行决定 cat SKILL.md。
  • 工具门控技能（browser/terminal/chart）会把完整正文预激活进 worker prompt。
  • 因此 catalog 是“索引”，不是“正文”。

6. 缺口

结构性问题

  • allowed-tools 不执行：技能可以声明允许的工具，但运行时不会按它裁剪/拦截。
  • visibility 只影响 catalog，不阻止模型用 terminal 直接读文件。
  • 信任是“整仓级”，不能逐技能信任。
  • DM Queen 的 SkillsManager 未传 default_preset_skills（见 21 章）。
  • 同名覆盖是“最后扫描者赢”，排障时需打印来源。

建议

  • 让 allowed-tools 参与运行时工具过滤，或明确标记为文档字段。
  • 为每个技能记录 provenance（scope + path + override）。
  • 给 hive skill doctor 增加“声明未执行字段”检查。
  • 把 trust 细化到 repo + skill 两级。
