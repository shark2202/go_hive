预算仲裁
七层预算，谁先触发、谁只是提醒、谁强制收尾

Hive 的预算不是一道闸，而是七层独立的闸门：迭代、每回合软/硬、生命周期、上下文、时间/流、grace、自适应群体预算。本页给出每层的默认值、触发点与“触发后发生什么”。

0. 结论先行

真正会“结束工作”的只有三个：迭代上限、生命周期工具预算、上下文压缩失败。每回合软检查点只是提醒；硬停只是把本回合剩余调用延后；grace 不是失败，而是“只允许收尾工具”的保证。上下文压缩在 LLM 之前发生，和工具预算互不替代。

2. 单轮内的实际顺序

iteration 开始
├─ 1. 恢复/构建 conversation、刷新 system prompt
├─ 2. 发布 context usage
├─ 3. needs_compaction()? → 压缩（先于 LLM）
├─ 4. LLM 流式调用（TTFT/事件间看门狗、重试）
├─ 5. 解析 tool_calls
│   ├─ grace? 非收尾工具 → 跳过 + 中性占位
│   ├─ 每回合硬停？ → 剩余调用延后 + 中性结果
│   ├─ 生命周期预算？ → 剩余延后 + 下轮 grace
│   └─ 执行（并行/串行、超时、截断、spill）
├─ 6. 软检查点（每批后，按 budget 倍数提醒）
├─ 7. judge（ACCEPT/RETRY/ESCALATE）
└─ 8. 下一轮：iteration≥max 或 lifetime 用尽 → grace
          grace_iterations 用尽 → 退出/报告

3. 自适应预算（Colony）

参数

  • min_samples=3 才开始学
  • floor=30 下限
  • multiplier=2.0 样本中位数倍数
  • max_guard=1.25 单次最多放大 1.25×
  • dispersion_limit=4.0 离散度过大不学
  • sample_window=50

语义

  • 只调整 tool_call_lifetime_budget，不碰每回合预算。
  • 显式 queen override 或 playbook dispatch 被 pin，不参与学习。
  • 预算是“群体”的：say 是 colony 级学习，不是单 worker。
  • 缩小是安全的；放大有 guard。

4. 缺口

结构性问题

  • 七层预算没有统一的优先级表；触发顺序靠代码位置。
  • “预算耗尽”不是错误，但提示文案与错误样式容易混淆。
  • 上下文压缩失败没有显式预算错误，只退化为更大压缩/停泊。
  • 自适应预算的样本与 pin 规则分散在 colony runtime。

建议

  • 写一个 BudgetArbiter：输入各层状态，输出“继续/提醒/grace/停”的唯一决定。
  • 把每次触发记录为结构化事件（哪层、当前值、上限、动作）。
  • 为 Queen 也提供可选 grace，而不是只有 Worker。
  • 把预算状态暴露到 UI 的统一面板。
