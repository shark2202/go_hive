0. 结论先行

CLI 不是“聊天的客户端”，而是**运行时的运维面**：serve/open 起服务，queen/colony/session 查磁盘或 live 状态，chat 只做一次性注入（不流式、不交互），skill/mcp/janitor 负责安装、配置、清理。真正会删数据的是 colony delete、session stop、janitor run --execute；会执行外部代码的是 skill install/update/test 与 mcp install/update。

这是 CLI 最容易被忽略的部分：同名“list”有的只读磁盘，有的打网络

open= serve --open，额外打开浏览器写 + 网络 + 长驻否
queen list/show/sessions读 profiles；ensure_default_queens() 首次可能写默认 profile读（首次写）是

mcp install/add/remove/enable/disable/config/update/init改 ~/.hive/mcp_registry；可能联网、起子进程做健康检查写 + 网络 + 子进程视命令

5. chat / session 的实际链路

hive chat

hive chat <session_id> "msg"
  → POST /api/sessions/<session_id>/chat
    body {"message": "msg"}
  → handle_chat (routes_execution.py:115)
  → deliver_to_queen → AgentLoop.inject_event
  → 立即返回；输出 SSE 地址
       /api/sessions/<session_id>/events
  • 不等待回复、不渲染流；要看回复需另开 SSE/前端。
  • 重复执行会重复注入，不是“替换上一条”。
  • 会话被 colony fork / superseded 锁定时返回 409。

hive session

hive session list
  → GET /api/sessions            （需要 live server）
hive session list --cold
  → SessionManager.list_cold_sessions()  （直接读磁盘）
hive session stop <id>
  → DELETE /api/sessions/<session_id>    （停止运行中的会话）
  • list 默认是 live 视图；没有 server 会报错并提示 --cold。
  • stop 只对 live session 有意义；磁盘目录不会删除。
  • queen sessions 是另一条只读磁盘路径，按 queen 列目录。

6. 发现与缺口

行为观察

  • hive chat 是 one-shot 注入，不是交互式 REPL；名字容易让人误以为能聊天。
  • queen list 首次运行会 ensure_default_queens()，属于“读命令带写副作用”。
  • hive --model 是全局参数，但 serve/open 自己又定义了 --model；子命令的默认值会覆盖全局值，容易误用。
  • colony delete 默认要求输入名字确认；--yes 跳过，脚本里要小心。
  • session stop 是运行时停止，不等于删除会话文件。

建议

  • 为每个命令补 reads / writes / network / destructive / long-running 元数据，并生成本页。
  • 给 hive chat 增加 --wait / --follow，或明确改名为 send。
  • 把 hive --model 与子命令 --model 的优先级写进 help。
  • 为 queen list 的首次写副作用加 --no-init 或文档提示。
