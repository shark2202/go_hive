B-02 · tool runtime

工具运行时
注册 → 分层 → 分发 → 超时 → 结果 → 事件

工具不是“函数调用”那么简单：它经过 ToolRegistry 注册、QueenPhaseState/ToolTierState 分层、AgentLoop 分发、超时/并发控制、结果截断/落盘、事件发布。本页把这条运行时链路拆开。

0. 结论先行

工具运行时的核心是两级过滤 + 一条执行链：注册时按角色/allowlist 过滤，呈现时按 eager/searchable 过滤；执行时再经过 schema 强制、grace/预算、重放检测、并发分区、超时、截断/落盘、视觉回退、事件发布。最薄弱的是“结果契约”：没有统一 error_kind，也没有结果 schema 校验。

2. 并发安全集合（8）

pdf_read, terminal_rg, terminal_glob, terminal_output_get, web_scrape, search_papers, search_wikipedia, download_paper

  • 只有这些只读工具可并行；写工具默认串行。
  • 并行上限 10（_PARALLEL_CAP）。
  • terminal_exec 永远不并发安全。
  • browser 读工具已改为 hive-browser page ... CLI，走 terminal_exec（串行）。

4. 权限与分层

注册/角色

  • Queen 工具并集 24；Worker 继承 6 个 task/tracker 工具。
  • Queen-only 20 个在 fork/spawn 时剥离。
  • MCP allowlist 只对 MCP 工具生效；非 MCP/always-enabled 绕过。
  • 凭据不可用的 MCP 工具在 spawn 时剔除。

eager/searchable

  • eager：schema 直接进请求。
  • searchable：只在 manifest 里出现，需 search_tools 加载。
  • 加载后持久化到 tool_tiers.json，恢复时 heal。
  • Queen 用 QueenPhaseState，Worker 用 ToolTierState。

5. 结果处理

成功

  • 非错误结果都走 truncate_tool_result。
  • >30k 字符：写 spill 文件 + 返回预览 + 路径。
  • JSON 结果提取结构预览（数组长度、键名）。
  • 结果写入 conversation，触发微压缩。

失败

  • is_error=True；不落盘。
  • transient/permanent 只做标签，不自动重试。
  • Worker 侧按提示词 fail-fast。
  • 没有统一 error code / user message。

6. 缺口

结构性问题

  • schema 动态生成，缺静态快照；改名/参数变化难审计。
  • 结果没有 schema；工具间契约靠约定。
  • 错误分类在 LLM 层与工具层语义不一致。
  • MCP/harness/框架三套执行路径，超时/截断不完全一致。
  • tool_access_policy 在 live 路径不执行（C-01）。

建议

  • 为每个工具生成 schema 快照 + CI diff。
  • 定义统一 ToolResult envelope（ok/error_kind/retryable/data）。
  • 把 MCP/harness 的结果处理收敛到同一函数。
  • 为并发安全集合加测试：写工具绝不并行。
  • 把 tool_tiers 持久化纳入恢复矩阵（18 章）。
