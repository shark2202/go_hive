A-01 · attachments & generated assets

附件与生成文件
路径、存储、上传、chip、lightbox 的完整链路

回答两个问题：上传/生成的文件是不是 /api/sessions/<sid>/attachment/<name>？Web 端到底怎么把它呈现给用户？结论：服务路径是 singular attachment；上传是另一个 upload-attachment 端点；内部统一用 hive-attachment:// 引用，渲染时再解析成该路由。

0. 直接回答

是，但只说对了一半。 文件“取回”的 URL 是 GET /api/sessions/<session_id>/attachment/<filename>（单数 attachment，filename 只能是 basename）。上传走的是 POST /api/sessions/<session_id>/upload-attachment，multipart 字段名 file。生成文件不是直接调上传端点，而是 attach_file 把文件复制进会话的 data/attachments/，再返回 hive_attachment_url，前端解析成同一个 GET 路由。

1. 端点与真实路径

用途方法 / 路径输入返回 / 行为
取回附件GET /api/sessions/<session_id>/attachment/<filename>path 参数只有 basenameFileResponse + Content-Type；未知扩展 octet-stream（浏览器下载）
上传附件POST /api/sessions/<session_id>/upload-attachmentmultipart，字段名 file{filename, path:"data/attachments/<name>", content_type, original_name, extracted_text, page_images:[]}
发送消息POST /api/sessions/<session_id>/chat{message, images:[{image_url:{url}}]}图片是 data URI 或 hive-attachment://data/attachments/<name>
生成文件无独立端点attach_file(paths) 工具复制到 <session_dir>/data/attachments/，向工具结果注入 hive_attachment_url

2. 服务端：一个 basename，四个搜索目录

搜索顺序

  1. <session_dir>/data/attachments/（新上传 + attach_file 复制）
  2. <session_dir>/attachments/（legacy）
  3. <session_dir>/（csv_write / write_file 落在工作目录根）
  4. <colony_root>/（colony 共享输出）

同一 session_id 可能在多个 colony 下有 fork；handler 会遍历所有匹配目录，返回第一个真正有文件的。

健壮性

  • 拒绝 /、\、..，只允许 basename。
  • 冷恢复会话按 resume-source 目录回退。
  • MIME 表覆盖图片/PDF/CSV/文本/代码；未知类型强制下载。
  • /api/* 统一 Cache-Control: no-store。

3. 用户上传链路

选择文件
  → 前端 classifyAttachment: pdf | csv | text | image | file
  → 前端限额: 5 个/条, PDF·CSV·text·file 100MB, image 10MB, 合计 120MB
  → POST /upload-attachment (multipart)
  → 服务端 sanitize + force ext + disambiguate → data/attachments/<name>
  → 返回 path = "data/attachments/<name>"
  → 前端生成 hive-attachment://data/attachments/<name>
  → 发送时放进 images[]（display + LLM 同一 ref）
  → /chat 解析 ref: PDF→file block / image→image_url / CSV·text→文本 prepend
  → 未知类型只给 [Attachment saved to disk] 指针，让 agent 用 terminal 读

服务端还会对 PDF/CSV/文本做 bounded 预览（PDF ≤200 页、CSV 前 200 行、文本 64KB 预览），用于 chip 预览与消息 prepend；大 PDF >10MB 不内联字节。

4. 生成文件链路（attach_file / image_generate）

Queen 调 attach_file(paths=[...])
  → MCP 工具返回 {attached:[{kind,mime,filename,resolved}], errors:[]}
  → AgentLoop 后处理：逐个复制到 session data/attachments/（basename 去重）
  → 向每个 entry 注入 hive_attachment_url = hive-attachment://data/attachments/<dest>
  → 工具结果 JSON 回写给模型；NodeConversation.add_assistant_message 扫描本轮 tool 结果
  → 把 hive_attachment_url 收进 assistant message 的 images sidecar（不发给 LLM）
  → SSE / 磁盘回放：chat-helpers 解析 attach_file 结果 → queenPendingChips
  → 挂到工具调用后第一条 queen 文本气泡；若本轮没有文本，execution_completed 时单独发 chip 消息

image_generate 额外：
  → 工具结果 images[].path + usage.credits
  → 前端按 basename 记 imageGenMeta
  → attach_file chip 命中同名文件 → _generated=true + _credits → GeneratedImageCard

5. Web 端怎么呈现

① 输入框预览条（AttachmentChip）

  • 图片：11×11 缩略图；其他：文档图标 + 扩展名。
  • 名称经 attachmentLabel：时间戳/UUID/哈希 → “Image 2”“PDF document”，真实文件名保留在 tooltip。
  • 大小、上传中 spinner、打开失败红字。
  • 点击：图片开 lightbox；非图片走 openAttachment 新标签页。

② 用户气泡（MessageAttachments）

  • 图片 → ImageGallery：1 张单图 letterbox；2–6 张 mosaic；>6 最后一张显示 “+N”。
  • 非图片 → FileCard：按扩展名着色（pdf/sheet/doc/slides/archive/code/media/file），显示名称、EXT · 大小、外链图标。
  • 点击 FileCard 打开解析后的 GET 路由；失败显示 “Couldn't open file”。

③ Queen 气泡（同一组件）

  • 生成图：_generated → GeneratedImageCard。
  • 其他图片：ImageGallery；文档：FileCard。
  • chip 出现在气泡内容上方；与工具调用气泡分开。

④ GeneratedImageCard

  • 大图预览 + “Generated image” + credits。
  • 复制图片到剪贴板、另存为、默认应用打开。
  • 点击图片开 lightbox 全尺寸。

⑤ Lightbox（ImageCarouselModal）

  • 图片：缩放 25%–500%、拖拽、键盘 +/−/0/←/→/Esc。
  • PDF：<embed type="application/pdf"> 原生预览。
  • CSV/文本：<pre> 展示 _extractedText。
  • 多附件：底部圆点 + 左右切换。

⑥ 解析与回退

  • resolveAttachmentUrl 把 hive-attachment://X 取 basename + encodeURIComponent。
  • sessionId 未就绪时显示 loading/占位，不渲染坏图。
  • 冷恢复消息用 attachmentSessionId 指向原会话，避免 404。

6. 安全与边界

已做

  • basename 校验，拒绝路径穿越。
  • sanitize_attachment_basename + content-type 强制扩展名，防 .jpg 嗅探。
  • disambiguate_attachment_filename 避免同名覆盖。
  • hive-attachment:// 解析后必须位于 queen_dir 内。
  • API 响应 no-store。

缺口/注意

  • GET 无 Content-Disposition，预览/下载由浏览器按 MIME 决定。
  • 上传 handler 没有显式服务端单文件大小限制；主要靠前端 100MB/120MB 与 aiohttp 20MB 全局配置（multipart 流式读取是否受 20MB 约束需按 aiohttp 版本验证）。
  • 同一 basename 在多个 colony/session 目录存在时，按搜索顺序取第一个。
  • 没有缩略图生成；大图走懒加载。
  • 未知类型不内联，只给磁盘指针。
