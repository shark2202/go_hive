5. 缺口

结构性问题

  • 没有 page → API → SSE 的集中依赖表。
  • 两个聊天页面 + 两个面板组件都是数千行巨石。
  • API 路径字符串散落，没有生成式 client。
  • 没有全局状态模型，跨 context 依赖难追。
  • SSE 事件名与后端字符串约定同步（G-01）。

建议

  • 从后端路由/事件生成前端 client 类型。
  • 拆分 ChatPanel/ColonyPanel 为消息流、工具、任务、Worker 子模块。
  • 建立 page → API → event 的 surface 表并进 CI。
  • 为 SSE 事件增加版本/契约测试。
