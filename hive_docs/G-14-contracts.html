2. 关键字段

module-inventory

  • schema_version / baseline_commit / python_root / go_root
  • status_vocabulary：ported / partial / out_of_scope / unported
  • status_rules + scan_rules + exclusions
  • files[]：每个 Python 模块 → Go 归属/状态

skill-discovery

  • scopes[]：name / priority / default_enabled / roots
  • scan：max_depth=4、max_dirs=2000、last_wins、skip_dirs、follow_symlinks
  • entry_order=name_ascending
  • 双端测试锁定

storage-fields

  • file_inventory.counts：python 39 / go 39 / both 27 / python_only 12 / go_only 12
  • observed_classes 10 / code_classes 9
  • presence_values：both / both_type_diff / python_only / go_only

校验链

  • module inventory：Python 生成 + Go checker
  • skill discovery：Python 测试 + Go 测试
  • storage：双跑 artifacts + 生成器
  • 任一改动需同时更新契约与校验

3. 缺口

结构性问题

  • module-inventory 的 baseline 已落后，无法证明“当前 HEAD 全量已归属”。
  • 三份契约没有统一入口/统一版本策略。
  • storage 契约只覆盖 HIVE_HOME，不覆盖内存/事件 payload。
  • 没有“契约变更 → 文档/报告”的联动。

建议

  • CI 每次 HEAD 变化自动重生成 module-inventory 并比较。
  • 给三份契约加统一 schema_version 与 changelog。
  • 把事件 payload / API schema 也纳入契约体系。
  • 在报告/文档中自动嵌入契约摘要。
