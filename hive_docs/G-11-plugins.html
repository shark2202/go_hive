插件契约
两个 entry-point 组：channels 与 turn_context

Hive 的外部扩展点很少但很明确：聊天应用通过 hive.channels 接入，每轮上下文通过 hive.turn_context 注入。两者都是“工厂拿 host → 返回 start/stop 对象”，失败都被隔离。

0. 结论先行

hive.channels 负责“把外部消息送进来、把 queen 输出送出去”；hive.turn_context 负责“在每轮前塞一段上下文”。两者都不是工具，不经过 ToolRegistry，也不受工具 allowlist 约束；它们是服务器启动时加载的进程内插件。

1. 两个 entry-point 组

组用途工厂/协议失败语义
hive.channelsChannel 插件（聊天应用）factory(host) → Channel(start/stop)30s 启动超时；失败不拖垮服务器
hive.turn_context每轮上下文包factory(host) → TurnContext(start/stop/context)5s context 超时；失败跳过该轮

2. ChannelHost 能力

方法作用返回/异常
open_session(queen_id, session_id?, title?)打开/恢复一个 queen 会话返回 session_id
send(session_id, text, images, display_text, correlation_id)把用户消息送入会话返回实际 session_id；锁定/无 queen 抛 ChannelError
subscribe(session_id, handler)订阅 queen 输出QueenOutput: message/question/error/files/idle
unsubscribe / set_title / close取消订阅/改标题/关闭—
judge(question, state, criteria)调用配置的 judge 协议返回概率或 None

3. 配置与目录

启用

  • configuration.json → channels.<name>.enabled
  • configuration.json → turn_context.<name>.enabled
  • 未安装/未启用 → 日志提示，不启动。

私有状态

  • HIVE_HOME/channels/<name>/
  • HIVE_HOME/turn_context/<name>/
  • schema 由插件自己定义。

4. 缺口

结构性问题

  • 没有插件 manifest（版本/权限/依赖声明）。
  • Channel 协议只有 start/stop；收消息靠 host 回调约定，类型约束弱。
  • turn_context 输出没有长度上限，可能撑大 prompt。
  • 插件可访问 host 的 judge/session 能力，但无权限分级。

建议

  • 增加插件 manifest：name/version/权限/配置 schema。
  • 给 turn_context 输出加字符上限与来源标记。
  • 为 ChannelHost 加 capability 白名单。
  • 把插件契约纳入 CI 的接口测试。
