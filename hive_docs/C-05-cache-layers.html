缓存层级
哪些缓存影响行为、哪些只是性能、何时失效

Hive 里“缓存”至少有 16 处，分布在模型端、进程内、磁盘派生与外部状态。把它们混为一谈会导致两类错误：以为改了配置立刻生效，或以为重启后行为不变。

0. 结论先行

真正影响模型看到什么的是前四类：prompt cache、凭据摘要、Soul、技能 catalog / 预激活正文。其余多是性能或运维状态。最容易踩坑的是：技能 watcher 有 1s debounce；凭据块 30s TTL；_BODY_CACHE 进程内永不失效；自适应预算样本重启即重置。

2. 三个必须知道的坑

① _BODY_CACHE 永不失效

  • 工具门控技能正文按目录名缓存在进程内。
  • 改了 SKILL.md 后，已缓存的正文不会更新。
  • 需要重启或改缓存键（加 mtime）。

② 技能 watcher 有 debounce

  • 文件变化后 1s 才 reload。
  • reload 会重建 catalog，但不会清 _BODY_CACHE。
  • UI 里“已应用”到模型实际看到之间可能有一拍。

③ 凭据块 30s TTL

  • 新增/删除凭据后，prompt 里的“Connected integrations”最多 30s 才变。
  • 显式 attach/detach 每轮读取，不受 TTL 影响。
  • 不要用凭据块做实时状态判断。

④ 自适应预算不持久化

  • 样本与学习结果只在进程内。
  • 重启后从头积累。
  • 显式 override / playbook dispatch 被 pin，不参与学习。

3. 缺口

结构性问题

  • 没有统一缓存注册表/失效 API。
  • 有的按 mtime，有的按 TTL，有的永不失效。
  • 缓存状态不可观测：无法回答“当前模型看到的是哪版技能”。
  • 进程内缓存与磁盘派生缓存混在一起。

建议

  • 定义 CacheLayer(name, scope, key, ttl, invalidator, behavior_impact) 并生成文档。
  • 为技能正文缓存加 mtime 键。
  • 在 UI/调试页显示“当前生效版本 + 最近失效时间”。
  • 把行为相关缓存与性能缓存分开监控。
